# HUMAN AGENT LOOP

多个人类与模拟助手一起讨论、比较和形成决定的通用模拟工作台。当前只维护这一套实现和一份可运行构建。

参与者提出关注点、补充合成信息并调整目标；规划、质疑和归纳助手提供明确标注的模拟回复；协调者负责确认选择或记录暂缓。助手没有决定权，也不会自动代表参与者达成共识。

## 运行

需要 Node.js 22.13 或以上版本，以及 npm。后台使用 Node 内置 SQLite，不需要额外服务或密钥。

```bash
npm --prefix Front ci
npm run build
npm start
```

服务默认只监听本机端口 48431。开发时保留后台进程，再执行 `npm run dev`；Vite 将同源 API 请求代理到后台。

在 cloud 环境中可以使用 `node scripts/manage.mjs start`、`node scripts/manage.mjs status`、`node scripts/manage.mjs stop`。管理脚本只操作 PID、入口和随机 marker 均匹配的自有进程，不抢占端口。

可选运行配置：`DECISION_PORT` 指定服务端口；`DECISION_DB_PATH` 指定 SQLite 文件。默认数据位于 Git 排除的 `.run/decisions.sqlite`，重启保留共同讨论、修订、反馈和决定记录。

## 使用

1. 使用虚构参与者代号选择协调者、参与者或观察者。不同浏览器会话可以分别加入，共享相同记录。
2. 在共同讨论区发表意见，或向规划、质疑、归纳三个模拟助手提问。
3. 设置目标效果、投入程度、可调整性和依赖程度的相对权重及硬边界，比较四种虚构方案。
4. 记录模拟信息修订；缺失值保留为未知，旧比较失效，既有人工决定提示复核。
5. 协调者写明理由后确认方案，或明确暂缓。其他参与者可以提交反馈，但不能代替协调者确认。

内置情景为活动方案选择、资源有限时的取舍、信息不足时的协作。所有数值为人工构造的合成假设，不代表真实人员、组织、业务制度或行动建议。

## 能力边界

- 多人共享的是实际保存的讨论与决定记录；冲突修订被服务端拒绝，界面提示刷新并保留尚未提交的草稿。
- 角色选择仅是本机模拟，不是生产身份认证。只有本机服务参与者可访问 API；不应用于敏感资料。
- 助手由本地规则生成，界面明确标注“模拟助手 · 非真实模型”。本版本没有调用模型 API，不宣称实际大模型推理、自动学习或自主执行。
- 比较采用硬约束过滤、加权效用和 Pareto 可行前沿。效用分不是概率或置信度，推荐不是人工决定。
- 当前源码和构建只包含当前产品。仓库历史维护与应用部署是独立操作；清理分支和标签不保证托管平台的旧引用、缓存或第三方副本随之消失。
