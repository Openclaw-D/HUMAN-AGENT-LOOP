# 任务 04｜实时工作台后端、独立验收与安全交付

## 0. 身份、输入与写入边界

先读同包 `00_READ_FIRST.md`。本任务负责 thin Edge/BFF、实时状态投影、独立故障与权限测试、启动/停止与发布核对。不承担四域政策裁决，不自行修改 A/B/C 来掩盖失败。

建议写入：`Back/Edge/**`（新增）、`Back/D/**`、登记过的启动/停止脚本、`docs/customer-next/acceptance/**`。最小浏览器验证页建议放 `Back/D/browser-harness/**`；不以此重做 Front 全站。后续视觉前端消费同一公开契约。

依赖任务 01/02/03 的固定输入版本与契约。发现源码缺陷必须返回对应 writer 修复；D 保持独立预置判据。

## 1. 目标

使未来“真实现场视频 + 透明面板 + 常驻聊天”页面拿到一致、实时、可恢复的客户状态，并用真实 HTTP/PG/媒体/模型受控测试证明它不是动画驱动的假闭环。

同时解决“我不知道本地修到哪”：每次交付可追溯到源版本、未提交变更指纹、dist、数据库迁移、规则和模型能力；用户能看到实际运行版本和真实能力状态。

## 2. 非目标

不重写 React/Vite、Blender/Unity 场景，不制作完整视觉稿，不公开部署现有 loopback 服务；不使用真实客户数据做故障注入；不把一次全绿定义为稳定；不做实际银行付款；不引入无测量依据的大规模微服务。

## 3. S1：独立判据与版本封存

### 先制定矩阵

在实现前保存每个验收用例的输入、前置、动作、预期、资源归属、清理方式和失败退出码。必须区分 PASS、FAIL、BLOCKED、NOT_RUN，不把零断言、异常、fixture 不可用当通过。

执行包版本包括 Git SHA、dirty 状态与非敏感源指纹、依赖锁指纹、dist 指纹、迁移版本、contractVersion、rulesetVersion、模型能力与模式。禁止输出密钥、数据库口令、客户标识或本地私人路径。

### 版本与健康接口

受控版本接口提供 buildId/gitSha/sourceDigest/sourceDirty/contractVersion/migrationVersion/capabilities。健康接口拆分：liveness 只表示进程存活；readiness 检查提供相应业务动作所必需的 DB/队列/对象存储等。DB down 不能被包装为“业务已就绪”。

媒体/存档/分析能力分别显示。例如 video=live、recording=gapped、policy=up_to_date、credit=lagging，不能汇总成一个虚假的 all_ok。

S1 提交边界：验收矩阵、版本协议、测试资源参数化与最小自检。先解决 A/D 测试旧端口/旧容器假设，禁止误操作遗留服务。

## 4. S2：客户工作台投影与实时事件

### 聚合 API 提案

按任务 01 冻结路径发布 `GET customer workspace snapshot`、`GET customer/session event stream`、`GET evidence locator` 与动作可用性。具体可以采用 `/api/jw/v2/**`，不得复活旧 `/api/v5-preview/**` 冒充新内核。

`WorkspaceSnapshot` 至少包含：

- customer 摘要与版本；当前会话及 live/replay 状态。
- consent/recording/ingestionCoverage/sourceFreshness。
- 四域各自 workflowStatus、riskDisposition、analysisState、inputVersion、evidenceRefs。
- 缺证/待核验/冲突列表及其归属。
- candidateLimit、approvedLimit、reserved/committed/outstanding、availableLimit、币种与时点。
- 人类正式决定、条件、审计定位。
- availableActions 与 disabledReasons，但 A 必须在执行时再次鉴权，不能信 UI 投影。
- 事件游标与 snapshotVersion。

### 状态维度分离

`workflowStatus=decided` 不说明结论是 approved；正式 rejected 也有 decided。stale 是依据新鲜度，不是任务失败；规则未命中不等于风险为零；模型运行完不等于人已接受；预算耗尽不等于客户信用差。

不能以 completedTurns.length、播放到第几幕或请求次数推导真实业务进度。进度必须指向已完成/未完成的明确核验任务；允许展示“已覆盖 5/8 必需项”，禁止无分母的假 87%。

### SSE 与恢复

业务状态推送优先采用现有 A outbox + SSE；不为简单需求先引入 Redis/Kafka。媒体使用 RTC，不走 SSE。

snapshot 与其 cursor 需有一致性边界；订阅事件不会漏掉 snapshot 获取与 stream 建立之间的变化。事件含 eventId、scope/tenant/customer/session、aggregateVersion、schemaVersion、occurredAt、payloadRef。至少一次投递，客户端按 eventId 去重、按业务版本拒绝旧结果。

断线后用 Last-Event-ID/等价 cursor 补取；cursor 过期要求重取快照，不能从当前时点静默漏事件。多实例网关重启不能丢仅存在内存的游标。缺少事件权限时不允许回放。

### 命令与网络结果未知

POST 成功后以服务端状态为准；响应丢失时先查回执/用同 requestId 安全重放，不自动生成新 ID 导致重复业务动作。版本冲突重新拉取并要求用户确认关键操作，不 silently overwrite。

S2 提交边界：只读聚合、事件、回放和失败投影；不夹带角色提权或新业务状态机。

## 5. S3：安全动作代理与页面连续性

### Thin Edge

固定上游、路由和方法白名单；不提供任意 URL 代理。可信用户会话与后端凭据映射由服务端控制，不把 tok-admin 或所有角色 token 发给浏览器。仅放在 loopback 不等于已具备用户认证或防 CSRF。

在目标部署形态实现认证、Origin/CSRF、WebSocket/SSE 授权、会话过期与权限变更处理。Cookie/HTTPS 设置按 local dev 与受控 staging 分开，不能把开发例外带入对外服务。所有敏感动作后台再鉴权。

底部消息区保留 `customer/internal` 受众。服务端验证 channelId、threadId、recipient、customerId 关联；不能由前端填 audience=customer 后自动把任何内部内容外发。对客户发送是可审计副作用，未知送达不标为已读。

### 最小可操作浏览器验证页

用无视觉装饰的 harness 先完成：客户选择、邀请/加入视频、打开/关闭面板、事实查询、片段定位、补证、四域候选、人工复核、额度预占模拟、事件断线恢复。

视频由稳定会话组件持有；面板开合和四域切换不卸载媒体连接。客户切换必须显式离开/保持当前会话并防错绑定，不能把 A 客户通话画面挂到 B 客户额度上。回放查看历史时，正式动作明确绑定当前版本并再次校验，不能基于历史画面偷偷操作当前授信。

客户端不可查看内部 HUD。内部面板不得自动进入客户共享屏幕或媒体合流；单页不等于所有人看同一套权限数据。

S3 提交边界：动作代理、会话鉴权、最小操作验证页、角色/受众/客户绑定负例；完整酷炫前端另行设计实现。

## 6. S4：故障、并发、安全与性能验收

### 必须故障注入的位置

只对 D 自己创建的进程/容器/数据目录操作：A/PG/B/连接器/网关/对象存储不可用；worker 在 sent/no-receipt 时被杀；写 DB 后丢响应；outbox 发布中断；录制回调丢失/重复/乱序；SSE 断流；磁盘写失败、Windows 文件替换 EPERM、预算锁与坏账本。

等待目标条件而非靠大段固定 sleep 让竞态消失。mock 控制面应能确认请求已进入/已完成，故障注入点可重复。每轮独立数据库/目录/roomId、动态端口、明确资源清单。

### 已知不稳定项

B 的文件替换与 crash recovery、D-25e 必须记录修复前后固定 hash、复現用例、失败点和所有重复轮次。要求相关确定性用例在目标 Windows 环境连续 30 轮通过，并在目标服务平台再验证；全套也必须通过。单测通过不等于 D 稳定；30 轮通过也不是无限稳定性的保证。

不得删除 flaky 用例、改成 skip、只展示最后一轮绿灯或将产品候选从 candidate→failed 的翻转改为预期。若认为 D 断言错误，先提供独立证据证明正确语义，再走审批修改测试，保留旧失败。

### 临时性能验收提案，不是现状承诺

基线环境至少明确 CPU/RAM/OS/Node/PG、网络、是否同机、provider 模式、数据规模。首轮建议在声明的测试环境上以 100 个合成客户、10 万条历史事件、5 场并行会话、最多 20 个活跃域任务进行测量；不在未测情况下承诺生产容量。

候选目标：客户快照 p95 ≤500ms；简单事务命令 p95 ≤1s；DB 提交至 SSE 客户端可见 p95 ≤1s。模型、ASR、RTC 的外部时延单独报告，不揉进内部指标掩盖问题。阈值须在测试前固定，失败后不能悄悄放宽。

质量维度：连续两小时受控运行，检查队列是否无界增长、资源是否泄漏、事件是否积压、媒体是否受分析峰值影响。系统过载应保护通话和事务，降低非关键分析频率并显示滞后，不能让核心 Gate 静默失效。

S4 提交边界：独立测试、固定版本结果、必要的 Edge 恢复修复和性能报告；A/B/C 缺陷由原 writer 单独提交。

## 7. S5：启动、备份、回滚与证据包

保留现有 Start-JW.cmd；新增独立完整模式入口，先不要覆盖原模拟入口。启动检查 Node、依赖、配置、端口、授权模式、PG、迁移和 dist 版本，分别报告失败原因。

只启动/停止本实例登记的资源；进程 PID 需结合启动标识复核，不只凭旧 PID 杀进程。端口被占则提示，不抢占。停止服务不删除数据卷。

数据库变更前在隔离/获准环境做备份与恢复演练。代码回滚不等于数据库回滚；不可逆迁移要有向前修复或恢复方案。已产生的客户消息、录制、授信记录与外部请求不能随 Git reset 消失。发布时冻结版本和配置摘要，敏感配置另存。

验收证据包含：命令/退出码、固定 SHA 和源指纹、每轮测试统计、失败日志的脱敏引用、业务事件/账本断言、对象/视频片段一致性、浏览器 Network 与版本截图、真实 provider 能力与 usage、已知限制。真实媒体与敏感日志不提交公开仓库，只提交脱敏索引或合成测试报告。

S5 提交边界：安全启动/停止、备份恢复说明、验收报告与发布清单。没有用户对应授权时保持 commit-ready，不自动提交/推送/部署。

## 8. 最终贯穿验收场景

一个合成企业客户有多来源商机、一个客户主额度评估、两笔不同交易类型的申请。通过企业微信支持的受控入口邀请视频，在获准的真实设备间通话；展示设备并提交发票/合同；数据成为带出处证据；四域形成不同意见和缺口；补证更新且旧候选标 stale；人类在权限内复核/批准；额度预占遇到并发不超上限；刷新/重启后事实与状态保留；新增矛盾证据使新正式动作暂停；内部意见未泄漏给客户。

若尚无外部授权，先运行本地 E1 并标 E2 BLOCKED；不得以 E1 场景替代最终真实媒体验收。真实资金支付始终不属于本轮测试。

## 9. 完成定义（Definition of Done）

四层结论分别签署：E0/E1 工程链路、E2 外部服务真实接入、业务规则/权限批准、用户操作与视觉验收。任何一层缺失都不得使用“整个产品已经可生产使用”。

本任务完成意味着：有可追溯版本、可真实操作的受控工程链路、有独立通过的关键安全测试和可恢复启动；不是“所有风险都被模型解决”。完整炫酷前端另有任务，但不能改变已冻结的事实、权限与事件语义。
