# 候选置信度与点选反馈：实施切片

2026-09-20。来源：用户要求“直接改进去”。用户已明确授权本任务直接完成前后端并协调。后端与前端最小闭环已实现，最终构建及视觉集成由现有FRONT串行接手；验收见 DECISION_FEEDBACK_ACCEPTANCE.md。不创建subagent或新任务。

目标：同一专业判断显示关键证据和最多5个真实候选，按同口径模型置信度排序、默认建议首项；点选保存反馈，可撤销，当前建议据此调整；后续同一客户同一问题的分析可读取经授权的相关反馈。模型估计明确未校准；不称在线训练或自动审批。

## 最小闭环

1. 用户明确请求候选分析，复用现有会话、客户授权、证据准备、provider、成本预算和持久回执。
2. 模型输出有限候选：稳定ID、判断文字、confidence（0–1或null）、证据ID、下一步影响。限制最多5项，不足3项如实显示；服务端校验类型/重复ID/来源/当前性，非法结果不可选择。
3. 返回decisionSetId及绑定的客户、助手、问题版本、证据版本/hash、模型版本；只有有效候选可选。候选为同一问题下的备选建议，不把多个并存事实伪装成互斥概率。
4. 页面展示证据、候选、置信度及“建议首选”；没有分数明确标未提供。默认选择只属于展示，不记录成人工选择。
5. 人点击候选/均不适合，以幂等feedbackId保存反馈。服务端重新校验身份、客户、decisionSet版本与候选成员关系；操作者来自会话，不接受客户端冒充。
6. 读回保存成功才显示“已记录”；失败/未知保留待核对，不显示已学习。允许撤销，撤销以新事件表达，不删除旧记录。
7. 当前页保留人工选择，不被模型排序覆盖；证据更新使旧选择退出当前有效态。再次分析只读取同租户/客户/任务范围且未撤销的相关反馈，并明确它是人的意见，不是已核实事实。

## 已实现API

- 候选分析：现有observe之外独立`assistant/decisions`入口，避免破坏旧文字观察接口。客户端提供问题与本次操作ID，服务端建立完整输入身份；相同操作重试幂等，明确重新分析使用新操作ID。
- 反馈写入：`POST /api/jw/v2/actions/customers/:customerId/assistant/decisions/feedback`（decisionSetId置于body），载荷包含幂等ID、选择ID或none、可选理由、预期反馈版本。用户选择、撤销以及旧版本拒绝有明确返回。
- 反馈读回：同一decisionSet的当前反馈投影及版本；每次鉴权，禁止直接遍历回执目录披露其他客户。
- 存储复用现有持久化基础，先选一个唯一owner；不要在浏览器localStorage存客户反馈，不另建影子审批库。追加事件保留原排名、分数、上下文身份与操作者。

## 文件ownership与依赖

- 后端：候选schema与校验独立模块；Edge模型调用、路由、回执相关改动由同一个writer串行完成。保留旧observe、未知发送不重发、成本门和正式业务零写。
- 前端：独立候选卡与反馈组件、必要client类型/方法、观察抽屉接线、局部样式、行为测试。与现有FRONT先明确这些具体文件归属，再集成。
- 最终装配：后端契约固定后联动；更新Front/dist。当前服务连通问题单独记录，不以绕过认证或测试替身冒充在线验收。

## 验收

- 正常：真实结构化结果按分数排序；默认无反馈写入；点选第二项持久保存并读回；重新打开仍在；撤销恢复建议态；后续分析确实携带相关反馈。
- 边界：null/NaN/越界置信度、重复/未知候选、无候选、未核验证据、陈旧输入、非JSON模型输出均明确处理，不生成虚假百分比。
- 权限：跨客户/租户/会话、撤权后重放、伪造操作者与候选、并发反馈版本冲突不越权。
- 恢复：模型发送未知不重发；反馈超时先读回；重复点击只落一次；重启后记录可读；失败不显示已学习。
- 校验：相关后端与前端行为测试、typecheck/build；页面验证另记。真实模型调用仅用已有明确授权的提供方/数据/预算，否则记录未测。
