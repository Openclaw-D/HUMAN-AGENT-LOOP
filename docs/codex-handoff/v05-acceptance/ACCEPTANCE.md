# V0.5 独立验收清单

2026-09-30。Owner：Codex。依据docs/integration/2026-09-30-final/00_SCOPE.md；三路ZCode已由用户手动分发并在实施。

本文件只是验收准备，所有门初始均为待验收；不复用旧测试成绩作为新版本通过证据。Codex在三路代码/材料/dist冻结后执行。实施期不接管代码、不运行会读到未冻结代码的套件或共享服务故障测试。

## 收件顺序

1. 01交回Front改动清单、源码/dist指纹、typecheck/build/关键测试、1920×1080截图及未完成项。
2. 02交回兼容契约、十案例材料/独立预期/准备配方、关键状态轨迹和测试证据。
3. 03基于01/02冻结交回最终栈、十案例浏览器结果、Windows运行说明、候选交付清单和缺陷表。
4. Codex核对实际diff与新增文件、测试覆盖范围、材料期望和运行结果，再做必要独立复验。跨writer整改交回原路；整改后重新冻结相关工件。

## 逐案例判定（各项待验收）

| 案例 | 必须在页面看见 | 必须验证的动作或边界 |
|---|---|---|
| 01收入红线反例 | 原件收入、金额单位和阻断依据 | 不可强制通过，分类标签不是判断输入 |
| 02权属冲突 | 申报、核验冲突与办理人记录 | 有权人拒绝并留痕，模型不能替人决定 |
| 03偿债不足 | 现金流/偿债口径和实际规则意见 | 拒绝或补证按现有规则，不能发明硬门 |
| 04现金流缺件 | 明确缺件、补件文件入口和等待原因 | 补件后只重算相关域，其余历史保持 |
| 05口径冲突 | 两份材料冲突与核实入口 | 核实后绑定版本重算，不自动选一份当真 |
| 06待人工核验 | 已有分析及收入/主体/权属核验入口 | 浏览器实际核验，不用脚本绕过缺失UI |
| 07陈旧结论 | 历史判断、补证、需复核标记 | 旧候选不能继续采用，当前依据可追溯 |
| 08预评估收口 | 五区结果与最终人工确认 | 只确认预评估，不变成正式额度批准 |
| 09履约待回执 | 前序、履约及等待外部回执 | 模拟回执明示，未确认不可结清 |
| 10结清返单 | 可追溯的结清与关闭演练历史 | 返单新周期独立，旧历史不覆盖 |

## 公共门（各项待验收）

| 门 | 通过证据 |
|---|---|
| 登录与可靠启动 | Windows正式入口启动后真实依赖就绪；数据库停机可解释，恢复后再次登录成功 |
| 横向案例与风格 | 十案例按差→中→好展示；1920×1080/100%无遮挡、可导航；不是十个全锁空盘；用户视觉验收另记 |
| 检查点真实性 | 材料hash/事件/角色/回执链支持当前状态；准备流程用API执行，不直写结果表 |
| 输入决定结果 | 独立预期由材料得出；改关键输入会改变判断，改caseId/名称不会改变业务逻辑 |
| 单事件多步骤 | 至少两个独立步骤的服务端作业与时间/依据/回执；依赖和人工门仍阻断 |
| 四页与助手 | 同客户/周期/依据一致；当前事实说明有用；确定性说明和模型回答来源区分 |
| 安全与异常 | 幂等单效果、旧版本拒绝、补件选择性失效、跨客户/撤权拒绝、断线/刷新/重启恢复 |
| 权威与接口 | A案例清单为权威、Edge无长期第二清单；中文角色不暴露凭据或偷偷借管理员权限 |
| 构建与回归 | 相关正常/异常/权限测试通过，typecheck/build与实际dist对应；不借旧成绩覆盖新改动 |
| 交付可复现 | 源码/dist/材料/操作手册/依赖/启动停止/非破坏性重演/恢复说明可由他人使用 |

判定：PASS=实际证据充分；FAIL=结果违反要求；BLOCKED=明确外部依赖；NOT_RUN=尚未执行。必要项FAIL/BLOCKED/NOT_RUN不算通过。执行者自测、03集成、Codex独立验收和用户视觉/业务验收分别记录。

## 最终用户检查顺序

选角色→横向扫十案例→差例看阻断→中例补件/核验→好例确认收口→履约待回执→结清返单；过程中抽查材料原件、已走流程及右侧说明。重点是用户无需猜“现在发生了什么、为什么停、下一步做什么”。
