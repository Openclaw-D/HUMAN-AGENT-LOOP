# 当前架构

React 页面 → 同源 Node HTTP API → SQLite 共同状态。

## 记录与权限

每次模拟会话由服务端生成独立参与者标识，用户只选择代号和角色。协调者、参与者可以讨论、比较、修订与反馈；只有协调者能确认选择。观察者只读。角色选择不构成真实身份核验。

写命令需要当前 revision 与唯一 requestId。SQLite 的事务将状态、事件和幂等回执一起提交。同一主体、载荷和标识重放不会重复执行；不同载荷或主体复用标识会被拒绝。并发修改基于修订号裁决，不让旧输入覆盖共同记录。

inputVersion 表示目标、边界或信息的变化。共同讨论不自动改动这些假设；信息更新使比较过期，历史人工决定保持原样并显示需复核。旧助手回复也标注其所依据的输入已变化。

## 多目标比较

四个维度均为 0–100 的合成指标：目标效果越高越好；投入程度越低越好；可调整性越高越好；依赖程度越低越好。先检查投入上限、可调整性下限、依赖上限和信息完整度下限，再计算归一化权重下的效用。

未知值不补零，不产生有效得分。Pareto 前沿只在满足边界的方案中计算。人的选择可与当前权重首选不同，但必须满足现行边界且写明理由。所有方案都不可选时，可以记录暂缓。

## 模拟助手

规划助手解释目标和可选方案；质疑助手提出假设与信息缺口；归纳助手整理已有参与意见和人工记录。回复基于同一情景的当前状态，mode=simulated、authority=none；不连接外部模型，不改变人的决定。

## API

- `POST /api/session`：选择模拟角色和参与者代号；返回 HttpOnly、SameSite cookie。
- `GET /api/session`、`GET /api/cases`、`GET /api/cases/:id`：读取会话和共同记录。
- `POST /api/cases/:id/discuss`：发送参与者意见。
- `POST /api/cases/:id/ask`：向指定模拟助手提问并保存回复。
- `POST /api/cases/:id/analyze`：提交共同目标与边界并比较。
- `POST /api/cases/:id/evidence`：修订一项合成指标及其依据。
- `POST /api/cases/:id/decide`：由协调者记录选择或暂缓。
- `POST /api/cases/:id/feedback`：保存复核意见，不自动训练或改规则。
- `GET /healthz`：本机服务与存储状态，明确披露模拟助手模式。

写接口检查同源 Origin、JSON 类型、输入白名单与大小上限。服务仅绑定 loopback；生产认证、多组织隔离、外部模型和公开部署均不属于当前已验证能力。
