# V0.4 Kanban 接续

用户明确创建新任务接手；V0.3先推送与打标签，再启动本任务。沿用JW现有目录，不建worktree，不归档旧任务。默认low，唯一执行writer，禁止内部subagent。

## 目标

保留工作台、材料清单、决策树、时间轴四页和最新纯聊天助手。右上角“向右/下一步”每次驱动一个节点的滑动切换，位置与当前客户保持一致。导航本身不提交、采纳、审批、发模型或上传；可执行业务动作仍需显式触发及后端鉴权。

各页同步同一来源的事件：谁在什么时间做了什么、问了什么、谁回复什么、要求输出什么、上传什么。右侧消息气泡附服务端时间戳、操作者/回复者和可追溯事件标识；缺失身份或时间明确未知，不伪造。请求、正在处理、已完成、失败/未知分别展示，不能将请求气泡当完成回执。

先审当前事件/消息/回执接口，复用已有字段；需要新增接口先冻结最小契约。增量实时刷新和页面切换去重，按customer/tenant/权限隔离；服务端版本确定排序与当前性，客户端动画不改变业务状态。后续分支仅按真实结果逐步展开，不预绘已完成未来链。

## 串行待办

1. 修订4项过时前端回归：替换已被用户撤回的旧面板断言，覆盖新聊天的输入/发送、输入法、跨页草稿、身份切换清理；保留权限与误发保护。
2. 实现单节点向右滑动，验证首尾、重复点击、回退、客户切换与刷新。
3. 接入统一时间线和右侧带时间戳的气泡，覆盖提问/要求输出/上传/回复；各页从同一持久记录更新。
4. 针对改动执行回归、typecheck/build及真实页面验收，再交回CTRL。不扩大为3D或全架构重写。

## 后端与模型接续清单

上传授权投影与路由未装配；单件/组合分析scope未接通；预测评分不是概率。先复用稳定接口，不以界面补造后端结果。

GLM-5.2高频测试作为后续独立串行批次：先核对docs/v0.3/real-api-qa的出站和usage口径、未知跨scope行为，再选5条差异明确的案例；实际出站、重放、未知、费用与源码版本分别计数。每批有上限，发现重复发送或未知绕过立即停止；不无限后台空跑、不为用完额度消耗，不与页面任务并发。既有用户费用授权不等于更换厂商或覆盖账本。

## 验收

四页相同事件ID对应同一时间/操作者/内容；刷新后一致；重复点击不重复业务调用；未知不能自动重试；跨客户不串记录。动画结果和服务端动作分别验证。功能验证、模型质量与用户视觉接受分开报告。
