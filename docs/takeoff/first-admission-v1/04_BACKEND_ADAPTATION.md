# 后端最小适配与裁剪计划

适用版本：TAKEOFF-FA-1.0.0。目标是将现有能力接到首次回租准入看板，不重建通用风控平台。

## 1. 实际基线与一个关键缺口

本次远端读取基线：`main@8c6d3b0edc7d0c467ab6876a765b80a30b1e268b`。用户本地工作树、数据库和运行服务未被本包读取或验证。

已读取源码显示现有客户主档、材料/事实、授信评估与正式额度已分层；已有工作本也已更新为二维事项卡及统一上传入口，不是最早的纯Tab或双上传形态。不要依据旧交接重新从头写一套。来源见06的R2–R6。

**必须先核对的接口缺口：** 当前实现说明明确 `decideAssessment` 只有 reject/withdraw，正面正式批准走 `facility.approve`。这不等于本轮所需的“正面预评估结论人工确认”。来源见06的R7；接续时必须对实际方法与路由再核验。

正确处理：复用现有评估、方案、依据包和决定记录，增加最小的、明确不产生授信效力的确认命令/状态投影。接口名称与存储落点在盘点后定，不在文档中伪造已存在端点。不得通过先创建额度、批准额度再隐藏结果来模拟预评估完成。

## 2. 保留的既有职责

| 既有区域 | 本轮应复用的职责 | 不应继续扩张的方向 |
|---|---|---|
| Front | 客户工作上下文、材料/核验/问答/结果组件、状态订阅、受控操作 | 旧全生命周期、演示模式入口、多套工作台 |
| Edge | 已认证的前端入口、资源授权、读投影、消息与回执传输 | 独立业务真相、浏览器自报角色/客户归属 |
| Back/A | 客户身份、证据/事实、评估、依据包、决定、事件、幂等与事务 | 本轮自动调用正式额度、支用和资金路径 |
| Connectors | 一次接收原件、校验、解析协调、可信客户绑定、回写A | 重复上传链、逐客户手工映射、为走通而SQL补状态 |
| Back/B、Back/C | 实际被调用的任务执行、分析、规则、恢复与预算能力 | 默认全量重跑、所有Agent常驻、未经测量推倒重写 |
| Back/D及现有测试 | 最小闭环、权限、版本、去重、恢复和本轮反例验证 | 只报总用例数，不验证这张页面能否真实办结 |

这些是职责映射，不是新建六个服务的要求。哪些服务必须启动，以接续时真实调用关系为准；不先拍脑袋合并或拆分。

## 3. 唯一数据流

```text
用户操作/上传
 → Edge认证、客户归属及操作权限
 → 既有统一材料通道（Connectors）接收真实原件
 → 权威客户绑定与A登记
 → 解析/事实提取，保留来源与未知
 → 受影响领域的规则与模型分析
 → A登记分析、发现、依据、候选方案及事件
 → Edge/已有读接口投影二十格、顶部、流程、记录、材料与待办
 → 人工确认当前预评估版本（再次校验）
 → 保存结果并读回；不触发额度或资金操作
```

各服务不要求一笔跨库大事务。A内的权威写入与事件使用既有事务/可靠事件机制；跨服务以稳定标识、回执、幂等和可恢复状态衔接。失败/未知不报done；旧输入的迟到分析不得覆盖新方案。

## 4. 前端需要的最小读取面

下面是**拟适配的读模型要求**，不是已部署API，也不是让执行者另建同名数据库表。

```text
AdmissionView
  scope: tenantId, customerId, assessmentId
  revision / asOf / sourceStatus
  customer: displayName, legalName, customerId
  request: productType=sale_leaseback, requestedAmount, equipmentRefs
  candidate: version, suggestedAmount, suggestedTerm,
             referencePrice, priceBasis, conditions,
             tendency, basisRefs, inputVersion, isCurrent
  assessmentState: collecting / assessing / waiting / frozen /
                   awaiting_human_review / completed / withdrawn
  result: outcome, confirmedBy, confirmedAt, confirmedVersion,
          scope=preassessment_only
  cells: 5 domains × 4 rows, progress + blockers + outputs + allowedActions
  nextActions / findings / evidenceRefs / eventCursor
```

状态名可映射现有枚举，不能为配合文档任意改旧状态机。必要的新状态由兼容扩展承载并测试。`revision`及当前性来自服务端，不是页面时间戳。

所有引用必须有客户和评估范围；读取别的客户、用他人requestId查回执均要拒绝。用户不复制内部ID串联流程。客户简称不是可信绑定依据。

业务真相是A等现有权威记录；二十格、流程图和时间轴都是投影，不是各写一份状态。可用现有读取面满足时不新增聚合平台；若需要薄聚合接口只输出视图，不夺取业务写入权。

## 5. 命令与确认语义

必须能够完成的操作：登记首次回租需求、提交原件、查看来源、发起/回答补证、纠正/复核事实、按需分析、读取候选变化、人工确认预评估、结束/撤回本轮。

每个操作先填写一个小型映射：页面入口 → 现有服务方法/路由 → 权限 → 数据落点 → 回执与状态变化 → 受影响测试。没有明确落点时不要画可点的假按钮。

新的正面预评估确认至少校验：人类身份及权限、同客户/本评估范围、当前方案及证据版本、与该结果相关的硬阻断、稳定requestId。成功后写入确认记录和事件，并可重读。失败不部分写入。

建议用机器可断言的不变量验收：本次确认前后，`credit_facilities`、`financing_requests`、`exposure_entries`没有因该动作新增或改变业务行。测试允许只读比对，不允许SQL补业务结果。

负面结论、撤回也必须可记录，但不等于删除客户。存在旧正式额度的历史测试环境不可被本轮“重置”。

## 6. 原件、模型与安全边界

统一一次上传以当前`originals-panel.tsx`和`ChannelCard`路径为起点。核对实际文件格式能力；PDF/扫描件/图片无法可靠抽取时返回待人工，不编造字段。模型可以做可用的视觉提取，工具不支持时如实标未接入。

原件与提取文字属于不可信输入；其中“忽略规则”“直接批准”等内容不得变成执行指令。模型工具权限、外发范围和预算在服务端限制。客户端不持服务密钥，不通过MCP绕过本轮授权。

不因一次模型API成功就宣布整条业务通过。分开验证确定性规则/工具、结构化模型输出、实际登记与页面消费。记录调用来源、模型/规则版本、运行ID、输入依据与失败；没有费率时成本为未知，不报0元。

真实API仅在用户明确选择提供方、数据范围与预算后调用。现有凭据在受控本地环境使用，不复制到交接、日志或Git。不得假定过去的一次测试授权等于本轮无限费用授权。

## 7. 必要裁剪：去掉无关功能，不删除可靠性

按“停用 → 确认无引用/无数据依赖 → 删除”处理，不以目录名或文件数量判断垃圾。

| 类别 | 执行方式 |
|---|---|
| 旧全生命周期页、合作历程、底部示例卡、旧图/旧任务入口 | 从本轮入口和构建路径移除；真正无引用且可恢复的文件删除 |
| 已退休3D/地图/手柄/世界原型 | 先检查近期清理成果，禁止从旧包复活；剩余无用资源按清单删除 |
| 旧训练/模拟入口 | 不混入真实办理；保留测试必要夹具，删除不再使用的展示分支 |
| 额度/用信/租后底层代码 | 本轮不调用；存在历史数据、共享函数或测试依赖时不能整块删除；单列评估 |
| 旧设计文档 | 失效入口更新；无保留价值且有可恢复来源的冗余文档删除，避免下一位再读错 |
| 原件、决定、审计、迁移、权限、幂等、恢复代码 | 不作为无用历史随意删除；需保持业务和兼容性证据 |

删除前保存工作区差异和必要未跟踪文件备份，记录路径、理由、引用检查、恢复方式及受影响测试。仅使用已确认的自有测试资源；不清空未知数据库，不停止未知服务，不改Dify等其他应用。

本包不包含自动删除脚本，不自动提交、push、切分支、创建worktree或执行reset/clean。先保住在制代码，再增量适配。

## 8. 分工与不扩面

本包更新产品优先级，不自行修改现行施工协作约定。已读仓库约定为Codex负责架构、契约和独立验收，小修改可直接做，中大型实现交ZCode；单文件单writer、依赖环节串行，不使用隐藏委派。

接续者先核对该约定是否被用户后续明确改变；没有变化则遵守，不因“最高产品权威”擅自扩大执行授权。可形成必要实施任务，但不要为了凑四路而制造四套系统。
