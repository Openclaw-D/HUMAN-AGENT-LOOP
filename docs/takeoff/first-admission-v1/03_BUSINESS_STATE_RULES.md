# 首次回租准入：业务与状态规则

适用版本：TAKEOFF-FA-1.0.0。本文定义产品语义，不制定机构真实授信政策、金额上限、利率或期限。

## 1. 对象与边界

客户是法律主体及材料归集对象；本次首次评估是客户下的一个受控工作范围。`assessmentId`或兼容现有评估引用可用于状态、分析、消息、方案和决定关联，不要求新建Project域。

此轮材料更新、分析重入与方案修订都属于本次首次评估，不能被误建为第二笔融资申请。客户、评估、方案版本、模型运行编号各有职责，不互相替代。

## 2. 五领域的工作与决策意义

| 领域 | 核心工作 | 必须区分 |
|---|---|---|
| 商机 | 主体、首次回租需求、申请金额、用途、设备范围、联系人 | 客户表述与已验证事实 |
| 政策 | 机构已配置的行业/地区/客户/交易要求、硬条件及合法例外边界 | 真实已批准政策、合成测试政策、政策未配置 |
| 信审 | 经营现金流、实际及隐性负债线索、关联风险、偿付压力 | 资料完整与真实偿债能力 |
| 商务 | 在风险和资产边界内比较金额、期限、价格、增信、客户接受度和收益 | 参考报价与正式合同；收益高与风险被覆盖 |
| 资产 | 回租设备存在性、权属、同一性、权利负担线索、合理价值及处置条件 | 设备存在与权属清晰；账面价与可实现价值 |

资产是准入组成部分，早期即可开展。最终方案要交叉引用信审、资产、政策等当前结果；商务可以先试算，但有明确未核验条件时只显示候选/待复核。

## 3. 局部顺序，部分并行

同一个核验事项有实际依赖：取得可用材料 → 分析/核验 → 必要人工复核 → 收口。但同一领域的不同事项、不同领域之间可以并行。

例如商机输入部分完成、智能处理部分完成、人工核验部分完成可以同时成立。不能要求输入整列100%后才允许任何智能或人工工作。

有权人工可以提前纠错和补充；“人工”不是只等机器完事后的按钮。只有明确的正式确认需要满足规定的前提。

自动推进仅适用于已满足条件且在权限范围内的处理动作。没有报错不等于通过；尚未运行、缺少规则、缺关键证据都不是默认绿灯。

## 4. 每个格子的进度与结果分开

后端事实是具体事项、输入版本、结果和回执；圆圈只是粗粒度展示。

建议读模型包含：

```text
CellProgress
  domain / row
  workVersion / basisRefs
  requiredItemCount / satisfiedItemCount
  displayBucket: 0 | 25 | 50 | 75 | 100 | null
  running / completed / needsReview
  blockers[]: reason + scope + requiredAction
  outcome: 正面 / 调整条件 / 负面 / 未定 / 不适用
  responsibleParty / allowedActions[]
```

以上为适配目标，不声明已有字段和接口。未知值用null，不伪造0。

分档工程默认：存在稳定、可解释的必要事项集合时，以完成比例向下取25%档；工作闭合前最高显示75%，只有办结条件满足才能显示100%绿。事项数量为0或适用性未知时不自动100%。任务刚启动但尚未达到第一档，可使用浅黄细外环表示运行，不能按计时填满。

如果现有子流程使用四个明确里程碑而非数量统计，可使用经确认的里程碑档位；必须显示计算依据与版本，同一格不得混用两套算法。不要人为把任何复杂工作凑成四份材料。档位是展示粒度，不是风险概率或真实工时百分比。

必要事项集合随有效新证据变化时可以调整，记录分母及版本变化。当前进展可以回退；旧“当时已完成”作为历史保留，不删记录。

“完成”行是本领域本轮收口汇总，不是第四个执行者；没有独立任务可以采用未闭合/已闭合二态，不为了四分之一强造审批步骤。存在真实闭合清单时才细分。绿色不代表支持融资，负面判断也可以完成。

重大拒绝依据已核实且足以结束评估时，不要求无决策价值的其余分析全部做完。未开展部分标明不再需要/不适用及原因，不能伪装已执行。硬规则禁止正面放行，不禁止记录有依据的负面终结。

## 5. 证据与方案更新

核心链：原件 → 带来源的事实 → 风险/冲突 → 领域意见 → 同版本方案 → 人工确认。

原件、主体、设备、日期、核验人/模型和版本可追溯；同一材料的重复上传、不同Agent复述或格式转换不构成独立新证据。互相矛盾的合同/凭证不能按“最后上传者覆盖”处理。

新证据能改善或恶化判断。系统只更新受影响领域及依赖结果；共享的负债、权属等重大事实变化必须影响所有相关领域，不能为节约调用遗漏。

每版方案至少包括：申请金额、建议额度、建议期限、参考价格及口径、必要条件、tendency、basisRefs、ruleVersion、输入版本、模型运行引用、产生时间、变化理由。

金额/期限/价格必须来自同一版方案；不能把最高额度、最长期限、最低价格分别取自不同方案。未知建议额度不写0。生产费率、资金成本、期望损失等未提供时，明确缺口，不能自动生成“最优价格”。

客户产品上限不是目标进度。500万元只可能是待配置/用户确认的边界示例，不是本轮默认政策；更不能从旧仓库默认值推定现在政策。评估可以在远低于上限时完成。

贝叶斯在本轮体现为证据更新后改变判断，而非“交材料积分”。没有经验证的先验、似然和校准结果，不显示伪精确违约概率、后验分数或置信度，不把模型自报概率当额度公式。数值模型未来可经授权验证，不是本轮交付前提。

## 6. 三种异常不能混为一谈

| 情形 | 状态含义 | 能否继续 |
|---|---|---|
| 待补 | 关键证据不足或不清楚 | 保留其他已知结果，补证与无关工作可继续 |
| 冻结当前方案 | 已有依据发生重要冲突/变化，不能安全继续确认当前方案 | 禁止相关正面确认，允许看证据、补件、纠正、复核和必要重算 |
| 不予准入 | 依据已经核实，由有权人员记录负面预评估结论 | 本次评估可以结束，客户档案及历史保留 |
| 技术失败 | 超时、解析失败、模型/网络/权限配置问题 | 进入重试、对账或修复，不直接降额、清零或拒绝客户 |

冻结须有范围、来源、时间和解除条件。模型可以提出疑点；是否机械阻断由受控规则及当前依据决定，不由聊天措辞决定。重要风险未核实先作为待核验线索，不标已证实。

解冻需要解除原因和当前有效依据；简单点“我知道了”不能解除不可豁免条件。白霜效果仅投影状态，不承担控制逻辑。

## 7. 首次重资源投入与停止条件

首次评估覆盖必要风险领域，对关键异常使用更强模型、更多交叉验证或人工核验。已明确的基本事实不重复分析；不把“全维度”做成无限审计。

强模型按需用于关键判断。轻量1–2B观察模型是用户提出的可选实现方向，不是已验证配置或必装依赖；模型型号、费用与准确性需实际验证。优先事件触发和去重；只有授权、预算、频率和上下文边界明确后，才启用低频心跳。无新事实/任务到期等有效触发时不反复读取整包，不准备用不断发言证明在线。

观察模型只能建议唤醒、摘要和提醒；不能改建议额度、状态、政策或批准结论，不能充当安全门。预算用尽暂停非必要推理，准确展示未完成，不能因此宣布低风险或自动拒绝。

可以完成的条件：形成了足够支持本次决定的有效证据，必要核验/冲突已得到与结果相匹配的处置，有权人员确认当前版本结论。结果可为支持、调整条件后支持、不支持；客户撤回另记为行政结束，不伪装风险拒绝。

未完成但需暂停：待客户材料、未配置关键政策、重要冲突未解决、授权不足、资源预算不足。暂停不算通过。

## 8. 人工确认与结束

人工确认绑定当前客户、评估、方案版本、证据快照、规则版本及结论；提交时服务端重查权限、当前性、阻断与幂等。只引用旧页面“看起来绿了”不够。

现有接口如果只能拒绝/撤回，必须增加明确的预评估确认语义；不能借正式额度批准接口来完成本轮。不得为了演示而创建占位授信设施。

确认后结果只表示首次预评估结论；不修改信用设施、融资申请或敞口账本。若后续重要证据推翻已确认依据，保留历史结论并显示需复核，不能覆盖原确认或默认重开正式决定。

## 9. 未知信息的处理

机构真实准入规则、岗位权限、产品上限、价格口径、模型凭据与费用预算由用户/机构明确。本包不替他们制定。

开发可使用清楚标记的合成规则与合成客户，走正常服务入口和真实持久化。需要业务裁决时只提会阻断当前最小闭环的具体问题；不要因为非关键数值未知而重开整个产品设计。
