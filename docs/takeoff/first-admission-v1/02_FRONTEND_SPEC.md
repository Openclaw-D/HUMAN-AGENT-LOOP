# 前端最终结构与交互规范

适用版本：TAKEOFF-FA-1.0.0。冲突时服从 `01_TAKEOFF_CORE_AUTHORITY.md`。

## 1. 页面结构

桌面横屏，不做手机适配任务。建议验收尺寸1920×1080及1366×768；比例可为最小可读宽度微调，但不改变信息结构。

```text
┌ 客户简称＋客户ID ─ 申请金额／建议额度／建议期限／参考价格／预计 ─ 流程 记录 材料 待办 返回 结束 ┐
├────────────────────────────────────────────────────┬──────────────────────┤
│       商机      政策      信审      商务      资产   │ 业务 政策 信审 商务 资产 见微 │
│ 输入   ○         ○         ○         ○         ○  │                          │
│ 智能   ○         ○         ○         ○         ○  │ 消息／所选格子事项／依据摘要 │
│ 人工   ○         ○         ○         ○         ○  │                          │
│ 完成   ○         ○         ○         ○         ○  │ 上传与工具栏／输入／发送    │
└────────────────────────────────────────────────────┴──────────────────────┘
```

没有上方“客户级主页面”等海报标题、没有总进度条、没有额度使用率、没有底部示例卡或合作历程。顶部靠近页面上沿，正文两区占满剩余高度；消息和材料内部滚动，不让正文不断把页面向下撑长。

左侧约80%、右侧约20%；窄桌面下右侧优先保证可阅读，记录实际比例。详细合同、图片和对比表不硬挤进右侧，按需放大。

## 2. 顶部摘要

| 字段 | 必须遵守的含义 |
|---|---|
| 客户简称 | 建议四字；点击可查全称与主体标识；不同主体同名不能自动合并 |
| 客户ID | 稳定且唯一；不能用简称作数据库键；由服务端授权确定当前客户 |
| 申请金额 | 客户本次提出的需求，不能与建议额度混为一项 |
| 建议额度 | 当前方案证据可支持的候选值；没有判断时为“待评估”，不是0 |
| 建议期限 | 当前方案的建议融资期限，单位明确；不是授信有效期 |
| 参考价格 | 价格口径、单位、是否包含费用须在详情说明；未配置时不编造利率 |
| 预计 | 本次评估的预计完成时间；无法估计显示“待估”；等待客户时可以标“待补”，不能给承诺式假倒计时 |
| 方案标记 | 小字显示方案版本、更新时间、暂估/待复核/冻结等；不是额外统计卡 |

数值变化显示前后值与原因入口，不能只用上涨绿色制造“变好”暗示。所有字段属于同一候选方案版本。产品上限可以放详情；不做涨满上限的奖励进度。

“返回”调用现有宿主回退；没有目录能力就明确返回当前上层入口，不新建目录项目。“结束”打开本次评估的受控结论确认，不能一键关闭客户。

## 3. 二十格的可见状态

- 行头：输入、智能、人工、完成，配黑灰小图标，不在标题下加小作文。
- 列头：商机、政策、信审、商务、资产，同样只用短标题与小图标。
- 圆形大小、描边和位置一致；完成后纯绿整圆，不再画对勾。
- 白底细灰黑边表示尚无已完成档位；浅黄填充按右上0–90°、右下90–180°、左下180–270°、左上270–360°顺序推进。
- 100%只在工作办结条件满足时显示绿色；执行中、缺材料、待人确认不得靠时间转绿。
- 卡点：不把整格染红；角标“!”或锁＋可读提示，正文保留当前进展。
- 冻结：当前方案或受影响格子白色霜边，附“冻结”与解冻所需动作；整页仍可读、补件、提问。
- 圆不是按钮式手工切换器；点击打开工作内容，不直接改业务状态。
- 屏幕阅读器、键盘焦点及提示文字能读出状态、档位、原因；不只依赖颜色。

精确分档与拒绝结果见业务规则文件。无可靠分母或不适用事项不得硬补进度。

## 4. 悬浮、点击和内容分层

**悬浮/键盘聚焦：** 同行、同列淡黄色交叉高亮；交点边框略深。短提示只说“什么格、做到哪里、是否卡住”。悬浮不启动模型、不改状态、不发送业务命令。

**单击：** 保持选中，打开真实事项面板。标准顺序是：当前问题 → 依据位置 → 需要谁做什么 → 允许动作 → 本轮输出与历史。

简单问题可在右侧或轻悬浮层处理；复杂流水对比、资产权属冲突、多个主体关系，使用同页大抽屉或模态层，提供放大与还原。关闭后恢复原格子、滚动位置、草稿与助手上下文。一次只维护一个详情上下文，避免弹窗套弹窗。

材料标注必须锚定原件版本、页码/图像坐标/文本范围及标注人或模型。没有可靠坐标就只给文本引用，不能伪造AI“已经圈出”的位置。修改、更正后保留旧标注关联，不静默贴到新版。

## 5. 右侧六助手与输入区

专业入口为业务、政策、信审、商务、资产，全局见微负责汇总与协调。一个消息区、一份草稿；切换助手不丢失客户、评估、所选格子和材料引用。

单击切换，长按插入@；同时提供明确的@入口及键盘方式，长按不是唯一可发现操作。正常人机对话左右呈现并标明身份；多个助手可以参与同一线程，但不能把内部讨论自动发给客户。

助手平时安静。只有相关事件、用户点选调用或@才处理需要的内容；提醒去重，不让六助手重复一件事。五个专业入口不等于五个常驻进程或六份完整上下文。

工具栏保留用户指定能力的入口结构：上传、语音、表情、字体、聊天记录、Skill、MCP、compact、ToDo、Goals；宽度不足放入同一工具溢出菜单，不另建一套Harness界面。业务链必须接通上传、会话与必要分析工具；未接入的扩展能力必须明确禁用/标未接入，不能做假成功。真正对外工具调用仍需可用权限和授权。compact只压缩模型会话摘要，不删除原件、决定或审计记录。

右下为发送/回车图标；输入法候选确认不能误发送。采用Enter发送、Shift+Enter换行的工程默认，并支持清晰提示。

## 6. 辅助页面：只通过入口进入

| 入口 | 视图规则 |
|---|---|
| 流程 | 从左到右的只读依赖/办理图，节点固定布局；可缩放、主要水平平移/滚动；不能拖动节点、编辑连线。显示并行依赖与阻断，不伪装严格流水线或数值贝叶斯模型 |
| 记录 | 从早到晚的纵向时间轴，可定位最新；记录材料、事实、分析、方案和人工操作。方案变更显示增减，报价建议变更不写成正式额度批准 |
| 材料 | 同一证据库提供主体/类型/时间查找、版本/主体对比、已证实关系视图；关系不确定要标明，不能靠同名推断合并。优先真实列表与对比，其他能力未接通明确标注 |
| 待办 | 谁处理、处理什么、什么证据算完成、当前可执行动作，点击回原格子 |

内容区域提供全屏/还原；这些不是首页下方的小卡。辅助页是相同业务记录的投影，不保存另一份可独立修改的办理状态。

## 7. 纸感、配色和动效

设计令牌为可调工程默认，不是新增品牌决策：

| 用途 | 默认 |
|---|---|
| 纸底 | `#F8F5E9`，很浅的暖黄 |
| 正文 | `#222222` |
| 次级文本/边线 | `#737373` / `#B8B8B8` |
| 白色 | `#FFFFFF`，空圆、霜边与必要留白 |
| 进行 | `#EED267`，浅黄，须明显区别纸底 |
| 完成 | `#4B7B45`，绿色 |
| 警示 | `#B63737`，红色 |

纹理低对比，粗纸纤维可感知但不脏、不厚黄、不影响小字。页面UI、图标、助手头像只用上述色系；用户原件保留原始颜色，禁止为了配色修改证据。

优先CSS Grid/Flex、SVG或CSS扇区及短过渡。悬浮120–160ms、点选/抽屉160–220ms、状态变化200–300ms为工程初始值。只让正在运行的少量元素有轻反馈，等待人工时不持续旋转。无大面积弹跳、粒子、雪花或循环脉冲。

纸纹优先一个静态可平铺小纹理；SVG噪声可用于生成，但不每格运行高成本实时滤镜。冰霜用白色蒙版边缘/轻磨砂，不使用蓝色霓虹。不强制新装动效库，不引入WebGL或3D引擎。

支持系统`prefers-reduced-motion`。正式代码仍采用当前React/Vite/TypeScript和锁文件，不为了这页进行框架升级。只读流程图优先现有SVG/布局能力；确需React Flow时才增加依赖，并关闭节点拖动与连线编辑。技术文档来源见06。
