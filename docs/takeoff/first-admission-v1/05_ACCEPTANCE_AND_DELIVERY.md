# 实施顺序、验收与交付

适用版本：TAKEOFF-FA-1.0.0。先完成一个真实闭环，再扩其他非关键细节；不能只交一张有动画的页面。

## 1. 四个小阶段

### A. 对齐与盘点

把本包落到既有仓库，更新最高产品指针；记录本地/远端HEAD、工作区修改、实际运行资源。核对当前源码而不是只读旧HANDOFF。

交付一页清单：可复用、必须补齐、本轮停用/待删。首先解决“人工确认预评估结论”与“正式授信批准”的接口边界。数值政策未知时使用明确合成配置，不重开产品设计。

### B. 主页面与真实读写映射

在现有工作本内替换布局为二十格＋右侧助手；取消底部卡、合作历程、全局进度和已用额度图。让材料、当前问题、回执和候选方案从真实后台读回。

先有可验证读写，再做纸感与短动效；不得借临时UI状态冒充服务端完成。改源码后同步构建`Front/dist`，确认运行页确实加载同版构建。

### C. 本地业务闭环

使用独立合成客户、真实文件字节、受控合成规则和真实持久化，完成上传→核验→候选变化→补证/纠正→人工确认→退出/重启读回。测定失败路径，不SQL填结果、不预置Gate伪装通过。

### D. 真实模型API与比赛可演示性

在明确授权与预算内，接真实模型API跑同样的结构化链。分别报告模拟、真实API、前端、后端和人工验收状态。模型失败应可恢复，关键演示不能依靠无边界重试。

保留一条启动方式、一个主入口及一段3–5分钟可重复操作脚本。不建设生产部署、支付或复贷功能。

## 2. 必须通过的验收集

| 编号 | 场景 | 通过判据 |
|---|---|---|
| T01 | 页面与范围 | 五列四行，左看板右助手铺满；没有提款、租后、结清、合作历程、总进度/使用率或底部演示卡 |
| T02 | 单次上传与来源 | 一份原件只走一条业务上传链；权威客户登记成功；能从发现/方案回到真实原件 |
| T03 | 部分并行 | 输入、智能、人工可围绕不同已就绪事项各自部分完成；资产核验不等待商务全部完成 |
| T04 | 有利与不利证据 | 候选方案按实际配置与证据改变，可增可减；每次变化可解释；不是前端硬写涨额脚本 |
| T05 | 重复/相关证据 | 重复上传及多Agent复述不增加独立证明力、不额外涨额、不重复业务写入 |
| T06 | 冲突与冻结 | 重要冲突阻断受影响的正面确认；原建议保留为冻结版本；可以补件、查看和复核；不可豁免门不能一键解除 |
| T07 | 技术失败 | 模型超时、解析失败、上游不可达不会导致客户自动拒绝/额度清零；能够同号重试或对账 |
| T08 | 新旧版本竞争 | 新材料到达后，旧运行迟到结果不能覆盖新版；只重做受影响范围，旧决定保留 |
| T09 | 正面人工确认 | 服务端校验身份/范围/当前性；确认只产生预评估结果；正式额度、融资申请和敞口账本不受此动作改变 |
| T10 | 负面/撤回结束 | 有依据的负面评估可完成；撤回与拒绝分开；不删除客户、不强制所有未必要格子刷绿 |
| T11 | 重复提交与恢复 | 同requestId同载荷单效果；异载荷冲突；退出/重启能恢复原件、方案、消息及结果 |
| T12 | 越权与不可信输入 | 另一客户/其他人回执不可读；假角色不可写；原件中夹带指令不获得系统或审批权限 |
| T13 | 点选与视觉 | 行列高亮、右上顺时针黄扇区、绿色无勾、白色冻结；无蓝紫青UI；放大还原保留上下文；输入法不误发送 |
| T14 | 辅助页与模型预算 | 流程只读可缩放水平移动，记录/材料同源；Agent安静去重；未授权API不调用、预算不足不假完成 |

T04的金额方向与预期由受控合成政策和已知证据推导，不拿随机真实模型的精确数值作为稳定断言。真实模型部分重点测结构、引用、权限、失败和业务回写；业务建议质量另由人审阅。

所有测试附：运行版本、配置模式、输入、动作、断言、结果、证据位置。`NOT_RUN`、`BLOCKED`和`FAIL`不能并入`PASS`。历史套件用例数不代表当前版本验证。

## 3. 一个最小合成客户足以起步

准备一个纯合成制造业客户，首次提出回租需求。合成材料包含主体资料、经营/负债资料、设备范围及权属/价值支持材料；不使用真实客户数据。

同一轮依次注入：正常证据、改善证据、不利或冲突证据、重复材料、纠正材料，并注入一次技术故障。所有数值和规则注明测试来源，不暗示公司制度。

验收重点不是“最后额度高”，而是：该变化时变化、该停时停止、停后知道为什么及下一步、人的确认不被机器绕过。

## 4. 固定快照再验收

在各写入者完成并构建后，固定源码/构建、配置模式、依赖与数据库迁移版本，再跑页面链。联调期间仍有并行改动时，不能把不同快照的成功片段拼为一次通过。

按风险做定向回归及必要原有安全/状态测试；不无收益地反复创建大量数据库和全量跑所有历史任务。清理只处理登记过的自有临时资源。

## 5. 交付只需四份简短运行记录

- `CURRENT_STATE.md`：已实现、未接入、阻塞、实际入口与运行版本。
- `ADAPTATION_MAP.md`：页面动作到接口/持久化映射、最小新契约和已停用范围。
- `TEST_RESULTS.md`：T01–T14及必要回归结果、配置模式、证据位置。
- `CLEANUP_LOG.md`：删除/停用清单、理由、备份/恢复位置；未删除的共享依赖为什么保留。

附必要页面证据和可重复演示步骤即可，不生成大量重复交付报告。开发自验、独立复核、用户视觉/业务验收分别标明。比赛可演示不等于生产可用。

## 6. 完成标准

普通使用者在主页面能回答“现在进度在哪、卡在哪里、谁处理、补什么、方案为什么变化”，并实际完成首次回租预评估的正面或负面人工确认；结果退出后仍可追溯。

无需达到产品额度上限，无需建设提款或租后功能，无需让所有辅助工具都伪装接通。必要闭环和未接入边界都必须真实。
