# V0.4 最终收敛：三客户四页完全同步

用户最新明确要求：只把好、中、差三个客户做清楚，不再扩展其他功能。沿用COLUMN_ADVANCE_R2整列推进、正常约五次/补证约六次、拒绝提前停止及页面不移动。

平台、材料、决策、流程四个独立页面必须来自同一客户、同一专业列、同一业务轮次的持久事实：平台该列进度；材料该列上传了哪些原件/版本及状态；决策该列的依据、候选、用户选择和后续路径；流程该轮谁何时做了什么及最终结果。四页不能各自推算一套进度。

统一关联键至少能追溯customer/domain/round/action或request/event/material版本/decision选择；字段名按真实后端契约。服务端版本和事件确定状态。异步期间各专业可不同状态，但四页对同一事实必须一致；刷新、切页、重连后可收敛至同一已确认版本，不能旧结果混入新版本。后端未落盘的动作仅标请求中，不能展示完成。

决策树：用户实际选择的节点/分支黑灰底、浅色字、文字加粗形成反色，未选节点白灰。建议默认首选不冒充用户选择；置信度变化不得静默覆盖已选路径。选中态同时有语义标记，不只靠颜色；失败/阻断等必要状态可另显示。路径保留历史与材料版本，最终输出能回溯选了什么、为什么及结果。

Front：将上述要求纳入当前Front实现，保留四页、现有用户布局与简单动效，禁止推进时移动视口。先实现可独立完成的真实选中态和统一读状态，不用本地四份数组造业务记录。接线缺口明确留在本任务，禁止假装全部完成。
Back：同步更新event-advance-contract内的四页字段映射、版本/关联键、状态读源与当前真实接口差距，沿用文档ownership，不抢在制ZCode实现。缺少统一推进/持久关联是整链阻点，不能仅靠前端解决。

完成标准：三例各有一份实际点击/请求/事件/四页对照证据；好例全流程真实完成钻石，中例信审真实补证重评后钻石，差例拒绝/下游停止/保留记录归档红叉。选中路径、材料版本与最终输出相符，刷新仍一致。实现通过、测试通过、用户视觉验收分开。

本轮不再扩展其他业务功能。不新增自动夜间监督、真实模型消耗或发布。各执行任务只在本任务交付后停止，不读取/创建/唤醒/控制其他对话、不发送协调反馈；所有协调由主任务负责。禁止subagent/worktree/commit/push/共享服务重启。
