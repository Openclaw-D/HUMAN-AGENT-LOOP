# 状态卡片百叶窗翻转过渡

用户最新明确要求：锁变扳手、扳手变绿勾时，卡片以中间轴为圆心像翻卡片/百叶窗一样翻过来。

Front在既有状态卡片组件和相应样式内局部实现：以卡片中央横轴为旋转轴（transform-origin:center，rotateX＋适度perspective），建议总长约600–800ms，前后两面/背面隐藏，转到侧面时更换图标。完成一次翻片后正面图标正立、清晰，不镜像、不倒置。优先做一次180度前后面翻转的完整视觉过程，不做多次空转；若使用360度需保证中段换图及最终正立效果。

只在真实状态发生lock→wrench、wrench→check时触发，不按点击计时伪造状态；初次加载、刷新恢复、切客户、同状态重渲染不重播。真实状态快速到达时以最新状态为准，可合并/打断动画，不延迟业务回执或最终状态；不能旧动画结束后把最新check/拒绝覆盖回wrench。
翻转的是原位置状态卡片/图标承载层，不改变格子尺寸，不滚动/平移页面；不新增图标或独立按钮。完成后只有实际running的扳手可延续已有运行轻动效，锁静止。reduced-motion下直接换图或极短淡入，不翻转；aria状态及时反映真实结果，不等待动画。

ownership：Front既有status-object及直接相关样式/状态测试/dist；报告 docs/v0.4/results/status-flip/。保护当前前后端接线和用户布局，不修改Back或业务状态。先核对当前状态动效，复用/替换避免两套动画叠加。验证两种变化、快速变化/失败打断、重挂载、减少动效和格子不位移；typecheck/build及自有预览视觉检查，禁止操作用户现有标签/viewport。

该任务是本轮前端小改，不替代整列真实推进缺口修复；结果仅留Front任务，不控制其他对话或发协调消息，完成后停止。
