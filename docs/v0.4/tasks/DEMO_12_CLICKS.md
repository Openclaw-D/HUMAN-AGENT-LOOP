# V0.4 三客户十二次推进展示节奏

用户最新明确要求：总共三个客户，每个客户点四次，共十二次主要推进，约五分钟，并配合简短步骤讲解。此为展示节奏，覆盖旧细颗粒技术节点导航的展示粒度；不改变实际业务权限、状态或结果。

前端按一个竖向业务流程呈现四个中等颗粒度的展示步骤。建议映射（按当前真实数据调整名称）：①客户与必看材料；②专业协作判断、依据与候选置信度；③人工选择及必要补证/补证后重评；④实际结论与下一动作。初始概览不另占一次主要推进；四次分别进入四步，末步不自动循环、不自动切客户。切客户与必要真实业务动作不硬凑进十二次点击统计。

三个客户复用同一结构，各自展示实际记录；可表达通过/拒绝/补充材料等真实分支，不预定三例结果。补证尚未完成就显示待补，不因展示进入第三/四步而伪造补齐。通过须区分建议支持、人工预评估确认与正式批准。

每步展示：本步做了什么、谁执行、服务端时间、材料/事件依据、判断摘要、候选与置信度、当前结果。未提供或未校准置信度如实标注。展示可审计判断摘要，不展示或生成模型隐藏思维链。

十二次指主要展示推进，不承诺十二次能完成所有真实办理。导航仍零审批/上传/模型副作用；需要执行的动作显式触发、鉴权并等待真实回执。使用已有记录时标明时间和版本，不冒充现场新调用。五分钟是目标而非已测成绩；可按每客户约80秒＋开场/转场约60秒设计简短讲解。

协作：Front将本节奏与用户正在直接调整的页面结合，不覆盖用户新UI决定；先完成当前在制小切片，再做最小展示适配，不扩大重构。后端接口和事件语义保持既有契约；缺少记录则明确未完成。结果仅留Front任务，不读取/控制其他对话，不给协调任务发送消息。
