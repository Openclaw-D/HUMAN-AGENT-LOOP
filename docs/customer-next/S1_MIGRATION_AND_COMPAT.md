# S1 提案 · 迁移设计、兼容说明与待决政策 safe default（任务 01）

状态：**设计提案（待总控冻结）**。实现窗口 S2（客户归集与证据映射）+ S3（账本与并发）+ S4（权限与 stale），范围 `Back/A/**`；本文只定设计与边界，不改运行态。

## 1. 数据库迁移设计

- 迁移文件序列：现有 `Back/A/migrations/001_init.sql` 不动；新增 `002_customer_credit.sql`（客户/关系/评估/额度/融资请求/账目/决定表 + 索引）。
- 幂等与可恢复（测试 A22）：迁移器记录版本表，逐版本事务执行；中断后重跑跳过已完成版本；`002` 内部按 `IF NOT EXISTS`/先查后建，重复运行零副作用。任何一步失败不损毁旧 `project/goal/evidence/audit` 数据。
- 新增列：`projects.customer_id`（可空外键）。**不**改写任何既有行；未匹配项目标 `legacy_unassigned`，不编造客户身份。
- 演练规程（S2 执行）：先在隔离库（新容器/新端口，不触碰 15432 旧容器与 `jw-v01-pg` 数据卷）导入快照演练；记录迁移前后行数、`projectId → customerId` 标识映射表、不可逆项清单；演练通过才安排对开发库的实施。
- 回滚说明：`002` 提供对称 `DROP`（仅删新对象与新列，`projects.customer_id` 置空回滚不丢原数据）；回滚同样先演练。

## 2. v1 兼容说明

- `/api/v1/**` 行为在 S2–S4 期间保持不变（含其禁键校验、principal 机制、outbox 事件词汇）；现有 v1 关键回归须继续通过（任务 01 §9 完成定义）。
- `Project` 不删除、不重用 `projectId`；投影层（V0.2 已规划的 Front 适配器）不受影响。
- 旧事件消费者按 `after=seq` 增量拉取的契约不变；v2 事件是**新增**类型（`CUSTOMER_*`/`FACILITY_*`/`LEDGER_*` 等），不改写既有事件语义。
- `staleReviewAck` 维持 v1.3 现状（技术兼容项，业务政策 PENDING-USER-RULING）；授信域不可豁免规则不接受通用 ack（S4 落负例）。
- 版本标识：A 服务启动 health 增加 `contractVersion` 字段（如 `v2.0.0-proposal`），部署与报告须能对出代码版本。

## 3. 待决政策与 safe default（未冻结前按此执行，不猜测公司规则）

| 编号 | 待决项 | safe default（开发期） | 解冻条件 |
|---|---|---|---|
| P-01 | 客户/关联组合并规则 | 不自动合并；合并=人类 `DecisionRecord` | 公司制度明确合并标准 |
| P-02 | 是否循环、还款是否恢复额度 | `revolving=false`；还款**不**自动恢复可用额（A17） | 版本化政策明确 |
| P-03 | 集中度口径（公司/关联组） | 单独约束检查；政策缺失 → `policy_pending` 阻断批准，不因未达 1,000 万默认可放 | 批准口径录入 |
| P-04 | 红线规则来源与不可豁免性 | 缺失即 `policy_pending`；不编造公司规则 | 规则原件入库 |
| P-05 | 审批金额档位与角色矩阵 | 矩阵缺失动作全拒（`policy_pending`）；jianwei 不默认超级审批人 | 公司批准矩阵录入授权目录 |
| P-06 | 利息/费用/担保计入敞口口径 | 本轮不计入；账本只记本金三态 | 政策明确后以 `adjust` 账目接入 |
| P-07 | 支用出账 | 只连受控模拟适配器；不调用真实银行/资金接口 | 独立授权 |
| P-08 | `staleReviewAck` 业务语义 | 维持 PENDING-USER-RULING；授信域硬红线不可 ack | 用户裁决 |
| P-09 | 1,000 万上限属性 | 产品上限配置（非监管限额、非默认批准额），可配置 | 用户/公司调整 |

## 4. 测试覆盖映射（设计 → A01–A24）

| 测试 | 设计机制落点 |
|---|---|
| A01 两渠道同客户 | 单一约束入口：客户→主额度串行；额度合并约束 |
| A02/A03 同名/同联系人 | `legalEntityRef` 唯一性 + 禁止自动合并（D1、P-01） |
| A04 重复材料 | 证据引用去重；文件数量不产生额度（D3/D8） |
| A05 有利后不利 | 新评估可降级/暂停；金额非单调（D3） |
| A06 上限+1 分 | `PRODUCT_CAP_EXCEEDED`，币种+单位明确（D4、§错误码） |
| A07 并发预占两笔 80 万 | 事务锁串行，第二笔 `INSUFFICIENT_AVAILABLE_AMOUNT`（D6） |
| A08 100 并发同 requestId | 幂等账目唯一约束 `(requestId, entryType)` → 单条效应 |
| A09 同键异金额 | `IDEMPOTENCY_REPLAY_CONFLICT`，零副作用 |
| A10 跨客户猜 ID | 全通道 tenant/customer 范围校验 + `NOT_FOUND` 不泄露 |
| A11 回执丢失重放 | 权限校验先于缓存回执；重放返原效应 |
| A12 付款 unknown | `settle_unknown` + 对账复核，不自动释放（D6、P-07） |
| A13 重复结算回调 | 结算事件幂等（requestId + entryType 唯一） |
| A14 暂停/到期 vs 支用并发 | 提交点事务内统一裁决（锁 + 状态复查）（D7） |
| A15 批准前依据更新 | 批准事务复查 basisVersion，`STALE_BASIS`（D7） |
| A16 降额低于敞口 | `over_limit` 显示、保留敞口、禁新增（D4） |
| A17 非循环还款 | P-02：不恢复可用额 |
| A18 模型输出额度字段 | `CreditCandidate` 合法但 authority=none，无激活通道 |
| A19 假角色 | 服务端授权目录校验；审计不含秘密 |
| A20 发票 vs 合同冲突 | 并存 + 冲突双留痕，禁 last-write-wins（D8） |
| A21 accepted 且 rejected | 投影带结论语义，工作状态≠风险通过（S1 API §6） |
| A22 迁移中断/重跑 | 版本表 + 幂等 DDL + 隔离演练（§1） |
| A23 DB 提交、outbox 失败 | 账目与事件同事务写入，恢复后补投（沿用 v1 outbox 语义） |
| A24 多子额度/直租回租并发 | 客户主上限 + 关联组约束，锁序固定（D4/D6、P-03） |

账本属性测试（随机序列、固定种子、失败序列留档）按 ADR D10 执行。

## 5. 阶段提交边界重申

- S2：客户结构、最小查询/关联命令、证据关系增量（EvidenceArtifact/FactAssertion/supersedes/冲突留痕）、迁移与测试；不夹带额度自动化。
- S3：账本、状态迁移、预占/释放/模拟确认、并发与幂等测试；不改四 Agent 策略。
- S4：正式动作、权限、stale/复核、审计；每项须含负例，不只 happy path。
- 完成定义（E1）：隔离 PG + 真实 HTTP + 两个独立客户端证明归集、并发安全、持久化、正式权限与依据复核成立；v1 关键回归仍通过。真实业务规则、生产身份、资金接口未验收前明确标为不在通过范围；无授权时报告 BLOCKED 门与已完成本地部分。
