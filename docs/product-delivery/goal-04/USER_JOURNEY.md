# 任务四 D1｜冻结用户旅程与失败判据（v1，冻结后改动需记 CHANGELOG 并声明理由）

本轮硬门 = **D27-L-UI：二维页面上，原件到人工决定，全程无开发者**。本文冻结第一条用户路径、九角色会话面、失败判据与反例集。任务01/02/03 就绪前，本文是装配目标；就绪后逐条对页面实测。

## 1｜角色与会话面（≥9 角色；合成身份，来源与管理员初始化记录在案）

| # | 角色 | 会话目标 | 关键权限边界 |
|---|---|---|---|
| 1 | admin（管理员） | 一次性初始化：身份目录、政策种子、必需域政策、规则包版本激活 | 唯一可配运行时；不在案例中途改权限 |
| 2 | business（业务） | 创建客户、发受限邀请、跟进待办、查看结果 | 无批准权；不能把自己提交当已评估 |
| 3 | customer-owner（实控人） | 受邀上传执照/流水/账表/合同/设备照片、答问、补材料 | 只见获准披露；不填内部 ID |
| 4 | customer-finance（客户财务） | 受邀上传账表/流水、答财务问题 | 同上 |
| 5 | customer-plant（客户厂长） | 受邀答设备/现场问题、补设备照片 | 同上 |
| 6 | policy（政策域专员） | 看政策域意见、复核、人工核验材料 | 核验≠批准 |
| 7 | credit（信审专员） | 看信审域意见与证据、提出定向问题 | 无批准权 |
| 8 | approver（厂长侧审批人/有权决定者） | 查看候选+完整当前依据，页面正式批准/拒绝/附条件 | 唯一正式决定人（human，service/模型恒不能） |
| 9 | finance-review（商务/财务复核） | 看商务域意见、成本缺口、复核方案 | 无批准权 |

隔离会话：至少 3 个浏览器会话同时在线（customer 一侧 + 内部两侧），跨客户隔离用第二个合成客户反证。真实物理终端数量如实记录（本机多浏览器 profile 即如实记 1 台机多会话）。

## 2｜冻结第一条用户路径（Happy Path·J1）

前置一次性动作（管理员初始化，步骤写入普通用户说明）：启动栈（安装说明→健康检查全绿）→ admin 登录 → 建身份目录与合成政策种子（显式测试配置，标注 simulation）→ 激活规则包版本 → 配置必需域政策。此后不再需要任何命令行。

- **J1.1** business 登录页面 → 新建客户（只填业务字段，零内部 ID）→ 生成受限邀请（角色×主体×种类），复制邀请链接/码给客户。
- **J1.2** customer-owner 用邀请进入（独立会话）→ 上传：营业执照扫描件（PNG）、银行流水 CSV、账表 XLSX、购机合同 PDF、设备铭牌 PNG、现场照片 PNG → 页面看到逐件上传/解析/预审分段状态；全程等常驻服务推进，不刷新救场。
- **J1.3** 处理产物经桥接进入 A：页面上同一原件可追溯到解析观测、来源定位（行号/页码）、材料版本；business 侧看到当前检查与待办。
- **J1.4** credit/policy 在页面看四域意见与具体证据 → credit 向 customer-finance/厂长发起定向问题（页面内受控渠道）→ 客户在获准线程回答并补材料；policy 对关键项做人工核验（页面勾选+理由，服务端记录核验人与依据版本）。
- **J1.5** 系统形成可复核候选+完整当前依据包（冻结修订）；approver 页面看到候选、依据版本、Gate 结果与提交点阻断情况 → 二次确认后正式批准 → 服务端留真实回执+依据修订号；business/customer 随后能看到决定结果（customer 只见获准摘要）。
- **J1.6** 刷新/退出重进/处理服务重启后记录仍在；追加一份后到不利材料 → 历史决定不改写，但页面当前复核与后续动作按已批准规则受限（新增用信/提额按规则阻断或走复核）。
- **J1.7** 第二合成客户并发存在：两个客户的页面互不可见对方数据（跨客户隔离反证）。

冻结判据：J1.1–J1.7 每步都有页面操作路径、预期页面表现、只读侧断言（DB/回执）。任何一步只能靠终端/SQL/手填 ID/控制台补状态才能继续 = 该步 FAIL。

## 3｜正例变体与反例集（原件包随3节判据冻结）

正例变体（合成原件包内同时提供）：
- **一致组**：执照主体、流水商户、账表期间、合同金额、设备编号全部互洽。
- **冲突组**：同一主体但合同金额与账表合计不一致、设备编号与铭牌不一致 → 预审必须产出可见矛盾/问题，而不是静默通过。
- **人工组**：扫描铭牌无获准识别提供方 → 走页面"原件可见+来源可选+人工录入/复核+标注人工"路线，产品不伪装自动识别。
- **后到组**：决定后再传不利更正材料 → 触发 J1.6 限制语义。

反例集（每项都有页面解释与合法恢复路线，且只读侧断言服务端状态）：
1. 引号金额/千分位/负号 CSV → 正确解析或明确拒绝，不错列后仍成功。
2. 非法日期行/坏行 → 坏行不参与合计，页面可见坏行原因。
3. 重复上传同一文件 → 幂等/去重可见，不产生双份事实。
4. 过期/撤销邀请 → 明确拒绝页面，无数据泄漏。
5. 匿名访问内部读口/跨客户访问 → 统一无存在性泄漏的拒绝。
6. 撤权后重放（回收 business 会话后用旧请求重放）→ 不借缓存回执，拒绝生效。
7. 伪/过期豁免、旧 Gate 版本、晚到分析结果、错设备/错期间证据 → 提交点阻断，页面给具体缺口。
8. 重复批准/重复提交（双击、并发两会话同批）→ 恰一次生效，第二次明确失败或幂等回执。
9. 数据已提交而响应丢失（断网重试）→ requestId 对账，不重复落单。
10. 处理服务被 kill 后重启 → 任务恢复续跑，零盲重发（外部发送计数不增）。
11. 未知外部结果 → 对账路线可见，不换 ID 盲发。
12. 重复文件/同字节不同元数据 → 按规则处理，页面可见判定依据。

## 4｜失败判据与报告语义（全轮统一）

- **PASS**：页面操作实际执行 + 页面表现符合预期 + 只读侧断言成立，三者齐备。
- **FAIL**：页面无法完成应有动作 / 服务端状态与页面不符 / 需要开发者手段续命 / 反例未被拒绝或无解释。
- **BLOCKED**：依赖的前路接口/页面未就绪（注明 owner 与依赖项），留门不改判据。
- **NOT_RUN**：本轮未实际执行（含真人试用未发生），如实保留，不算 PASS。
- 必测集合里任何 FAIL/BLOCKED/NOT_RUN 不得汇总为发布 PASS；浏览器自动化证明"操作可达"，不冒充真人可用性验收（真人试用单列为 D27-L-UI 的人证轮）。
- 解耦反证：移除桥接/提交门（隔离副本变异）→ 相应测试必须失败，否则判据无效。
- 性能：固定同一发布快照，≥3 轮同环境记录首屏/文件处理/预审等待/关键提交/跨角色同步/查询调用数/资源峰值；改善不得来自跳过核验或隐藏异常；旧兼容接口数据不冒充新链数据。

## 5｜禁令（全程有效）

终端/SQL/调试接口/浏览器控制台补业务状态；allow-legacy-basis；隐藏剧情按钮；预填事实/固定 CLEAR 进分析输入；API 脚本登记"运行完成/通过意见"替代真执行器；把分别通过的处理链和审批链拼成全程成功声明；改 A/B/C/Connectors/Edge-src/Front 源码掩盖失败（缺陷退回对应 writer）。
