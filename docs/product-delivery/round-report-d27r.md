## 0. 结论速览

1. **二维硬门 D27-L-UI 不依赖任何真实提供方**，现有链路（扫描件→安全接收+预览+人工录入、模拟规则包分析、页面内消息）已自洽。本报告为只读调研，对硬门验收零影响。
2. 缺口分两类性质不同：**OCR/LLM/外发渠道**是"有产品内替代路线、缺真实提供方"；**ASR/语音、视频、三维多人空间（D27-S）**是"连入口都不存在"。后者接入属新增能力，不属本轮。
3. 若用户未来授权接入，推荐排序（试点→生产）：
   - OCR：本地 PaddleOCR（零外发零费用试点）→ 腾讯云 OCR（生产，免费额度 1,000 次/月/接口、约 0.011 元/次起）
   - ASR：本地 Whisper（试点）→ 腾讯云录音文件识别（生产，约 1 元/小时以内）
   - LLM：智谱 GLM（A 内核已预留 GLM transport 注释，有免费/低价档）→ DeepSeek（境内、价最低档）→ 通义千问；境外模型不推荐（数据出境+可用性）
   - 企微渠道：群机器人 Webhook（免费、单向通知、最小授权面）→ 自建应用（免费、双向、需企业管理员创建）
4. 所有真实接入动作都被 §4 授权门拦住：**未获用户明确授权前，一切维持现状**（人工路线 / 能力位 blocked），这与任务书"未授权/未实现如实保留"一致。

## 2. 任务②｜真实提供方调研（OCR / ASR / LLM / 企业微信渠道）

通用合规前提先列一次，各小节只写差异点：

- **PIPL（个人信息保护法）**：处理个人信息须告知同意、最小必要；身份证件、金融账户等属敏感个人信息，需单独同意；委托第三方处理须有数据处理协议。客户尽调材料属高敏感级（金融行业标准 JR/T 0171《个人金融信息保护技术规范》、JR/T 0197《金融数据安全 数据安全分级指南》口径）。
- **数据出境**：选用**境外**提供方（OpenAI、Anthropic、Google、AWS 等）= 个人信息出境，触发安全评估/标准合同/认证三条通道之一，另有支付与中国区可用性障碍。**境内提供方一般不触发出境**，但仍需协议+脱敏+最小化。
- **生成式 AI 服务管理暂行办法**（网信办等，2023-08 施行）：**面向公众**提供具舆论属性/社会动员能力的生成式服务须大模型备案+算法备案+显著标识；企业**调用第三方已备案模型 API 做内部辅助**通常只需登记层面配合，义务显著减轻。本产品当前形态（模型输出仅为候选意见、authority=none、人保留正式决定权）属低负担的内部辅助形态。
- **密钥纪律**：任何 API Key/Secret 只进本地运行配置（不入 Git、不入日志、不进测试断言），与本仓既有"依赖/凭据/数据库不进 Git"决定一致。

## 3. 任务③｜与二维硬门 D27-L-UI 的边界

1. **硬门不依赖本报告任何建议落地。** 二维旅程"原件→处理→四域意见→人工决定"的每一段都有不依赖外部提供方的既有实现：扫描件走安全接收+预览+人工录入（`adapters.mjs:629,649`）；分析走 simulation_rule_pack/calculation，且 `real_http` 缺 transport 时显式报错而非静默 mock（`kernel.ts:677-678`）；通知走页面内消息+审计（`messages.mjs:1-4`）。
2. **D27-R / D27-S 维持单列**，状态"未授权/未实现，如实保留"（`ACCEPTANCE_MATRIX.md:59-60`），不并入硬门结论，不因本调研写成"进行中/部分解决"。
3. **不顶替**：不用录屏/合成工厂冒充真实媒体能力；接入与否都不改变"未接入能力显式标注"的页面纪律（goal-03 `DESIGN.md:47`、`PAGE_INVENTORY.md:34`）。
4. **三维不阻二维**：D27-S 不建设，未做三维不阻止本轮二维硬门验证（任务书 §6 原文）。
5. **反向纪律**：将来任何提供方接入后，能力位仍须"逐一独立报告，永不汇总为 all_ok"（`server.mjs:552` note），且不能把接入真实提供方后的数据与模拟链路数据混算进同一份性能/验收记录。
6. **本会话行为边界**：只读仓库+公开网页；唯一写入即本文件；未启动任何授权动作，未触碰任何端口/容器/密钥。
