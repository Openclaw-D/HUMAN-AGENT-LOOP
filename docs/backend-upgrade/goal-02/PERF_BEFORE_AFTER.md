# goal-02 · PERF_BEFORE_AFTER（2026-09-17 实测）

## 方法与纪律

- **同输入、同能力、只切策略**：两臂使用同一固定批次、同一确定性四域管线、同一规则包（four-domain-rule-pack-v1）、同一发送通道（FakeWecomTransport），唯一差异是 `processing.strategy`：
  - `naive_full`（before，现状基线形态）：无解析结果复用、每件材料触发四域全量重算、无同键问题幂等（每次新 msgid 重复外发）；
  - `selective`（after，本轮交付）：解析去重缓存 + 域消费面签名选择性重算 + 同键问题幂等外发。
- **提速不得来自跳过必要核验**：两臂核验覆盖等价性由脚本强制断言（不等价即 exit 1）：
  - Gate 语义投影集合一致（result+ruleIds+四域状态+释放条件类型）✅
  - 问题覆盖集合一致（按对象|期间|目的|受众|回答权限去重键）✅
  - 转人工覆盖一致（按去重材料 sha 集合）✅
  - needs_followup 覆盖一致（按去重材料 sha 集合）✅
- 模型调用两臂恒 0（确定性管线，如实）；真实账单未接入=实际费用**未知**，不记 0（台账 `processing_costs.actual.billKnown=false`）。

## 固定批次

8 份银行流水 CSV（其中 4 份为同字节重复上传）+ 4 份声明 txt + 2 个 ZIP（各含 csv/txt/pdf 三 entry）= **18 次上传 → 24 个处理任务**（ZIP 派生 6 个子件任务；其中 6 个任务为重复内容）。

## 实测数字（2026-09-17，Node v22.23.1，本机 PG jw-connectors-pg@15443）

| 指标 | naive_full（before） | selective（after） | 变化 |
|---|---|---|---|
| 上传耗时（18 次 HTTP） | 279 ms | 279 ms | 持平（同入口） |
| 处理总耗时（全部任务到终态） | 2496 ms | **1372 ms** | **1.82× 提速** |
| 真实解析执行次数 | 20 | **15** | 重复件零重复解析（6 次缓存命中） |
| 域计算次数 | 80 | **26**（+复用 34） | **3.08× 降低** |
| 事实候选插入次数 | 48 | **38** | 重复件不重复入账 |
| 客户外发条数（重复提问） | **100** | **5** | **20× 降低**（同键问题幂等） |
| 内存峰值（heapUsed） | 13.8 MB | 14.3 MB | 持平（缓存代价可忽略） |
| 模型调用量 | 0 | 0 | 两臂同为确定性管线 |
| 转人工（unsupported pdf） | 1 份唯一内容 | 1 份唯一内容 | 覆盖一致 |

## 对照实验与消融结论的口径声明（任务书 §六）

- 本对照是**功能消融实验**：naive_full 臂刻意移除解析去重、消费面签名复用与同键幂等三件事。
  它只证明这三件事的必要性（各自贡献的减少量见上表），**不证明任何"多 Agent 协同"的因果优势**。
- 两臂耗时中 PG 写入（阶段留痕、任务状态）占比显著；绝对毫秒数随机器而变，倍率关系是本轮结论。
- 提速来源全部为"不重复做已做过且仍有效的工作"（解析缓存/域复用/同键幂等），核验覆盖集合逐项相等，无任何必要核验被跳过。
- 原始证据：`evidence/perf-goal02-*.json`（最终轮 `perf-goal02-1789664574259.json`；复现命令
  `cd Back/Connectors && node scripts/perf-goal02.mjs`）。

## 基线（改码前）补充说明

改码前的系统在接收入口之后没有任何处理推进（无解析、无四域、无提问——见 DESIGN §0 断链清单），
因此"before"取"现状唯一形态"= 每件全解析+每次事件四域全量重算+无问题幂等（naive_full 臂），
而非虚构一条不存在的旧链路。改码前四域处理的唯一入口是 B worker 对 A goal 的执行路径（保留未动）。
