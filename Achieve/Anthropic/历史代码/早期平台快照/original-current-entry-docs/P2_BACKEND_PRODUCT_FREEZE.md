## B1. 唯一权威业务事项与组织主线

状态：`FROZEN / USER CONFIRMED`

### B1.1 后端唯一一级业务事项

- 见微 V2 后端围绕的唯一一级业务事项是：**融资租赁事项**。
- 决赛不以跨行业、跨金融业态复用的通用“协同事项”作为后端权威根对象。
- `CollaborationCase` 不得作为与融资租赁事项平级或更高层的权威业务根对象。后续即使保留协同辅助对象，也必须从属于融资租赁事项；其具体形态尚未冻结。
- 本条只冻结见微聚合、追踪和接续工作的业务根对象，不表示见微取代既有系统成为全部业务事实的权威来源。原系统继续持有其负责的权威事实，见微只保存后续讨论确认的最小协同状态、事件、责任、证据与回执。

### B1.2 决赛业务边界

- 当前业务范围锁定为**融资租赁**。
- 银行、保险、信托及全牌照叙事不进入当前后端对象、术语、流程、演示或验收。
- 跨业务复用只可作为远期可能性，不得反向改变本期数据语义和验收对象。

### B1.3 组织主线

- 主协同关系锁定为：**业务 ↔ 大风控**。
- “大业务”在本项目中统一简称为“业务”，指触达供应商、发现和推进商机、联系和服务客户的销售及业务人员群体。
- “大风控”固定包含四个板块：**信审、政策、商务、资产**。
- 决赛重点放在**信审**，但信审与政策高度关联，不得将信审描述为脱离政策独立运行的单点 Agent。
- **政策**负责准入、行业、风险政策、标准和规则支持，并与信审判断形成强关联。
- **商务**偏执行和流程，主要涉及合同、物流、资金及业务落地相关事项。
- **资产**负责起租后的租金和还款履约、催收、资产处置以及诉讼资源等存续期管理。
- 风控是显性优势和主要证据，但见微仍是业务与大风控之间的人机协同平台，不得退化为单一信审或风控 Agent。

## B2. 单一总生命周期与高层时序

状态：`PARTIALLY FROZEN / HIGH-LEVEL LOGIC USER CONFIRMED`

### B2.1 已冻结

- 每个融资租赁事项只有**一条总生命周期**。政策、信审、商务、资产不得各自成为与事项平级的独立主生命周期，也不得由四条生命周期事后拼出事项总状态。
- 总生命周期从**商机**开始。商机阶段需要表达商机如何获得、来源是什么，以及相关 Agent 如何参与发现或触发；具体 Agent 和调用语义尚未冻结。
- 商机后进入**尽职调查（尽调）**及后续业务推进。
- 大风控四板块按业务逻辑时序表达为：**政策 → 信审 → 商务 → 资产**。
- 政策先提供规则、引擎能力和必要数据基础；信审据此进行风险把控；商务承接合同、物流、资金等合规与执行流程；资产承接起租后的履约、催收、处置及诉讼资源等存续管理。
- 资产是当前总生命周期的下游和收口阶段，不把起租视为事项结束。

### B2.2 尚未冻结

- 政策究竟是每个融资租赁事项都要人工经过的第一阶段，还是事项发生前长期存在的组织级规则基线，并只在例外或解释时进入个案。
- 总生命周期的精确状态名、进入条件、退出条件、允许回退、循环、暂停、终止和重开语义。
- 尽调与政策判断的精确先后关系，以及哪些板块可以并行参与。
- 商机、客户、供应商、资金需求之间的对象关系。
