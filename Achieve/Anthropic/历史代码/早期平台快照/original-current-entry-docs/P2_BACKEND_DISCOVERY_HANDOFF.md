## 2. 当前唯一业务范围

- 产品名称：**见微-人机协同平台**。
- 决赛范围：**融资租赁**，不混入银行、保险、信托或全牌照叙事。
- 组织主线：大业务团队与“大风控”团队协同。
- 大风控四板块：**信审、商务、资产、政策**。
- 上游可包含：客户商机、资金需求、项目准入/立项。
- 中段可包含：尽职调查、信审、商务条件、政策/规则支持、合同与起租。
- 下游可包含：资产/履约监测、风险预警、续作、退出或再营销。
- 风控场景是显性优势和主要证据，但见微不是单一风控 Agent；各板块可装载自己的 Agent，平台负责组织与接续。

## 3. 产品上下两层

上层愿景是组织智能和组织判断：让多个人使用模型，并把人、Agent、规则与系统联合调度，提升组织产能。

三周可证明的技术形态是部署在现有生态旁边的轻量协同 Harness：不替换现有系统，不统一全部数据，不重建完整 OA/知识图谱/审批平台。

当前跨环节主循环候选：

> 感知变化 → 解释为什么找谁 → AI 推荐若干人/Agent → 有权人员确认 → 受控上下文分发 → 人与 Agent 执行 → 结果、证据与回执返回。

第一体验原则：被邀请者先看懂“为什么找我、我负责什么”，之后才看 Agent 如何辅助。

## 4. 最高优先级 Gate

必须回答集团 AI 领导的问题：如何与现有规则、系统、人员、内网环境和自研 Agent **最小化融入**。

候选原则：

- 复用现有身份、规则、审批和 Agent；
- 原系统继续保存权威业务事实；
- 见微只保存最小协同状态、事件、责任和回执；
- Adapter contract-first，可从 stub/影子/只读开始；
- 高风险动作人工确认，模型无业务权威；
- 失败关闭、可回退；移除见微后原业务仍可运行；
- 短 Time-to-First-Value，但不承诺字面上的即插即用或生产部署。

## 5. 外网与证据边界

- 当前只在外网开发和演示。
- 不获取、复制、导出或推断未授权的集团内网代码、客户数据、制度全文、接口凭据或商业秘密。
- 只使用合成、去标识和公开材料。
- 模拟 Adapter 只能证明接口契约，不得写成已接集团系统。
- 集团有算力和内网 GPU 是未来部署条件，不代表当前已具备模型质量、数据授权、系统接入或生产运维证据。
- 三周目标是最小前后端连调验证原型；真实生产体系可能需要数月到一年以上。

## 6. 模型与 GLM 边界

- 产品 adapter 先用 fake/stub 验证权限、失败、审计、幂等和回执。
- 若需要脱敏 live smoke，使用项目独立产品凭据和人工 Gate。
- GLM coding runner 凭据绝不能复用为产品凭据。
- GLM-5.3 只在后端契约冻结后作为串行、文件边界明确、可独立验收的编码 worker；Codex/GPT 负责产品、架构和最终 Gate。
