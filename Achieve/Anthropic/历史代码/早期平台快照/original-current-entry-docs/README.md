# 见微-人机协同平台

**见微-人机协同平台**是本目录唯一的真实项目，也是唯一的决赛项目名称。

## 最新产品方向入口

截至 2026-08-28，当前最高优先级、最新的产品方向来源是 [P2_PRODUCT_DISCOVERY.md](P2_PRODUCT_DISCOVERY.md)。项目正在重新进行产品发现，尚未冻结实现；`P2_CONTRACT.md` 与 P1 材料只作为历史候选和证据，不能覆盖这次最新讨论，也不能单独授权开发。

产品定位是企业级人机协同 Harness：为企业中的人、Agent、模型、工具、数据源和现有系统提供统一运行环境，用于装载上下文、执行工作、调用能力、经过权限与人工 Gate、生成可核验产物，并记录结果、成本和责任。

可以把它理解成“面向企业业务工作的 Codex 式 Harness”。这里的 `Corporation Harness` 只描述产品类型，不是项目名、品牌或第二套产品。

## 十场景产品原则

- 十个场景都必须从真实中国市场需求、岗位、流程和痛点中做深，不设置“3 个正式场景 + 7 个装饰场景”。
- 首页场景顺序先固定为：`风控业务协同`、`需求开发协同`、`人机交互协同`；其余七个 `XXXX协同` 名称由市场研究后冻结。
- 前三个场景是最先验证内核的锚点，不等于平台最终只服务三个场景。
- 候选能力只有在至少三个语义和责任结构明显不同的场景中都被真实需要，才有资格进入共享内核；否则保留为 ScenarioPack 配置或连接器能力。
- 市场证据、产品判断和工程实现必须分层记录，不能用界面存在或测试通过代替真实需求成立。

## 平台组成

1. **Control Plane**：组织、Workspace、身份、角色、权限、策略、模型与工具注册。
2. **Runtime Plane**：Work、Run、上下文组装、Agent 协作、任务执行、人工 Gate 与责任交接。
3. **Integration Plane**：企业数据源、Evidence Adapter、Tool/Action Connector、Webhook 与 API。
4. **Experience Plane**：统一工作台、任务 Inbox、时间线、协同视图、审批台和管理控制台。
5. **Evaluation Plane**：质量、成本、时延、风险、业务结果、Replay 和审计。

## P1 前端基线

- 首页只展示必须知道、必须看到、必须处理的信息。
- 顶部是标题、场景选择、协同事项选择和紧凑状态；缩放、重置等低频操作不占据主界面。
- 左侧为大面积协同视图，右侧为接近 Codex 信息密度的详情与操作看板。
- 指标压缩为左下方单行；技术细节、可选字段和低频设置折叠收纳。
- 图谱使用拖拽与 `Ctrl + 滚轮` 缩放；桌面端以 `1920×1080` 为响应式基线，同时保证窄屏可读可操作。
- 用户界面使用“协同事项”，后端仍可使用通用对象名 `Work`。
- 前端只显示后端真实 Projection，不以 localStorage 或静态样例伪造成功状态。
