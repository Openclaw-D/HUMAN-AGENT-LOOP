业务 项目主理人
可创建、提交、补充、回应
不能作风险审批决定
从自然需求开始

理解客户需求、交易目标与现实约束，形成业务方案。

材料与语境

上传材料并解释其业务含义；任何时候都能直接提交风控。

确认真实事实

确认系统整理结果，纠正错误理解，补充必要说明。

使用智能

追问建议与理由，补充真实语境，选择下一项材料。

围绕问题协作

解释业务逻辑，回应关键分歧，继续补充有效信息。

继续推进项目

接收决定；通过后推进，沟通时完善，新情况触发再评估。

系统 协作基础设施
可组织、计算、触发、等待
不能作最终决定
建立项目空间

创建唯一项目上下文，让所有角色围绕同一事实中心工作。

汇入同一项目

把材料、消息、任务和说明组织到同一个项目中。

确定性处理

整理结构、计算固定指标、检查完整性并提示明显缺失。

提供可靠输入

向智能提供当前项目事实、基础计算结果和最新状态。

协调协作节奏

路由任务、提醒负责人、等待补充并同步最新进展。

保持历史连续

记录完整过程和决定；新情况开启新一轮，不覆盖原判断。

智能 判断增强层
可理解、比较、解释、建议
不能替代人类决定
理解业务目标

理解业务想完成什么，并协助梳理项目问题。

读取新增变化

阅读材料和业务说明，识别新信息与变化部分。

发现判断难点

结合系统结果，识别冲突、缺口、异常与不确定性。

形成判断建议

输出摘要、风险解释、关键问题、建议、依据与未知项。

持续更新解释

随着补充信息变化，解释判断为何变化或保持不变。

支持而不越权

提供决策支持与结果复盘，永远不替风控确认结果。

风控 协同守护者
可审查、沟通、通过、否决
承担最终判断责任
设定关注原则

明确风险关注方向，但不介入业务每一个准备细节。

接受直接提交

业务可随时提交；系统和智能不得增加新的强制门槛。

减少重复检查

先查看系统整理与初筛结果，把时间留给实质判断。

聚焦关键判断

审阅有实质影响的建议、依据和不确定性。

协同解决分歧

围绕关键问题沟通，帮助项目变得更清楚、更可判断。

承担最终责任

作出通过、沟通或否决，并说明决定理由。

循环 A · 自助完善 业务 ↔ 系统／智能

帮助业务整理和完善项目，但不是门槛；业务始终可以直接提交风控。

循环 B · 协同判断 风控提问 → 业务补充 → 系统更新 → 智能重判 → 风控继续判断

只有关键问题未解决时发生；目标是共同完成项目，而不是简单退回。

循环 C · 持续更新 关键新情况 → 保留原判断 → 开启新一轮判断

项目历史连续存在，旧结论不被修改，新信息形成新的判断依据。
