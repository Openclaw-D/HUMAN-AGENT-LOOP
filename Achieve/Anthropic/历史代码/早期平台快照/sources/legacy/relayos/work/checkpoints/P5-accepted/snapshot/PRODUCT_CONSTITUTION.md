## 1. 一句话产品

**RelayOS 是人与可路由 Agent 共同处理企业关键事项时的连续性与权威控制层：它让目标、证据、决策权、责任交接、Human Gate、外部动作回执和业务结果跨人员、Agent、会话与系统持续存在、可恢复、可审计。**

RelayOS 不替代模型、Agent runtime、workflow engine、CRM、ERP、工单或设备控制系统。它对“工作连续性与权威关系”负责，现有系统仍对各自业务事实和实际执行负责。

## 2. 目标用户与买方

### 2.1 日常用户

- 跨部门关键事项的当前 owner、接收者和具名审批人；
- 业务运营、客服、风控、供应链、研发效能、内容治理等流程 Owner；
- 负责企业 Agent 落地的 AI Product、AI Transformation、Automation 与 IT 团队；
- 需要复盘目标、证据、权限、交接、例外和外部动作结果的风险、质量与审计人员。

### 2.2 经济买方

- 首要买方：COO、CIO/CTO、AI Transformation Office 负责人、业务单元运营负责人；
- 高异常成本场景的共同买方：风控/合规、客户成功、供应链、内容安全或研发平台主管；
- 内部 champion：Head of AI/Automation、Enterprise Architecture、Service Operations、RevOps、流程治理负责人。

早期采用对象应具备：事项持续数小时至数周、跨至少三个角色或两个系统、有可量化异常成本、已有 Agent/assistant 试点，但责任和证据主要散落在聊天、邮件、表格或单次 workflow run 中。

## 3. 核心价值

| 价值 | RelayOS 必须交付的可见结果 | 首要验收指标 |
| --- | --- | --- |
| 连续性 | 工作不属于某个会话或单个 Agent；重启、换人、换 Agent 后仍能恢复当前目标、owner、证据和下一步 | 恢复完整率、重复调查率、事项重开率 |
| 权威性 | 能说明谁在什么范围和时间内有权改变目标、批准动作或处理例外 | 越权写入数必须为 0；权威链完整率 |
| 可验收交接 | 发出交接不等于转移责任；接收者检查并接受后 owner 才改变 | 交接接受时延、澄清/拒绝率、owner 歧义数 |
| 可控模型能力 | 模型负责提取、总结、识别冲突和给建议；确定性后端负责权限、状态与持久化 | 模型失败/歧义/越权时权威写入数必须为 0 |
| 可审计执行 | 外部动作先成为 `ActionIntent`，通过权限/Gate 后执行，并保留 `ExecutionReceipt` | 无回执动作数、重复执行数、回执可关联率 |
| 可比较业务结果 | 十场景共享同一指标对象，并分别保留业务、风险、效率指标 | 每场景三类指标数据源、Owner、阈值与失败处理齐全 |

## 4. 六条不可违反的产品哲学

### 4.1 工作属于业务使命，不属于聊天或一次运行

`WorkCase` 是唯一的长期业务事项聚合根。聊天、模型调用、Agent session、workflow run 和 UI tab 都只能引用它，不能成为权威状态来源。`WorkItem` 仅可作为外部执行系统中的叶子任务引用，不另建第二套 RelayOS 状态机。

### 4.2 模型可建议，不能取得权威

运行时模型只允许做材料抽取、上下文总结、冲突识别、配置建议和行动建议。模型输出、provider 成功响应或 tool call 均不是权威业务事件。目标改变、权限授予、owner 转移、Human Gate 决策、外部写入授权和权威持久化必须经过确定性后端校验。模型超时、失败、结构无效、歧义或越权时，对权威数据必须零写入。

### 4.3 责任只有在被接受后才转移

`HandoffOffer` 只表达原 owner 的提议；`HandoffAcceptance` 只能由指定接收者针对仍有效的目标与上下文版本作出。接受前、拒绝后、请求澄清后、过期后或目标版本变化后，`WorkCase.owner` 均不改变。

### 4.4 事实有来源、上下文有版本、系统各守边界

RelayOS 保存证据引用、来源、观测时间、版本、用途和新鲜度，不把模型摘要冒充事实，也不复制外部系统成为第二真相。CRM、ERP、代码库、审核系统、设备平台等继续拥有自己的 domain facts；RelayOS 只拥有跨系统的目标、责任、权威、Gate、动作意图、回执关系和业务事件。

### 4.5 一套内核，差异来自配置和适配器

十个场景共用同一组对象、状态机、API、事件语义、前端信息架构和运维边界。场景差异只能主要来自词汇、角色、Agent 责任、系统 adapter、触发规则、Gate policy、指标定义、模拟数据和受命名空间约束的扩展字段。禁止复制十套状态机、十套 API 或十套 UI。

### 4.6 可重放、可测量、可运维是产品本体

每次权威变化都必须产生足以重建状态的 `BusinessEvent`；事件、命令回执和投影更新在同一事务边界内成功或全部失败。业务、风险、效率指标与日志、trace、健康检查、重启恢复、Origin 边界和优雅关闭不是发布后补丁，而是同一产品哲学的运行证据。

## 5. 市场证据、推断与产品假设

### 5.1 已确认事实

- P0 市场漏斗为 100 个候选、99 个去重候选、91 条有效证据；其中 84 条 `job`、7 条 `strategy_topic`。来源和等级边界见质量摘要。
- 91 条有效证据按报告口径分为 39 条业务应用、30 条 Agent 平台/Runtime/治理、22 条基础模型/算力。
- 报告给出十个工作流反推线索卡：电商、金融、视频生成、本地生活、企业自动化、供应链、客服、AI Coding、内容治理、终端 OS/IoT。
- 公开招聘材料频繁出现模型、Agent、Infra、业务落地、性能、稳定性、成本和风险；较少显式描述跨部门共享工作项、Accepted Handoff、具名 Gate、跨系统证据链与统一业务事件回放。
- 招聘数量和薪资只是投入方向的代理信号，不是企业预算、采购意愿、内部流程或 RelayOS 收入预测。

### 5.2 有证据支持的产品推断

- 当事项跨多角色、多系统、持续多轮且异常成本较高时，单轮 Copilot 或一次 workflow run 难以独立保持目标、责任和证据连续性。
- 中国企业本地化的关键不是复制某个国外模型产品界面，而是把模型能力翻译为可审计的企业对象：长上下文变成 `ContextVersion`，tool use 变成 `ActionIntent/ExecutionReceipt`，multi-agent 协作变成具名 `RoutableAgent` 与 Accepted Handoff，human-in-the-loop 变成有权限边界的 `HumanGate`。
- 共享内核若成立，其业务价值应表现为更少 owner 歧义、重复调查、越权动作和缺证据关闭，以及更短交接/例外处置周期。

### 5.3 尚未被市场材料证明的假设

- 企业愿意为独立的连续性与权威控制层付费；
- RelayOS 相比现有 workflow/CRM/ITSM/Agent 平台能显著改善目标指标；
- 十场景的共同状态与权限语义足够稳定，不会被场景扩展吞没；
- 显式 Human Gate 在关键场景中的风险收益高于新增时延；
- 无认证的演示可以证明产品逻辑，但不能证明生产安全或真实身份治理。

## 6. 反证条件与停止条件

任一条件成立时，不得用新增行业模板掩盖问题，必须停止通用化扩张并回到产品 Gate：

1. 十场景契约测试中，有任一场景必须修改共同状态机或复制专用 API/UI 才能通过；应收缩场景或重新定义内核。
2. 新场景所需场景专用字段超过该场景配置字段的 20%，或场景分支超过共同 domain command 的 20%；应拒绝“万能 schema”，拆回外部系统 adapter 或放弃该场景。
3. 从空投影按 `BusinessEvent` 重建出的 canonical state 与事务后投影不一致；立即停止后续 Gate，禁止用快照掩盖事件缺失。
4. 模型失败、歧义、结构无效或越权时出现任何权威状态写入；立即停止 P3/P5，回滚到 `MockProvider`。
5. Accepted Handoff 试验未降低 owner 歧义/重复解释，或引入的中位交接时延增加超过 20% 且风险指标无改善；收缩交接强制范围。
6. Human Gate 未降低误操作、损失、申诉改判或审计缺口，却让相应流程周期增加超过 20%；改为分级 Gate 或停止该 Gate policy。
7. 三个展示场景的首次使用测试中，至少 80% 的目标用户不能在 5 分钟内准确回答“当前目标、当前 owner、待接受交接、开放 Gate、下一步”五问；停止视觉扩展并重做信息架构。
8. 现有企业平台已提供等价的 mission-owned state、Accepted Handoff、可重建事件和跨系统回执，且接入 RelayOS 不改善任一业务/风险/效率指标；停止独立产品主张，评估嵌入式能力或终止。

## 7. 明确非目标

- 不做聊天产品、通用 Agent Builder、拖拽 DAG、模型训练平台或另一个 Agent runtime；
- 不替代 CRM、ERP、SRM、WMS、TMS、工单、代码托管、审核、发布、设备控制、支付或量产系统；
- 不为十个行业复制十套内核、状态机、API 或 UI；
- 不让模型决定目标、权限、owner、Human Gate 结果或持久化写入；
- P1 不安装依赖、不调用真实模型 API、不实现 UI、不声称 Z.AI General API 已联通；
- 本阶段不做账号登录、SSO、OAuth、真实身份认证、生产多租户安全、合规认证或高可用；
- “演示角色选择”不是登录、认证、授权凭证或安全边界；
- 不把招聘数量、薪资、岗位目标或 strategy topic 冒充预算、已实现效果或客户购买证据；
- 不重建企业私有流程；十场景数据均为可追溯公开线索驱动的合成模拟。
