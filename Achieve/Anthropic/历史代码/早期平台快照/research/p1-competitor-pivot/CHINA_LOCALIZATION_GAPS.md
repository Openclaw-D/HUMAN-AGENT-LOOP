# 中国企业本地化缺口：事实、推断与假设分栏

研究截止：2026-08-27。这里不把“在中国销售”或“有中文界面”误写成已满足企业本地化。

## 缺口总表

| 维度 | 可核验事实 | 现有产品覆盖 | 见微应做 | 见微不应做 | 判断性质 |
| --- | --- | --- | --- | --- | --- |
| 组织目录与应用身份 | 飞书把应用可用范围、通讯录范围、字段权限分开，部分字段需管理员审批；CLI API 调用可按应用 scope、用户/应用身份并行治理并进入审计日志。[E36][E37] | 飞书/钉钉/企微是身份和操作入口；扣子/CodeArts也有 workspace/企业角色 | 用 adapter 映射员工、部门、外部协作者、服务主体；把外部身份快照写成事件证据 | 不复制 IM 的通讯录、审批或 IAM；不把“机器人可调用”视为业务授权 | 事实 + 工程推断 |
| 审批与人工 Gate | 飞书应用权限/发布可以按管理员审批生效，且可配置审核人；它证明“企业已有审批能力”，不证明业务 Gate 已被见微替代。[E36][E38] | 飞书/钉钉/CodeArts 具有各自审批/权限机制 | 用 Gate adapter 发起审批、回收具名决定；Gate 决定必须绑定 Work/对象版本/证据/权限/时点 | 不把聊天确认或模型文本当批准；不在见微内重新实现完整审批 OA | 事实 + 工程推断 |
| 审计与留痕 | 飞书官方说明 API 调用可按时间、用户、应用、操作类型查询审计；扣子说明访问行为记录审计、消息日志有保留期。[E37][E06][E07] | 平台日志能作为外部证据，但粒度/保留/导出各异 | 自建 append-only 业务事件、投影版本、外部 receipt/unknown；外部日志只作关联证据 | 不以供应商 UI 日志取代核心事件账本 | 事实 + 工程推断 |
| 数据境内/出境 | 《个人信息保护法》第40条对 CII 运营者及达到规定数量的处理者设境内存储要求；第38条规定出境条件。2024 规定也列出豁免情形，不能笼统说“所有数据一律不可出境”。[E39][E40] | 国内云、私有化和模型路由可能是采购选项，但每家适用性不同 | 数据分类、最小化、区域/模型路由、可配置保留与删除、证据脱敏；将法务选择显式化 | 不自行宣称“等保合规/完全数据不出境/天然满足所有行业监管” | 法律事实 + 合规工程推断 |
| 私有化/信创 | Dify/FastGPT/MaxKB/RAGFlow 等公开自托管路径；这只是部署可能性，不是等保/信创认证。[E15-E18] | 开源平台/国内云各有部署选择 | 把 adapter、模型供应商、存储与密钥管理做可替换；从单企业单租户开始 | 不在 P1 宣称已完成信创适配、测评或行业认证 | 事实 + 假设 |
| 中文知识库和国产模型路由 | 国内 RAG/Agent 平台普遍把知识库、工作流、多个模型作为产品能力；例如 MaxKB 和 FastGPT 明示 RAG/workflow，扣子资源中包含知识库。[E16][E17][E06] | 可作为 RAG/模型适配层候选 | 统一 `Evidence` 引用/版本/适用范围，模型只给 proposal；按数据等级/成本/时延选择 provider | 不把“接了模型”当作“知识正确”或让模型写权威状态 | 事实 + 工程推断 |
| 长任务与断线恢复 | CodeArts 公开称 Agent Team 成员有持续化上下文和故障成员恢复；Qoder 使用 Session Thread；这些都属研发平台语境。[E10][E08] | 运行时局部可借鉴 | 自研 event cursor、idempotency key、Run 状态、取消/超时、unknown receipt、replay | 不依赖 UI 聊天历史作为业务恢复唯一来源 | 事实 + 工程推断 |
| 外部动作成本与责任 | 飞书 API 权限上限由获批 scope 决定，且用户身份与应用身份独立。[E37] | IM/业务系统能限制技术调用权限 | 统一“谁请求、谁批准、以哪个身份执行、对哪个版本、得到何 receipt”的业务证据 | 不把 connector token 赋给模型，不让模型自行通过 Gate 或执行高风险动作 | 事实 + 工程推断 |

## 现有产品的覆盖边界

| 产品层 | 已可利用的能力 | 不能替代的见微核心 |
| --- | --- | --- |
| 飞书/钉钉/企业微信 | 组织身份、消息、审批、文档/知识、应用 scope、平台审计 | 跨系统 Work 事实、版本化责任、跨 Agent handoff、三视图、unknown/receipt 处置 |
| 扣子/百炼/Dify/FastGPT/MaxKB/RAGFlow | Agent、流程、RAG、模型和工具连接 | 人工 Gate、可重放业务事件、对象级责任/权限、跨场景 Projection |
| CodeArts/Qoder/Comate/Codex/Claude Code | session、subagent、拆解、并行、权限/沙箱局部 | 非研发业务流程的责任、证据、回执与审计内核 |

## P1 本地化最小要求（建议，不是已实现承诺）

1. 首个纵向闭环只接一个企业身份/审批入口和一个模型 provider；所有 connector 允许禁用。
2. `Actor` 显式区分人、组织角色、服务主体、Agent；不能从聊天昵称推断身份。
3. `Authority` 与 `GateDecision` 绑定目标/版本/时效/依据；外部 action 必须有幂等身份和 receipt，缺回执即 `unknown`。
4. 中文可见文本与审计理由完整；知识引用保留来源、版本、适用范围、脱敏状态。
5. 投影可以被删除重建；恢复后先显示最后已知事实与核验责任人，而非伪造成功。

## 假设待客户验证

- 哪个入口优先：飞书、钉钉还是企业微信；不能由技术团队替客户决定。
- 是否属于第40条等特定数据处理情形、需要何种私有化/区域部署与保留期；由法务、安全与采购确认。
- P1 首场景是否确实需要外部动作；若不需要，先用模拟 connector 验证 Gate 与 evidence 语义。
- 十场景中哪些必须使用国产模型、哪些可用多模型路由；以客户数据分级、成本、质量与可用性证据决定。
