# 直接竞品判定：没有已证实的中国本土同类成品

研究截止：2026-08-27；范围：公开、可访问的一手资料。这里的“没有”是“在本次核验的公开一手证据中没有发现”，不是对未公开企业采购、内测或定制项目的绝对否定。

## 一页结论

**结论（高置信度）：中国本土公开产品中，未发现同时满足七项门槛的“直接同类”成品。** 即：共享且可恢复的工作状态、多角色/多智能体、显式 handoff/continuation、责任或权限边界、人工 Gate、审计/事件证据、可在真实企业流程运行，七项必须同时有一手证据。矩阵中的所有中国候选均至少缺少一项公开证据，或产品范围仅限软件研发/智能体搭建。

**最接近的运行时邻近物是华为云码道（CodeArts）Agent Team、Qoder Agent Teams/Quest 和扣子企业版的组合，但三者不是同一个产品。**

- CodeArts 的公开资料确证了持续化独立上下文、共享任务池、成员通信、故障恢复、企业角色和 CLI 审批；但其公开定位是代码开发 Agent Team，且“全程可视、无需人工干预”不能等价为按业务对象/版本运行的人工 Gate 与可重放审计内核。[E10][E11][E12]
- Qoder 已公开多 Agent、Session Thread、协调者/子 Agent、任务与会话流；资料范围仍是编程任务，未证实跨业务系统的责任转移、人工 Gate、不可变业务事件或企业审计。[E08][E09]
- 扣子有企业工作空间、RBAC、动态校验、消息/Trace 日志和发布权限控制，但公开资料把协作对象放在“智能体/工作流/应用资源”，没有证明以一个业务 Work 为中心、可恢复交接并用 Gate 管控外部动作。[E05][E06][E07]

## 对 Codex 的明确结论

### 可以直接复用到什么层

`openai/codex` 的**公开仓库仅是 Codex CLI/SDK 开源实现**，仓库明示为本地运行的 coding agent，并以 Apache-2.0 授权。[E01][E02] 公开文档可证实：

- 按 session ID 或最近会话恢复，且可以跨目录查找；
- 从已有 session fork 新 chat；
- 子代理线程的检查/继续入口；
- sandbox、写目录、人工 approval policy；
- `--json` 的逐状态 JSON 事件输出。[E02][E03][E04]

因此可在许可复核后借鉴或选择性复用：CLI session 标识/恢复交互、受限执行配置、approval/sandbox 的**开发者工具抽象**、JSONL/状态流协议、AGENTS.md 指令分层。它们不是企业业务状态机、组织权限系统或三视图工作台。

### 不能直接照搬的部分

1. CLI 的 `resume` 是保存的编码会话恢复，而非多人围绕一个可版本化 Work 的责任交接；官方 CLI 命令参考中未找到 `handoff` 命令。[E03]
2. `fork` 是复制 conversation 到新 chat，不是把责任、权限、未决 Gate、外部回执转移给另一位责任主体。[E03]
3. sandbox/approval 约束本机命令权限；它不替代按企业角色、业务对象版本、双签/复核规则的授权策略。[E04]
4. 官方仓库 README 明确区分开源 CLI、desktop app 和 Codex Web。桌面/云服务里可见的 task/thread/fork/handoff 编排体验不得反推为 `openai/codex` 已公开的 Corporation Harness 源码；本研究未发现官方公开仓库授予其 UI、服务端或内部调度实现的复用许可。[E01]

| 中国公开产品没有七项齐备的直接同类 | 高 | CodeArts、Qoder 的多智能体和持续上下文已非常接近；若其私有版另有业务 Gate/事件审计，公开资料不足以排除 |

## 分层判定

| 维度 | 判定 | 理由 |
| --- | --- | --- |
| 产品定位同类 | 否 | 候选多为 coding agent、Agent builder、RAG 或项目/协作 SaaS；见微是跨十场景的受控 Work Harness |
| 运行时同构 | 部分 | CodeArts/Qoder/Claude Code/Codex 有 session、队列、subagent、并行等局部相似性；都未以公开证据覆盖七项业务内核 |
| 前端交互同构 | 否 | 未发现“关系—进度—矩阵同源投影 + 接续台”的公开产品证据 |
| 可直接复用代码 | 局部 | 仅开放授权项目的非业务局部；详见 `CODE_REUSE_AND_LICENSE_MAP.md` |
| 可直接购买/集成 | 局部 | 可购买/集成 Agent builder、研发协作、IM/审批连接器；不能替代核心状态、Gate、审计与三视图 |

## 对当前 P1 的止损建议

建议选择三选一中的：**保留自研内核，但复用局部**（证据推断，主控与用户仍保留产品决定权）。

- 不是“复用现成核心并本地化”：没有一个候选被一手证据证明覆盖七项，直接替换会把核心差异（版本、责任、Gate、回执 unknown、event replay）降级成 UI 拼装。
- 不是“组合多个开源底座”：Dify/FastGPT/MaxKB/RAGFlow 等可提供 Agent/RAG/工作流能力，却无法自动形成同一权威投影；许可也分别包含专有附加条件或 GPL，组合成本与边界风险高。[E15][E16][E17][E18]
- 保留的最小自研内核应只包括 `Work/Version/Participant/Authority/Handoff/Gate/Action/Receipt/Event/Projection` 及失败关闭；模型、RAG、IM、审批、国产模型路由均做可替换 adapter。

## 事实、推断、假设

- **事实：**本文件中带 `[E##]` 的产品能力、许可证与资料边界均链接到 `EVIDENCE_REGISTRY.md` 的一手来源。
- **证据推断：**“不是直接同类”“应保留自研内核”由七项门槛与已公开证据的缺项得出。
- **假设：**目标企业需要与飞书/钉钉/企业微信、组织目录、审批和国产模型相连；需在真实客户 discovery 中验证其优先级。
