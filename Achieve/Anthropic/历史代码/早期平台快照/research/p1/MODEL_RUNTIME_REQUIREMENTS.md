# 项目内模型运行产品要求

日期：2026-08-27  
状态：R1 产品契约；描述产品能力和后端义务，不指定实现 Schema、供应商 SDK 或部署方式。

## 1. 边界结论

模型是受人类显式委托的无权工作者：可以产生产物、提案、质疑和证据请求，不能拥有目标、通过人工关口、扩大权限、接受责任交接或制造外部动作已经成功的事实。所有十场景共用同一运行控制语法，但输入完整性、允许任务、关口与指标留在场景包/策略包。

普通聊天消息只追加非权威对话，不触发模型。仅下列显式行为可以请求运行：用户点击“运行智能体/继续此任务/生成候选/复核证据”等场景动作；在输入中明确选择某个智能体并确认任务；从失败/未知运行点击“重试”且再次确认输入版本和预算。

## 2. 可见角色与中文映射

界面只显示简体中文：

| 内部含义 | 用户可见名称 | 权力 |
| --- | --- | --- |
| human principal | 人类负责人 / 专业负责人 | 拥有目标；在资格与策略允许时决定关口和外部动作 |
| model worker | 智能体 / 分析助手 / 内容助手等场景角色 | 无权或仅建议；只能在明确任务和上下文内运行 |
| connector executor | 外部系统执行器 | 只执行已批准意图；其返回仍须按可信回执标准核验 |
| policy control | 策略控制 | 验证身份、权限、资格、对象版本、证据和动作条件 |
| runtime control | 运行控制 | 记录请求、状态、成本、取消/重试/恢复，不作业务决定 |

具体供应商和内部模型标识默认不作为主要角色名；若为审计/成本需要展示，应放在“运行详情”并映射成中文可读名称。

## 3. 显式请求前的输入合同

运行请求必须由后端验证并冻结以下产品含义：

- 请求人、所属组织与当前身份/权限；
- 场景、工作身份、目标版本、投影版本和选择上下文；
- 明确任务、期望输出类型及其不可做事项；
- 允许读取的证据/产物引用、各自版本、适用范围和敏感级别；
- 场景策略版本、工具允许范围、是否完全禁止工具；
- 最大成本/用量、期望时限、重试上限和取消规则；
- 幂等身份及“相同请求”的判定范围；
- 输出接收人、需要的人工审阅/关口，以及断连后的恢复位置。

若目标版本已改变、选择对象已过期、必要证据缺失、权限不足或预算不可用，请求在开始前失败，并以中文说明原因和可执行下一步；不得偷偷换用全局上下文或旧版本。

## 4. 运行生命周期与审计事实

产品至少需要还原以下顺序，名称为内部事件语义，界面使用右栏中文：

| 事件语义 | 界面状态 | 必须记录/显示的事实 |
| --- | --- | --- |
| requested | 已请求 | 请求人、任务、工作/目标版本、输入摘要、权限、预算、幂等身份 |
| started | 运行中 | 实际开始时间、模型/配置版本、接续位置、已用成本/时延 |
| artifact produced | 已产生候选产物 | 产物身份/版本、引用证据、生成者、待审状态 |
| proposal produced | 已提出建议 | 建议对象/版本、依据、限制；不得改变业务状态 |
| challenge raised | 已提出质疑 | 质疑对象/版本、理由、证据缺口、需谁回应 |
| evidence requested | 等待证据 | 缺什么、向谁请求、截止、恢复条件 |
| completed | 运行已完成 | 运行终止，不代表产物通过、动作执行或业务成功 |
| failed | 运行失败 | 失败阶段、可否重试、输入是否可能有副作用、下一步 |
| unknown | 状态待核验 | 最后已知事实、未知原因、核验责任人；不能转成功 |
| cancel requested / cancelled | 正在取消 / 已取消 | 谁取消、取消边界、是否仍有在途工具动作、最终状态 |

`运行已完成`、`产物已通过`、`外部动作已生效`是三个不同事实。右侧接续台不得把它们合并成一个绿色/成功状态。

## 5. 输出合同

允许的正式输出只有：

1. **候选产物：**绑定目标和输入证据版本，状态为待审；
2. **提案：**明确建议、依据、限制、替代项及不确定性；
3. **质疑：**针对具名对象版本，给出理由、风险和需补证项；
4. **证据请求：**说明缺失事实、请求对象、恢复条件；
5. **运行说明：**成本、时延、用量、截断/降级、失败或未知。

任何自然语言“我已发布、已退款、已放款、已部署、已开方”等都不能成为事实。只有外部系统的可信回执、专业签名或策略规定的核验事件可以改变动作状态。

## 6. 运行控制与故障语义

### 6.1 幂等与重试

- 幂等范围绑定请求人、工作/目标版本、任务、输入引用集和允许工具范围；输入或目标变化必须创建新请求。
- 纯生成失败可在上限内重试，但每次尝试属于同一运行族并记录原因、次数和成本。
- 可能触发外部副作用的工具步骤先查回执再重试；未知时不自动重复。新的补偿/撤销是新的动作意图。
- 模型产生了候选产物但终止状态未知时，产物可保留为“来源运行待核验”，不能自动提交人工关口。

### 6.2 取消、超时与预算

- 请求人或具备权限的工作 owner 可取消；界面先显示“正在取消”，直到运行和在途工具均有终态。
- 达到成本、时延或重试上限时默认停止并要求人工决定，不自动换模型/扩大预算。
- 右侧常显本次已用/上限、已运行时间/目标时限、重试次数；成本单位和估算误差在详情说明。

### 6.3 断连和重启恢复

- 前端断连不取消后端运行；重连后按运行身份和事件游标恢复，而非重新提交。
- 服务重启后必须重建到最后已确认事件；有外部工具在途但无可信回执时进入 unknown。
- 客户端重复点击由幂等身份折叠；若任务/输入已变更，界面明确询问创建新运行。
- 无法确认是否仍在运行时显示“状态待核验”，提供核验/取消请求，不伪造“已失败”或“已完成”。

## 7. 右侧接续台的模型区域

无模型运行时只显示“尚未运行”和显式主动作，不主动弹出。运行后按层级显示：

1. 状态、任务、请求人、目标版本；
2. 当前阶段、开始/更新时间、时延、成本/用量、取消；
3. 新产物/提案/质疑/证据请求，均标记“待人审”或“等待证据”；
4. 失败/未知原因和可执行的重试、核验或返回；
5. 折叠的模型/配置、输入引用、策略版本、尝试历史。

普通输入框旁不得放一个含义模糊的“发送即运行”行为。发送消息与请求模型是两个清晰动作；外部动作和人工关口又是另外两个清晰动作。

## 8. 十场景允许作用与明确禁权

| 场景 | 允许的真实作用 | 明确禁权 | 关键质量/负向关注 |
| --- | --- | --- | --- |
| S01 风控 | 汇总证据、风险建议、异常/补证质疑 | 放款、拒绝、冻结、解除、关闭申诉 | 校准/人工推翻；证据过期、重复资金动作、unknown |
| S02 研发 | 实现/测试候选、评审建议、缺陷定位 | 改目标、批准自身产物、合并、发布 | 需求覆盖/缺陷；目标漂移、重复部署、回滚 unknown |
| S03 人机 | 分解、产物、相互审查、交接建议 | 扩权、代替人裁决、接受责任、未批工具调用 | 冲突/交接；循环、预算耗尽、取消竞态 |
| S04 内容 | 候选内容、事实/品牌/IP风险提示 | 声明权利、批准、发布、撤回 | 一致性/IP；来源缺失、标识丢失、重复发布 |
| S05 增长 | 策略/实验候选、归因与异常质疑 | 启用客群、改预算/价格、扩量、宣称因果 | 增量/归因；样本偏差、数据越权、预算超限 |
| S06 物理 | 场景/测试建议、异常检测、修复候选 | 测试准入、升级、设备控制、关闭事件 | 覆盖/安全；版本错绑、失联、接管失败、假回执 |
| S07 知识 | 带引用答案/草稿、冲突与缺口 | 扩大权限、外发、正式写入、高风险业务决定 | 引用/权限；来源注入、过期、敏感泄漏 |
| S08 客服 | 意图/摘要、建议答复、转接/质检质疑 | 确认身份、越权承诺、退款/补偿、关闭投诉 | 首解/上下文；机器人循环、重复赔付、转接 unknown |
| S09 履约 | 影响分析、方案/权衡、数据异常质疑 | 供应商选择、合同/采购/付款、客户承诺 | 承诺一致；约束遗漏、重复采购、多系统分裂 |
| S10 医疗 | 带证据辅助建议、病历/随访草稿、禁忌质疑 | 诊断/治疗终局、处方/签名、关闭危急事件 | 临床安全/修改；身份错配、禁忌、写入 unknown |

## 9. 策略与安全要求

- 模型读取证据遵循最小必要、身份权限与目的限制；不得默认跨场景共享上下文。
- 提示、模型输出、工具返回都按不可信输入处理；关键字段由结构化事实系统/策略验证。
- 运行记录不得泄露秘密、凭据或完整敏感正文；审计保存引用、版本、访问理由和去标识摘要。
- 场景策略决定哪些输出必须双人/专业资格审核、哪些工具完全禁止、数据和日志保留多久。
- 模型/配置或策略版本变化不追溯改变历史运行；重放只重建投影，不重新调用模型或工具。

## 10. 后端产品义务（非实现 Schema）

后端必须支持：创建/校验运行请求；以幂等身份开始或返回既有运行；追加不可变运行事件；流式或轮询恢复；取消；在策略允许时重试；查询成本/时延/尝试；将候选产物/提案/质疑绑定工作和目标版本；把外部工具动作分离为需审批的动作意图；把无回执状态保持 unknown；服务重启后恢复运行与投影。所有业务状态变化必须来自对应命令/事件，而非解析模型自然语言。

## 11. 验收测试清单

1. 发送普通消息，断言无运行请求/开始事件。
2. 显式请求缺目标版本、权限或证据时，断言运行未开始且有中文可执行错误。
3. 同一幂等请求双击，断言只产生一个运行；输入改变则创建新运行。
4. 模型生成“批准/已执行”文本，断言关口、动作和回执状态均不变。
5. 完成运行但候选未人审，界面同时显示“运行已完成、产物待审”。
6. 在外部工具无回执时重试，断言进入核验而不产生重复副作用。
7. 运行中断开前端并重连，断言按事件游标恢复，不重复请求。
8. 后端重启且在途动作不明，断言状态为未知、显示最后事实与核验责任人。
9. 取消与完成竞态时，断言唯一可解释终态和完整事件序列。
10. 达到成本/时延/重试上限，断言停止并等待人工选择。
11. 十场景逐一注入禁权动作，断言策略拒绝且审计请求人、对象版本与理由。
12. 所有模型状态、错误、无障碍名称和成本说明均为简体中文且不含英文字母。
