## S01 风控业务协同

### 入选、对象与边界

F：监管材料明确董事会最终责任、总行主责部门、模型人工复核验证和反欺诈监测；企业流程包含申请、征信/三方数据、人工复核、控制与解除。（RC-001～RC-004）目标为银行、消费金融及平台风控部门；触发为贷款申请、交易异常、风险预警、申诉或解除请求。核心痛点是证据跨系统、模型与人分歧、控制后无人持续负责以及外部动作 unknown。与 S08 的边界是：这里决定风险是否可接受以及是否实施资金/账户控制，不以客服满意或会话解决为主。

**协同对象与判断。** 风险案件/申请、证据快照、模型建议、审核意见、控制决定、申诉和回执。角色为业务申请人/客户、风险审核员、模型/规则 owner、总行主责部门、合规/法务、运营执行、申诉复核人。模型只能提出风险建议和质疑；审核员对个案判断负责，主责部门/董事会承担制度责任。事实系统包括信贷/交易、征信、反欺诈、合同、预警和申诉。失败路径包括材料不足、规则冲突、审核拒绝、重复放款/冻结、解除未生效；unknown 时禁止重复资金动作。（RC-001～RC-004）

**成功/失败/未知。** 成功要求决定所依据的证据与对象版本一致，具名审核完成且外部审批/控制回执可信；失败保留拒绝/退回理由与责任人；回执或系统状态无法证实时保持未知并由运营核验。

### 三视图

**关系视图。** 默认中心为“当前风险案件”。一侧放客户/申请人与申请、征信、交易、三方证据，另一侧放模型/规则、审核员、主责部门和执行系统；控制决定、人工关口、申诉与回执位于主路径。边必须区分“提供证据、产生建议、人工复核、批准控制、执行、回执、申诉挑战”。典型交互是拖动证据簇检查缺口、聚焦模型—审核员分歧、点选“解除回执未知”进入右侧核验。缩小时仍保留当前责任人、未决关口和资金动作。

**进度视图。** 阶段为：`受理 → 身份/材料核验 → 征信与三方取证 → 风险建议 → 人工复核 → 决定 → 外部执行 → 回执核验 → 申诉/解除`。每步显示案件版本、负责人、输入/输出、时限和下一步。独有循环：材料不足回到补证；模型与人工分歧进入二次复核；预警形成“筛查—控制—复查—解除”循环；申诉可创建新证据版本；放款/冻结/解除超时进入 unknown 核验，不得自动重试。

**矩阵视图。** 行为审核员、模型/规则 owner、业务 owner、合规、执行运营、申诉复核；列为材料、风险建议、复核、决定、执行、申诉。单元格强调案件责任、可查看敏感证据范围、可建议/可批准/可执行、交互次数、最后交互、等待谁与超时。下钻“审核员×复核”显示其查看过的证据版本、模型分歧、决定理由和资格；“运营×执行”显示动作意图、幂等身份和回执，不展示其无权查看的征信正文。

### 右侧接续、模型和指标

默认摘要常显案件目标版本、当前风险级别、当前审核员、缺失材料、待决定关口和最后回执。选择证据节点显示来源/时间/适用范围；选择“人工复核”阶段显示分歧与补证；选择矩阵格显示具体权限；选择回执显示外部状态与防重复提示。待接动作包括请求材料、提出质疑、提交复核、批准/拒绝/退回、核验回执；高风险决定二次确认。

模型显式输入为案件目标版本、允许访问的证据引用、规则/策略版本和具体分析任务；输出为风险建议、证据缺口、冲突/异常和可解释理由。禁止模型批准、放款、拒绝、冻结、解除或关闭申诉。质量指标：证据完整、建议校准、人工推翻、申诉与误伤；成本：人工复核/数据/模型；时延：受理到决定、预警到控制/解除；业务结果：不良/欺诈损失、通过率与客户影响。负向测试必须覆盖证据过期、模型失败、人工资格失效、动作重复和回执 unknown。

**推荐默认：进度。** 个案首先要回答“到哪一步、为何卡住、是否可决定”。关系图用于复杂证据与责任分歧；矩阵用于队列负载和权限审计。

## S02 需求开发协同

### 入选、对象与边界

F：官方材料支持需求—代码—检查—构建—测试—部署—发布—运营链，并列出产品、项目、开发、测试职责。（RD-001～RD-005）目标为软件企业产品研发和数字化部门；触发为新需求、缺陷、范围变更、发布准备、线上事故。核心对象是目标版本、需求、任务、代码/制品、测试、发布和监控。与 S03 的边界是：本场景的成败由软件版本是否达到目标并安全交付判断，不由 Agent 数量或交接拓扑判断。

**关键判断和责任。** 产品 owner 冻结目标/验收，项目/技术负责人拆分计划，开发对实现负责，评审者对审查意见负责，测试对验证证据负责，发布 owner 对合并/部署决定负责；模型只建议。事实系统包括需求/Issue、Git、评审、流水线、制品、部署和监控。失败包括范围漂移、代码/测试不满足、依赖失败、发布失败和线上回归；部署状态不明时不得宣称发布成功。（RD-001～RD-005）

**成功/失败/未知。** 成功要求目标、提交、测试、制品、环境和监控结果可追溯；失败必须停在具体检查/环境并给出修复或回滚责任；部署/回滚无可信状态时保持未知。

### 三视图

**关系视图。** 中心为当前目标版本；围绕它组织需求、任务、代码分支、制品、测试证据、缺陷、发布关口、环境和监控。参与者与智能体通过“负责、实现、评审、验证、批准、部署、回执”相连。相对关系要突出需求→代码→测试→制品的追溯，以及目标变更影响的全部对象。典型交互是选择一个失败测试查看关联提交、开发者、评审和发布阻塞；拖动仅调整布局。

**进度视图。** 阶段为：`目标冻结 → 需求分析 → 任务分解 → 实现 → 代码评审 → 测试/修复 → 发布准备 → 部署 → 监控/恢复`。独有循环：需求改变创建新目标版本并标出受影响任务；评审退回实现；缺陷修复后进入回归；流水线失败可在幂等运行身份下重试；部署失败可暂停、恢复或回滚到具名制品；监控异常触发事故分支。每一步显示 commit/制品/环境的可核验引用，但界面标签全中文。

**矩阵视图。** 行为产品 owner、技术负责人、开发、评审者、测试、发布/运维、安全，以及可选编码/测试智能体；列按场景使用“需求项或交付任务”，二级列显示实现、评审、测试、发布。单元格状态须能发现无人负责、同一人自写自批、评审未回应、测试证据缺失、发布权限不足和目标版本错配。下钻展示任务目标、责任/权限、关联提交/制品、最近交互、未关闭质疑和发布回执。

### 右侧接续、模型和指标

默认摘要常显目标版本、当前阶段、负责人、未通过检查、下一关口、最后流水线/部署回执。选择代码/产物显示对应需求和测试；选择阶段显示返工原因和下一命令；选择单元格显示参与者在该任务的评审/合并/发布权限。接续动作包括请求澄清、分派/接收任务、提交评审、回应质疑、批准发布、请求回滚和核验环境状态。

模型显式输入为目标版本、允许的代码/需求/测试上下文、任务和预算；输出为实现建议、代码/测试产物、风险质疑、修复建议。禁止修改目标、批准自身产物、合并、发布或宣称部署成功。质量：需求覆盖、缺陷逃逸、评审发现、回归；成本：开发/评审/模型/流水线；时延：需求到交付、评审等待、恢复；业务：目标效果、变更失败率和恢复结果。负向覆盖提示注入、目标漂移、流水线断连、重复部署和回滚 unknown。

**推荐默认：进度。** 版本交付是阶段/循环主导；关系图用于追溯依赖和评审责任；矩阵用于资源、职责分离与多任务瓶颈。

## S03 人机交互协同

### 入选、对象与边界

F：治理证据要求可追溯责任、身份权限、人工监督和异常处置；企业材料将 Agent 定义为指令、知识、工具、边界和多步工作流组合。（HA-001～HA-005）目标为部署企业智能体/多智能体的团队；触发为人类目标、任务分派、智能体冲突、工具调用、权限变更、运行失败。核心判断是“谁拥有目标、谁有何权、交接是否完整、冲突由谁裁决”。与 S07 分界：这里管理智能体运行与权力边界，知识/文档只是上下文。

**角色和失败。** accountable human 对目标和最终决定负责；任务 owner、Agent owner、工具 owner、知识 owner、管理员、审计/安全各有责任。事实系统包括身份权限、智能体配置、知识源、工具/API、运行和审计。失败包括指令冲突、重复执行、上下文遗漏、权限越界、循环耗尽、工具 unknown 和责任悬空。（HA-001～HA-005）

**成功/失败/未知。** 成功是人类目标达成、交接被具名接收且工具回执真实；失败保留运行/冲突/拒绝原因和已产生候选；运行或工具状态不能确认时保持未知，不把“模型已输出”当业务完成。

### 三视图

**关系视图。** 默认中心为“当前人类目标”；人类 owner 与任务 owner 位于上游，智能体、子任务/产物在中部，知识/工具/外部系统在下游，质疑、人工关口和回执跨越主链。节点必须区分人、智能体、工具和证据，边明确“委托、交接、监督、引用、允许、禁止、调用、回执、冲突”。典型交互：拖动智能体比较彼此依赖；聚焦一条交接查看上下文包；选择冲突边进入右侧裁决。缩放后仍显示权限边界、当前责任和未决冲突。

**进度视图。** 阶段为：`目标确认 → 权限/上下文准备 → 分解 → 智能体运行 → 产物交接/相互审查 → 质疑 → 人工决定 → 工具动作 → 回执 → 评估`。独有循环：两个智能体冲突进入具名人裁决；上下文不足回到补充证据；运行失败在预算/次数内重试；失控循环可取消；断连后从事件游标恢复；目标变更使旧运行只读。每次运行是阶段子步骤，不等同工作整体进度。

**矩阵视图。** 行是人类 owner、任务 owner、各智能体、工具 owner、知识 owner、安全/审计；列是子任务/交接/工具动作。单元格强调“无权、仅建议、可执行受限工具、可批准”差异，以及交接次数、最后交互、待回应、循环/冲突。下钻智能体×工具动作必须展示被授予 scope、请求人、输入版本、人工 Gate、幂等身份和回执；不得用一个“可用”开关代替权限。

### 右侧接续、模型和指标

默认摘要显示当前目标、人类 owner、活动智能体、运行成本/时延、未决交接/冲突和最近工具回执。选择人显示责任/可裁决项；选择智能体显示任务、输入版本、明确禁权与运行状态；选择交接边显示发送/接收、上下文包与接受时间；选择工具动作显示审批和回执。普通输入只发消息；只有“运行智能体/继续此任务”等显式动作触发模型。

模型输入为人类明确任务、选择上下文、证据引用、目标版本、权限/策略和预算；输出为产物、提案、质疑或证据请求。禁止改变责任、扩大权限、替人批准、自动接受交接或执行未批准工具。质量：任务完成、交接完整、冲突发现、人工推翻；成本：调用/人工/工具；时延：运行、等待交接/裁决；业务：端到端完成与风险事件。负向覆盖多智能体重复动作、恶意上下文、预算耗尽、取消竞态、断连恢复和工具 unknown。

**推荐默认：关系。** 拓扑、权限与交接是本场景主问题；进度图解释运行循环和恢复；矩阵适合审计多智能体×任务/工具的权限冲突。

## S04 内容生产协同

### 入选、对象与边界

F：法规要求生成/合成内容审核、日志和标识；企业案例揭示商品事实、模板、生成、投放回流、一致性、知识产权、水印和人工参与。（CP-001～CP-005）目标为品牌、电商内容和营销创意团队；触发为商品/活动上新、素材变更、本地化、合规/客诉和投放结果。核心判断是“内容是否真实、权利清楚、品牌合规并可发布”。S05 只接收已审内容并决定预算/客群/扩量。

**对象、责任与失败。** 内容 brief、商品事实、来源/授权、候选资产、审核意见、标识、发布包和渠道回执。品牌/内容 owner 对发布负责，创作者对来源声明负责，法务/IP与合规对权利/禁止项负责，渠道运营对发布动作负责；模型无发布权。事实系统为商品、素材、品牌规范、生成平台、版权/授权、内容/广告平台和客诉。失败包括事实偏差、侵权、标识丢失、版本混乱、发布失败和客诉后未撤回。（CP-001～CP-005）

**成功/失败/未知。** 成功要求事实、权利、品牌、标识关口通过且渠道回执绑定获批资产版本；失败进入补证、返工、阻断或撤回；渠道状态不明时暂停复投并核验。

### 三视图

**关系视图。** 中心为当前内容资产版本；商品事实和 brief 在左，模型/创作者/编辑在上，品牌/法务/合规关口在右，渠道、受众反馈和投诉在下。边区分来源、生成、编辑、质疑、批准、标识、发布、撤回和反馈。必须突出“资产—商品事实”“资产—权利来源”“批准版本—渠道版本”三组关系。选择某素材可在右侧检查授权与被哪些发布包使用。

**进度视图。** 阶段：`brief/商品事实 → 权利与来源准备 → 生成 → 自动检查 → 品牌/权利审阅 → 标识 → 发布 → 效果/客诉反馈 → 修订或撤回`。独有循环：事实/品牌偏差返工生成；权利不清发起补证；多渠道规格触发派生版本；发布超时进入 unknown；客诉/政策变化可暂停投放、撤回并创建新版本。旧资产与新资产不能覆盖。

**矩阵视图。** 行为内容 owner、策划、创作者/模型、商品运营、品牌审核、法务/IP、合规、渠道运营；列为内容资产/渠道任务，二级列为事实、生成、权利、品牌、标识、发布。单元格状态突出“待素材、待授权、待修改、已批准、渠道未知、客诉异常”；交互量反映多轮审阅。下钻法务×资产显示权利来源、质疑、决定版本；渠道×发布显示标识、发布时间和回执。

### 右侧接续、模型和指标

默认摘要显示资产版本、内容 owner、事实/权利/品牌检查、当前返工、待发布关口和最后渠道回执。选择资产节点显示预览引用和版本差异；选择权利阶段显示缺失授权；选择单元格显示具体审核责任和最近评论。待接动作是补商品事实、声明来源、回应修改、批准/退回、添加标识、发布/撤回和核验渠道。

模型输入为 brief、商品事实、允许素材、品牌/渠道约束和生成任务；输出为候选内容、差异说明、风险质疑和标识建议。禁止声明权利归属、批准自身内容、发布或撤回。质量：事实/品牌一致、违规/IP/客诉、人工修改/通过；成本：单资产、返工、人审/模型；时延：brief 到可发布、批量吞吐、撤回；业务：采用、受控实验增量和撤回率。负向覆盖来源缺失、敏感内容、提示攻击、渠道超时、重复发布和标识丢失。

**关系视图。** 中心为客户问题/工单；客户、机器人、一线客服、专家、班组长、投诉/质检围绕，订单/政策/附件为证据，退款/补偿/转接/通知为外部动作。边必须表达会话、交接、负责、升级、批准、执行和客户确认。必须突出机器人→人工的上下文包和当前责任转移。选择交接边可查看发送内容、接收人、接受时间和遗漏项。

**进度视图。** 阶段：`身份/意图 → 订单与证据 → 机器人尝试 → 置信/情绪判断 → 带上下文转人工 → 专家/补偿关口 → 外部动作 → 客户确认 → 质检/复开/投诉`。独有循环：机器人重复达到阈值即强制转人；转接被拒需重新路由但保留上下文；证据不足补问；客户拒绝方案升级；问题复开发新回合；投诉时限独立计时；退款/补偿 unknown 时防重复执行。

**矩阵视图。** 行为机器人、一线客服、专家/二线、班组长、退款/补偿审批、投诉、质检/知识运营；列为会话/工单，二级列为识别、处理、升级、动作、确认。单元格显示当前责任、技能/金额权限、处理状态、交互/转接次数、最后交互、待客户/待审批、超时/情绪/上下文缺失/重复异常。下钻“一线客服×工单”显示会话摘要、承诺、可用权限和待接；“审批×补偿”显示证据、金额、历史动作及幂等状态。

### 右侧接续、模型和指标

默认摘要显示客户问题、当前处理人、服务时限、机器人/人工状态、最近承诺、待审批动作和最后回执。选择客户节点显示身份验证状态但最小化敏感信息；选择转接阶段显示上下文完整度；选择矩阵格显示当前技能/金额权限；选择退款回执显示防重复警示。聊天是工作本体的一部分，但接续台仍优先显示当前责任、下一动作、证据和时限。

模型输入为当前会话、允许的订单/政策/历史工单、明确任务和权限；输出为意图/摘要、建议答复、转接建议、证据缺口和质检质疑。禁止确认身份、承诺越权结果、批准退款/补偿、修改订单/账号或关闭投诉。质量：首解、上下文完整、复开/投诉、质检和客户满意；成本：单接触、人工/模型/补偿；时延：响应、转接、解决、投诉时限；业务：留存、流失和风险。负向覆盖低置信循环、脆弱客户、提示攻击、恶意退款、转接断连、重复赔付和消息发送 unknown。

**推荐默认：进度。** 当前工单的接续、时限和升级最重要；关系图解释多次转接与承诺责任；矩阵用于队列、技能、过载和金额权限。

## S09 供应链履约协同

### 入选、对象与边界

F：国家指南将计划、生产、采购、库存、物流、质量、风险、供应商和交付责任连成端到端链路，并强调多源交换、风险感知和协同响应。（SL-001～SL-003）目标为制造、零售、电商、物流和医药供应链；触发为需求/订单变化、缺货、供应商/质量/运输异常、价格/交期变化或调拨。关键判断是事实是否一致、替代方案如何权衡、谁能改变合同/采购/库存/客户承诺。转化目标归 S05。

**对象、角色与失败。** 需求/供给计划、订单、库存、产能、物料清单、供应商/合同、采购单、仓运任务、质量、交付承诺和多系统回执。供应链/履约 owner 对端到端结果，计划、采购、生产、仓储、物流、质量各对本段负责，供应商/承运商对外部承诺和回执负责。事实系统为企业资源、计划、供应商、制造、仓储、运输、订单、质量、合同/付款和物联数据。失败包括多系统版本冲突、无人负责、建议忽略合同/质量、供应商失约、重复采购/调拨和假完成。（SL-001～SL-004）

**成功/失败/未知。** 成功要求数量、时间、合同/质量约束和多系统/外部承诺一致；失败保留不可满足约束与业务影响并升级/重排；供应商、承运商或系统状态冲突时不宣布履约完成。

### 三视图

**关系视图。** 中心为当前履约事件/承诺；需求/订单、库存/产能、供应商/合同、生产、仓储、物流、客户承诺形成网络，角色与外部主体通过计划、挑战、批准、执行和回执相连。必须突出内部计划与外部承诺、数量/版本/时间的一致性。选择供应商边查看承诺版本、最近确认和替代依赖；选择冲突回执定位源系统。

**进度视图。** 阶段：`信号/异常 → 多系统事实快照 → 影响分析 → 方案/权衡 → 跨角色质疑 → 采购/质量/合同关口 → 采购/调拨/仓运动作 → 多系统回执 → 跟踪/交付 → 复盘`。独有循环：预测/订单变化重排；供应商拒绝切换替代方案；质量失败退货/重采；运输延误重路由；数量或时间冲突补对账；外部主体未确认保持 unknown；动作失败执行补偿而非删记录。

**矩阵视图。** 默认主视图。行为供应链 owner、计划、采购、供应商经理/外部供应商、生产、仓储、物流/承运商、销售/渠道、质量、财务/法务；列为订单/物料/异常处置任务，二级列为计划、采购、生产、仓储、运输、交付。单元格显示分段责任、合同/金额/质量权限、状态、交互次数、最后承诺、待确认、超时/数量冲突/质量/外部 unknown。下钻“供应商×采购”显示报价/交期/承诺版本与回执；“物流×订单”显示运输事件、客户承诺和异常处置。

### 右侧接续、模型和指标

默认摘要显示履约目标/承诺版本、当前异常、端到端 owner、影响订单/数量/时间、待决定方案、外部确认和最近多系统回执。选择矩阵格优先显示该参与者本段责任、权限、最后承诺和待接；选择进度方案显示成本/服务/质量权衡；选择关系边显示跨企业证据与数据新鲜度。待接动作包括请求确认、提出替代、批准采购/调拨/加急、更新客户承诺、核验多系统和升级业务连续性事件。

模型输入为需求/订单/库存/产能/合同/质量/运输事实的版本化引用、目标和明确优化任务；输出为影响分析、方案、权衡、异常/数据质疑。禁止选择供应商、签合同、创建采购/付款、调拨、承诺客户或宣称履约。质量：预测/库存准确、承诺一致、异常闭环、质量；成本：库存、采购、仓运、加急、缺货；时延：响应、采购/调拨/交付；业务：准时足量、满足率、周转、毛利和连续性。负向覆盖过期库存、供应商数据污染、约束遗漏、重复采购、跨系统分裂和承运商 unknown。

**推荐默认：矩阵。** 多组织、多任务、多段责任和外部确认最适合矩阵暴露；进度图负责单个异常闭环，关系图负责供应网络与依赖风险。

## S10 医疗服务协同

### 入选、对象与边界

F：医疗机构、医师、药师的诊疗/处方/质控责任明确，人工智能只能辅助；公开场景集中于辅助决策、病历、质控和随访。（MS-001～MS-006）首版目标限医疗机构的诊疗辅助、病历/处方质控与随访；触发为患者咨询/就诊、检查、病历/处方建议、质控预警、随访异常或不良事件。关键判断是信息是否充分、是否适宜线上、专业人员是否签署、是否需转线下/紧急升级。保险、药研和泛医院运营不在当前范围。

**对象、角色与失败。** 患者身份/同意、主诉病史、检验影像、指南/药品规则、辅助建议、病历/处方草稿、医师/药师决定、质控、不良事件和随访。医疗机构/科室承担组织责任，接诊医师对诊疗，药师对审方，护士/检验/影像/医务质控对本专业环节负责；AI 无诊断/处方终局权。事实系统为病历、医院业务、检验、影像、处方/药品、预约随访、质控和不良事件。失败包括身份/同意缺失、临床事实不全、禁忌、线上不适宜、未签署、危急升级迟延和写入 unknown。（MS-001～MS-003）

**成功/失败/未知。** 成功要求医师/药师专业决定、签名、患者/目标版本和系统回执一致；失败转线下、补检、停止或紧急升级；病历/处方/签名状态未知时不得视为已诊疗或已发药。

### 三视图

**关系视图。** 中心为当前就诊/质控事件；患者及同意、临床事实、检验/影像、辅助模型、医师、药师、护士、科室/质控与业务系统相连。边必须区分提供事实、辅助建议、专业判断、审方/质控、签署、执行、随访和上报。必须把模型置于证据到专业人员之间，不能视觉上成为决策中心。选择建议可追溯引用和医师修改；受限临床数据按权限最小显示。

**进度视图。** 阶段：`身份/同意 → 临床事实收集 → 检验/影像补充 → 智能辅助 → 医师判断 → 药师/质控关口 → 病历/处方/转诊动作 → 签名与系统回执 → 随访/质量观察`。独有分支/循环：首诊或病情变化转线下；证据不足补检；禁忌/相互作用退回医师；危急值直接紧急升级；质控退回修订；处方撤销/修订保留版本；签名或写入 unknown 时不得视为完成或发药。

**矩阵视图。** 行为患者/请求者、接诊医师、护士、药师、检验/影像、科室 owner、医务/质控、信息/安全、辅助模型；列为就诊/病历/处方/质控/随访任务，二级列为事实、判断、审方、签署、执行、随访。单元格显示专业责任/资格、可查看临床范围、可建议/签署/执行、状态、交互量、最后专业交互、待补检/待签、禁忌/危急/资格失效/回执 unknown。下钻“医师×诊疗”显示证据、辅助建议、修改和签名；“药师×处方”显示药品规则、质疑与决定。

### 右侧接续、模型和指标

默认摘要常显“当前首版范围：诊疗辅助、质控、随访”、患者对象去标识摘要、同意状态、接诊医师、当前阶段、危急/禁忌质疑、待专业关口、签名和系统回执。选择临床证据显示来源/时间/完整性；选择医师阶段显示建议与专业判断差异；选择矩阵格显示资格/权限；选择回执显示签名、患者对象和版本。待接动作包括补充检查、提出专业质疑、签署/退回、审方、转线下/急诊、撤销处方、核验写入和随访升级。

模型输入为获授权且最小必要的临床事实引用、明确辅助任务、指南/规则版本；输出为辅助建议、证据引用、禁忌/冲突质疑、病历/随访草稿。禁止独立诊断、治疗、开处方、签名、决定转诊终局、关闭危急事件或写入正式病历。质量：病历完整、审方、质控缺陷、医师修改、漏诊误诊/不良事件；成本：医护时间、检查/随访、模型；时延：就诊到专业决定、报告/处方、危急响应；业务/结果：可及性、随访完成及经机构批准的临床指标。负向覆盖身份错配、同意撤回、证据缺失、幻觉引用、禁忌遗漏、专业资格失效、签名/写入 unknown 和断连恢复。

**推荐默认：进度。** 临床安全依赖明确阶段、专业关口、补检和紧急分支；关系图用于多专业/证据责任；矩阵用于科室任务、资格和质控覆盖。
