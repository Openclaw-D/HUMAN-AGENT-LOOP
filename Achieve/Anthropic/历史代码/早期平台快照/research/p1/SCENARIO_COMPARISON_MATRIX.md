## 2. 同名对象不能同义化

| 对象 | 跨场景共同语法 | 必须保留的场景差异 |
| --- | --- | --- |
| Work | 目标版本、owner、状态、截止、证据 | 风控是案件；研发是变更；内容是资产；医疗是就诊/质控事件 |
| Evidence | 来源、采集时间、版本、适用范围、完整性 | 征信/病例等受限证据不能用普通文档权限处理；物理现场需传感/版本关联 |
| Artifact | 版本、作者/Agent、证据引用、挑战、状态 | 病历/处方、发布制品、广告策略、内容资产的 schema 与法律效力不同 |
| Challenge | 发起者、对象、理由、严重度、证据、关闭人 | 医疗禁忌、车辆安全、版权、实验因果、代码安全不可使用同一枚举表 |
| HumanGate | 具名决策者、权限、决定、理由、时间、对象版本 | 医师/药师专业资格、董事会/主责部门、预算 owner、发布 owner 等不可互换 |
| ActionIntent | 对象、动作、参数、幂等键、策略与批准 | 放款、OTA、处方、退款的授权与补偿策略不同 |
| Receipt | connector、外部 ID、状态、时间、响应摘要 | 医疗专业签名、设备现场状态、广告生效、部署监控的可信标准不同 |
| Metric | 定义、口径、基线、目标、观察窗、归因 | 临床结果、坏账、GMV、OTIF、DORA/交付指标不能跨场景平均 |

## 3. 能力归属判断

判定含义：`K`=共享内核候选；`SP`=ScenarioPack；`PP`=PolicyPack；`SC`=领域 Schema；`M`=指标定义；`C`=Connector。共享资格只表示至少三个语义不同场景真实需要，仍需成本与安全 Gate。

| 候选能力 | 归属 | 判断依据 | 不进入共享内核的部分 |
| --- | --- | --- | --- |
| Work / GoalVersion / owner | K | 十场景都需要冻结目标、责任与版本 | 场景阶段、必填字段与状态映射进 SP/SC |
| Actor / Role / Authority | K + PP | 风控、研发、人机、医疗等均需具名责任和无模型终局权 | 专业资格、金额/风险阈值进 PP/SC |
| ContextSnapshot / EvidenceLineage | K + SC | 信贷、代码、知识、现场、病例均需版本化证据 | 受限字段、领域完整性规则进 SC/PP |
| Artifact / Challenge | K + SP + SC | 所有场景都有产物与结构化反对/补证 | 处方、广告实验、车辆安全 case 等独立 Schema |
| Gate / DecisionRecord | K + PP | 所有场景都有具名放行、拒绝、退回 | 谁能批、什么条件、是否双签进 PP |
| ActionIntent / Receipt / unknown | K + PP + C | 十场景都存在外部动作与状态不确定性 | 具体 API、补偿、幂等范围进 Connector/PP |
| Event / Projection / Replay | K | 责任链、审计、恢复与多视图都需要事件事实 | 领域事件字典与保留期限进 SC/PP |
| Evaluation / OutcomeMetric | K + M | 都要区分过程质量、成本、时延、业务结果 | 指标口径、归因窗、临床/财务阈值进 M/SP |
| Policy version binding | K + PP | 法规/组织规则变化必须能说明当时依据 | 每部法规和组织例外不硬编码进 K |
| Connector registry / identity / idempotency | K + C | 多场景均需身份、scope、回执与防重复 | 外部字段映射、认证和回滚由 C 负责 |
| 场景角色、阶段、文案与默认视图 | SP | 会显著改变用户理解，但不改变内核语法 | 不做十套独立引擎 |
| 风控/医疗/车辆/广告规则 | PP + SC | 属于领域责任与禁止项 | 不做全局硬编码阈值 |
| 业务指标仪表板 | M + SP | 指标口径决定页面与决策 | 不用一个“效率分”横跨十场景 |
