# 三视图与右侧接续台产品契约 V2

日期：2026-08-27  
状态：R1 候选冻结；替代 `P1_PROJECTION_CONTRACT.md` 作为后续实现输入，不修改根目录控制文件。

## 1. 产品不变量

1. 关系、进度、矩阵不是三份数据，也不是三个独立页面；它们读取同一权威工作投影，并共享同一选择上下文。
2. 同一工作在三个视图中的 `工作身份、目标版本、投影版本、事件游标、负责人、参与者、阶段、质疑、关口、动作、回执、更新时间` 必须一致。
3. 视图只改变空间组织、聚合和操作入口，不得创建权威业务状态。节点坐标、折叠和缩放可为本地显示状态；责任、进度和决定不能是本地状态。
4. 模型无权改变目标版本、责任、关口决定或外部动作状态。普通消息不触发模型运行。
5. 任何版本不一致、投影滞后、回执未证实或连接器断连均以“未知/待核验”显示，禁止静默推断成功。

## 2. 1920×1080 布局与显示语言

- 顶部约占高度 10%，第一行放场景、工作切换与三视图切换；第二行常显目标摘要、负责人、当前阶段、当前质疑、人工关口、最新回执和更新时间。
- 下方左侧主画布约占宽度 80%，右侧接续台约占 20%。右侧查看详细上下文时可覆盖式展开至约 45%，收起后不改变画布选择。
- 白色背景，黑白为主，只用极少灰色表达非当前、禁用与辅助信息。状态差异必须同时使用文字、线型、边框/纹理或图标，不能仅依赖颜色。
- 所有最终可见文字、无障碍名称、空态、错误、提示、枚举和值说明均为简体中文，不出现英文字母。内部标识、接口、枚举和模型标识可用英文，但投影到界面前必须映射。
- 删除旧左下“查看全局/查看全局动态”。无选择时右侧显示全局接续；选择任一对象后自动进入局部接续；“返回全部”位于右侧标题区。

## 3. 单一权威投影的产品所需信息

以下为产品要求，不是实现 Schema：

| 信息组 | 后端必须可提供的含义 | 三视图共同用途 |
| --- | --- | --- |
| 投影身份 | 工作区、场景、工作身份、投影版本、事件游标、生成时间 | 判断三个视图是否来自同一快照；不一致时禁止操作 |
| 目标与版本 | 当前目标摘要、目标版本、前一版本、漂移原因、变更人和时间 | 顶部摘要、进度漂移、关系影响、矩阵异常 |
| 主体与责任 | 人/智能体/组织/外部主体、角色、当前责任、可执行权限、委托/代理、资格状态 | 关系节点、进度负责人、矩阵行、右侧权限 |
| 工作结构 | 阶段、子步骤、分支、循环、依赖、开始/到期/完成时间、当前节点 | 进度主结构、关系工作流位置、矩阵列 |
| 证据与产物 | 引用、来源/版本/适用范围、完整性、产物版本、作者、关联目标 | 关系证据边、进度输入/输出、矩阵下钻、右侧证据 |
| 质疑与关口 | 对象版本、提出者、理由、严重程度、缺失项、负责人、决定人、决定/理由/时间 | 三视图卡点、右侧待接动作与人工关口 |
| 交互与交接 | 消息、结构化交接、上下文包、参与者、关联对象、时间、是否已读 | 关系交接边、矩阵交互量/最后交互、右侧对话 |
| 动作与回执 | 动作意图、外部对象、批准版本、幂等身份、执行状态、可信回执或未知原因 | 进度完成依据、关系外部节点、矩阵异常、右侧回执 |
| 模型运行 | 显式请求人、任务、输入版本、权限、状态、产物/提案/质疑、成本、时延、失败/未知 | 右侧模型状态、关系智能体节点、进度运行子步骤 |
| 指标 | 定义、口径、基线、目标、观察窗、当前值、数据时间、归因限制 | 顶部结果摘要与各视图下钻，不合成跨场景总分 |

## 4. 统一选择上下文

选择上下文至少包含：全局/局部范围、来源视图、所选对象类型和身份、对象版本、关联工作、关联阶段/任务、关联参与者，以及最近一次有效选择时间。其行为为：

1. 关系节点、边、进度阶段/分支/卡点、矩阵单元格都可成为选择对象；选择立即刷新右侧，不修改业务状态。
2. 切换视图时保留可映射选择。例如从“测试阶段”切到关系图，自动聚焦关联负责人、产物、质疑和关口；切到矩阵，定位相同阶段列及关联参与者行。
3. 无法一对一映射时保留工作级选择，并在右侧说明“已切换到该工作的全部上下文”，不得静默选中错误对象。
4. 选择对象在新投影中被删除或版本过期时，右侧显示“所选对象已更新”，提供查看新版或返回全部；不得继续对旧版本执行动作。
5. URL/本地视图状态可保存视图、缩放、折叠和选择引用，但打开后必须对照权威投影重验证。

## 5. 关系视图

### 5.1 必须表达的语义

节点类型至少包括：人、智能体、组织/外部主体、工作/阶段、证据、产物、质疑、人工关口、外部动作/回执、风险。边类型至少包括：负责、协作、委托、交接、引用、产出、质疑、等待批准、允许/禁止、触发、执行、回执、依赖、影响。

节点位置不是事实，但相对组织必须帮助理解：当前工作/选中对象为中心；直接责任人和当前阶段靠近中心；阻塞者、未决关口、未知回执处于主路径；仅历史或间接影响对象退居外围。拖动后不能改变边语义、负责人或工作流顺序。

### 5.2 交互契约

- 节点可拖动，画布空白处可平移；滚轮平移，`Ctrl+滚轮` 缩放；同时提供界面内“放大、缩小、适应范围、聚焦当前”按钮，避免只能记快捷键。
- 缩放必须有上下限和当前比例反馈；缩小时保留节点类别、责任/风险符号和主要边，逐级隐藏长文案；不能把卡点或人工关口隐藏到不可见。
- 双击节点聚焦其一跳责任/证据/动作关系；再次执行“适应范围”恢复全图。拖动、平移、缩放不应写入业务事件。
- 单击节点/边只改变选择上下文并联动右侧；从右侧选择证据、关口或回执可反向聚焦画布。
- 自动布局须稳定：同一投影和场景模板应保持大体方位，避免每次刷新“跳图”。用户拖动位置保存在本地显示层，目标版本变化时只增量调整新增/删除节点。
- 键盘可遍历节点和主要关系，焦点文案全中文；高风险边在黑白界面中使用实线/双线/虚线及文字标签区分。

### 5.3 关系视图失败状态

投影版本不一致时冻结业务操作并提示刷新；关系数据缺边时显示“责任关系待核验”，不能用位置暗示责任；节点过多时按场景包聚合，但当前负责人、当前卡点、未决关口和未知回执不得被折叠。

## 6. 进度视图

### 6.1 结构和状态

进度由阶段、子步骤、分支与循环组成，不是线性三步。每个可操作节点至少显示：名称、状态、负责人、开始/到期/最近更新时间、输入、输出、缺失项、当前卡点、下一步、目标版本和关联回执。

统一状态词：`未开始、可开始、进行中、等待证据、等待人工决定、等待外部回执、已暂停、重试中、需返工、已回退、已完成、已失败、未知`。场景包可增加领域状态，但必须映射到上述共享语法并显示领域原词。

### 6.2 分支、循环与恢复表示法

| 情况 | 必须表达 | 操作与事件要求 |
| --- | --- | --- |
| 分支 | 分支条件、选择人/依据、未选分支、是否可回到 | 分支选择必须有决定记录；模型只能提出建议 |
| 返工 | 从何节点退回、原因、受影响产物和新版本 | 创建新产物/目标版本，保留旧版本，不覆盖历史 |
| 补证 | 缺什么、向谁请求、截止、收到/拒绝/过期 | 证据请求、提供、拒绝、过期均为可审计事件 |
| 重试 | 原运行/动作、失败类型、次数、退避、幂等身份 | 不得把重试显示成新业务动作；达到上限转人工 |
| 暂停/恢复 | 发起人、原因、暂停范围、安全状态、恢复条件 | 只有具备权限的人可恢复；恢复绑定最新版本 |
| 回退 | 回退目标、影响范围、补偿动作、外部系统状态 | 回退不是删除历史；外部动作需新回执 |
| 目标漂移 | 新旧目标差异、发起人、影响阶段/产物/关口 | 未重新确认前，受影响后续节点标记“版本待确认” |
| 未知 | 未证实对象、最后已知事实、核验责任人和下一次检查 | 不得自动转成功；允许核验、取消或人工处置 |

### 6.3 操作与联动

点击阶段展示相关角色、证据、产物、质疑、关口、动作、回执和模型运行；点击卡点直接定位右侧“当前阻塞”；“下一步”只能来自权威投影可执行命令，不能由前端猜测。关系视图需聚焦同一阶段的责任网络，矩阵需定位对应列。

## 7. 矩阵视图

### 7.1 行列与单元格

默认行是参与者/责任主体，列是场景定义的阶段或可交付任务。场景包必须明确使用阶段还是任务作为主列，并允许按工作规模切换二级列，但不能把十场景硬套同一空模板。

每个单元格至少可提供：

- 责任：主责、执行、协作、咨询、知会或无责任；
- 权限：可查看、可建议、可编辑、可提交、可批准、可执行外部动作、禁止；
- 状态：未参与、待接、处理中、等待他人、已交接、已完成、异常、未知；
- 交互信号：权威协调事件次数、最后交互时间、最后交互类型、未读/待回应；
- 卡点/异常：缺证、权限不足、责任空缺、多人冲突、超时、版本不一致、外部回执未知。

“交互次数”只统计与该参与者×任务交叉点相关的业务消息、结构化交接、质疑、关口决定和回执确认；被动系统刷新和纯阅读不计数。定义、时间窗和过滤条件必须可查看。

### 7.2 聚合与下钻

- 行/列汇总显示责任空缺、过载、超时、异常与未知数量，不显示虚假的统一效率分。
- 单击单元格后右侧先显示该参与者在该任务中的责任/权限、当前状态、最近交互、待接动作和异常，再显示证据、消息与历史。
- 双击或“查看关联”可在关系图聚焦该参与者及任务，在进度图定位该任务；选择上下文不丢失。
- 对多人同责、无人负责、无审批人、参与者已离岗/资格失效等情况必须显式告警。聚合不能掩盖高风险异常。

## 8. 右侧“聊天+接续”台

### 8.1 常显层级

右侧最小常显顺序：

1. **选择摘要：**全局或所选对象、所属工作/版本、负责人、状态、更新时间；
2. **当前阻塞与下一步：**原因、缺失项、等待谁、到期时间、一个主动作和最多一个次动作；
3. **责任与权限：**谁负责、当前用户能做什么、模型明确无何种权力；
4. **最近对话与输入框：**人与智能体消息分开展示，普通消息只记录对话；
5. **模型运行状态：**仅在显式触发后显示请求、运行、产物/质疑、成本、时延、取消/重试；
6. **证据/回执、人工关口、异常、历史上下文：**按当前风险自动展开或折叠。

### 8.2 折叠规则

- 当前质疑、待人工关口、失败和未知默认展开；已完成的普通系统事件压缩为一行；证据/回执默认展示最新且决定性的三项，其余折叠。
- 人与智能体的最近对话保持展开；长历史按日期/目标版本分组，切换版本需明确提示。
- 首屏最多一个主要动作和一个次要动作。会产生外部副作用或通过人工关口的动作使用内联确认卡；高风险动作二次确认并显示对象版本、影响与可否回退。
- 右侧扩展详情不创建第二套选择状态；关闭详情后返回同一对象。

### 8.3 选择联动

| 选择来源 | 右侧首屏必须回答 |
| --- | --- |
| 关系节点 | 它是谁/是什么、承担何责、与当前工作为何相连、正在等待什么、有哪些风险/证据 |
| 关系边 | 关系类型、双方、依据、最近交接/变更、是否存在权限或责任冲突 |
| 进度阶段 | 到哪一步、为什么卡住、负责人、缺什么、下一步、时间、循环/回退和目标版本影响 |
| 进度卡点/关口 | 谁提出、针对哪个版本、需要谁决定、证据、可选决定及后果 |
| 矩阵单元格 | 该参与者在该任务的责任、权限、状态、交互量、最后交互、待回应和异常 |
| 全局 | 当前工作全局活动、未决质疑/关口、未知回执、即将到期与最近对话 |

## 9. 后端事件、命令和策略的产品要求

不规定具体接口或存储结构，但后续实现必须让以下变化可审计并可重建投影：目标版本建立/变更、责任分配/转移/失效、证据请求/提供/拒绝/过期、产物建立/修订、质疑提出/回应/关闭、关口请求/决定、交接建立/接收、动作请求/批准/执行、回执确认/未知、暂停/恢复/回退、模型运行请求/开始/产物/质疑/完成/失败/未知/取消、连接器状态变化。

可变更业务状态的命令必须携带期望投影版本或目标版本，验证当前用户权限与场景策略；普通消息命令只能追加非权威对话。策略必须能回答：谁可做、针对哪个对象和版本、需要何证据/资格/双签、失败和 unknown 如何处置。

## 10. 跨视图一致性 Gate 与可执行测试

1. **同源测试：**并行读取三视图，断言工作身份、目标版本、投影版本、事件游标一致；人为返回旧版矩阵时，界面应冻结操作并提示刷新。
2. **选择贯通测试：**选中矩阵中“测试负责人×发布准备”，切换进度和关系视图，断言仍定位同一任务、负责人及右侧上下文。
3. **版本漂移测试：**变更目标后，旧产物/关口标记为受影响；不得在旧版上执行批准。
4. **循环测试：**分别注入补证、返工、重试、暂停/恢复、回退和 unknown，进度图显示起点、原因、负责人和下一步，历史不消失。
5. **矩阵语义测试：**责任空缺、资格失效、多人冲突、超时和回执未知均能在单元格与聚合层发现，并可下钻到证据。
6. **关系交互测试：**拖动不改责任；平移/缩放/Ctrl+滚轮有效；适应范围与聚焦当前可恢复；高风险节点在最小缩放仍可识别。
7. **接续台测试：**四类选择来源均刷新局部上下文；返回全部恢复全局；旧左下全局栏不存在。
8. **语言与视觉测试：**检查所有可见文本和无障碍名称不含英文字母；截图像素和样式审查只出现黑、白及允许灰阶。
9. **模型禁权测试：**普通消息不产生模型运行；模型提案不改变关口或动作；未证实回执保持未知。
