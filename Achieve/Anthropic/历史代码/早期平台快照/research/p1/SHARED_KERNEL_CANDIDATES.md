# 共享内核候选审查

日期：2026-08-27  
规则：至少三个语义、责任和风险结构明显不同的场景都真实需要，才获得候选资格；资格不是充分条件。

## 2. 只进入扩展层，不进入共享内核

| 候选 | 归属 | 理由 |
| --- | --- | --- |
| 领域阶段、角色名称、默认文案和页面布局 | ScenarioPack | 对用户语义关键，但跨场景状态并不等价 |
| 医疗专业资格、车辆准入/接管、风控额度、广告/隐私、退款金额规则 | PolicyPack | 规则高风险、易变化、需组织/属地版本，不应硬编码 |
| 病历/处方、征信案件、安全 case、内容权利、实验、PO/交付承诺 | Schema | 字段、完整性和法律效力不同；只共享 envelope |
| 坏账/GMV/OTIF/临床结果/首解率/DORA 等 | Metric | 共享 metric definition 结构，不共享指标含义与阈值 |
| EMR、核心信贷、广告平台、CI/CD、车队、ERP/WMS/TMS、CRM | Connector | 共享调用与 Receipt 协议，不共享具体认证/字段/补偿 |
| 领域模型置信阈值、路由策略、自动批准规则 | ScenarioPack + PolicyPack | 尚无跨域充分证据；置信分可校准性也不同 |
| 内容标识、医师签名、车辆最小风险状态、广告档案 | PolicyPack + Schema | 它们是特定责任/证据结构，不是通用组件开关 |

## 3. 暂不应进入内核的候选

- **统一 Agent 评分或自动裁决器**：没有证据证明跨场景可比较，且会掩盖人类责任。
- **一个通用“AI confidence”字段**：不同模型、任务和校准集不等价；应绑定证据、版本与场景阈值。
- **全自动高风险执行**：风控、车辆、医疗、资金/合同动作的材料反而支持具名人 Gate 与 fail-closed。
- **十场景统一状态机**：共享事件 envelope 可以成立，但同名 `approved/released/closed` 的业务含义不同。
- **默认跨场景共享上下文**：证据权限、目的限制和最小必要原则不支持。

## 4. 进入实现前的 Gate

每个内核候选还需通过：①至少前三锚点 + 两个差异场景的字段原型；②权限与负向路径测试；③事件/Receipt/unknown 语义测试；④存储与 connector 成本估算；⑤能从 UI 解释“谁、依据什么、批准了哪个版本、外部是否真实生效”。未通过者退回 ScenarioPack/PolicyPack/Schema/Metric/Connector，不因“复用率高”强行内核化。
