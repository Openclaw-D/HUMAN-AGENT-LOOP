# 见微-人机协同平台：十场景档案

日期：2026-08-27  
用途：P1-01 市场、角色、工作流、责任和风险证据冻结输入。产品决策与最终 Gate 归主任务。

## 阅读约定

- **事实 F**：来源直接揭示的制度、角色、流程或系统能力。
- **推断 I**：由多条事实支持、供产品建模的解释；仍需客户验证。
- **假设 H**：为了后续发现访谈或原型测试而提出，不写成已成立需求。
- 模型、Agent 和自动化默认 `authority=none`；外部动作只有具名人类 Gate 或已授权规则才能放行。`unknown` 表示动作结果未被可信 Receipt 证实，禁止静默记为成功。

## S01 风控业务协同（固定锚点）

**市场背景与目标企业。** F：商业银行互联网贷款要求董事会承担最终责任、总行集中管理并设主责部门，模型自动审批要有人工复核验证机制；公开岗位同时出现反欺诈、反洗钱和内容风险职责。（RC-001、RC-002、RC-005）I：首批目标是有线上信贷、交易或内容风险队列的银行、金融科技与大型平台风控部门。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 贷款/交易申请；预警信号；资料补充；规则或模型版本变更；申诉/解除预警（RC-003、RC-004） |
| 目标 / GoalVersion / 成功判据 | 在绑定规则/模型版本与案件证据的前提下形成可追责风险决定；成功=具名决定、理由和外部审批/控制 Receipt 一致，unknown 未被误记成功 |
| 参与角色 | 董事会/风险委员会（最终责任）；总行主责部门；业务经办；风险审核员；合规/法务；模型与数据团队；申请人/客户；外部数据提供者（RC-001、RC-002） |
| 具名责任结构 | `Accountable`=机构董事会与总行主责部门；`Responsible`=具名风险审核员/经办人；模型仅给建议和证据，不转移责任 |
| 现有事实系统 | 核心信贷/交易系统、征信、反欺诈规则与模型、客户资料、合同/面签、预警队列、申诉记录（RC-001、RC-003、RC-004） |
| 上下文与证据 | 申请材料、征信/三方数据、规则命中、模型版本与特征摘要、历史行为、预警原因、补充材料、审批与解除记录 |
| 协同断点 | 资料缺失或冲突；模型结论与人工判断分歧；预警无负责人；跨系统证据不可追溯；解除控制没有原始依据 |
| Artifact | 风险案件包、证据清单、模型/规则解释、人工复核意见、控制/解除方案、决定记录 |
| Challenge | 对数据时效/授权、规则命中、模型解释、身份一致性或潜在偏差提出结构化质疑 |
| HumanGate | 具名风险审核员批准/拒绝/退回；高风险策略变更由主责部门批准；重大事项上升风险委员会 |
| 外部动作 / Receipt | 写入审批状态、冻结/限额/拒绝/放款、请求补件、解除预警；Receipt 必须含外部系统、对象、动作、时间、版本和回执状态 |

**路径。** 成功：证据齐备→机器建议→必要人工复核→具名决定→外部系统回执。失败：资料不合格、禁止性规则或人工拒绝→理由与证据留痕。unknown：放款/冻结写入超时或回执不一致→保持待确认并禁止二次重复执行。F：公开案例已经呈现“申请—征信/三方数据—必要人工复核—面签—核对/补件”和“预警—筛查—确认—控制—解除”链路。（RC-003、RC-004）

**指标。** 质量：坏账/欺诈漏检、误报、复核一致性、证据完整率；成本：单案人工分钟、外部数据与模型成本；时延：申请到决定、预警到控制、unknown 恢复；业务：通过率、不良率、代偿赔付率、风险损失和客户申诉率。（RC-002）H：阈值与目标值必须由真实机构基线确定。

## S02 需求开发协同（固定锚点）

**市场背景与目标企业。** F：产品/方法文档和研究报告呈现需求、版本、代码、检查、构建、测试、部署、发布与运营数据的端到端交付结构；产品负责人、项目经理、开发和测试具有不同职责。（RD-001、RD-002、RD-003、RD-004、RD-005）I：这些材料证明流程结构和产品能力存在，不证明客户生产环境普遍贯通；目标为有多团队研发、审查与发布门禁的软件企业和企业 IT 部门。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 新需求/缺陷/事故；目标或验收标准变化；代码提交；测试失败；发布与回滚请求 |
| 目标 / GoalVersion / 成功判据 | 将冻结的目标版本交付为经评审、测试和发布 Gate 接受的制品；成功=验收证据齐备、生产 Receipt 与监控一致，范围变化生成新版本 |
| 参与角色 | 需求提出者、产品负责人、项目经理、开发、测试、架构/安全、发布负责人、运营/支持、代码 Agent（RD-002、RD-003） |
| 具名责任结构 | `Accountable`=产品负责人对目标版本、发布负责人对生产放行；`Responsible`=任务 owner、代码 reviewer、测试 owner；Agent 不可自批合并/发布 |
| 现有事实系统 | PRD/需求库、Issue/迭代、代码仓、Code Review、CI、测试与缺陷、制品库、部署/监控（RD-001、RD-004、RD-005） |
| 上下文与证据 | GoalVersion、范围/排除项、Acceptance Criteria、架构约束、代码差异、测试结果、风险、依赖和历史决定 |
| 协同断点 | 需求版本漂移；任务与代码/测试脱链；生成代码缺少证据；审查责任不明确；发布状态被口头宣称 |
| Artifact | 需求基线、实现计划、代码/配置差异、测试证据、发布/回滚包、DecisionRecord |
| Challenge | 对需求歧义、安全/隐私、兼容性、测试覆盖、依赖和发布风险发起可关闭质疑 |
| HumanGate | 目标接受、范围变化、代码合并、安全例外、生产发布与回滚均由具名 owner 决定 |
| 外部动作 / Receipt | Issue 更新、代码提交/合并、CI/CD、部署与回滚；Receipt 绑定 commit/制品/环境/执行 ID/最终状态 |

**路径。** 成功：冻结目标版本→任务分解→实现→评审/测试→发布 Gate→部署回执→监控。失败：验收不符或测试/安全门禁失败→退回修复；范围变化生成新 GoalVersion。unknown：CI/CD 超时、部署状态与监控冲突→不宣称发布成功并进入核验。（RD-001、RD-003、RD-005）

**指标。** 质量：需求覆盖、缺陷逃逸、回归通过、审查问题关闭率；成本：人时、模型/CI 成本、返工；时延：lead time、review/repair/release time；业务：发布频率、变更失败率、恢复时间、目标采用/效果。H：不将自动化 green 当产品验收。

## S03 人机交互协同（固定锚点）

**市场背景与目标企业。** F：企业厂商材料把 Agent 描述为指令、知识、工具/API、边界和工作流的组合；权限需经租户管理员审批并可审计归因。官方治理材料要求责任链、风险监测、异常处置、解释和人工监督。（HA-001、HA-002、HA-003、HA-004、HA-005）I：该组合可作为建模先验，不证明所有企业 Agent 架构同构；目标为部署多 Agent、企业知识与跨系统工具调用的组织。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 人类目标；定时/业务事件；子 Agent 请求；证据冲突；敏感工具调用；异常/拒答 |
| 目标 / GoalVersion / 成功判据 | 在 accountableHuman、权限和成本边界内完成版本化目标；成功=产物可核验、冲突已裁决、工具 Receipt 可信且无越权 |
| 参与角色 | accountableHuman、任务 owner、Agent coordinator/executor/reviewer、知识/数据 owner、工具 owner、租户管理员、安全/合规 |
| 具名责任结构 | 任务必须绑定 `accountableHuman`；管理员只批准 scope，不替代业务 owner；Agent authority 固定为 none（HA-002、HA-003、HA-004） |
| 现有事实系统 | IAM/scope、Agent 配置、知识库、工具/API、业务系统、策略与审计日志（HA-004、HA-005） |
| 上下文与证据 | GoalVersion、角色与权限、ContextSnapshot、来源引用、Agent 运行/交接、质疑、成本、动作意图与回执 |
| 协同断点 | 多 Agent 重复/冲突；权限与业务责任混淆；上下文丢失；工具结果未回收；人类无法解释为何执行 |
| Artifact | 计划、子任务、答案/草稿、Agent handoff、冲突报告、DecisionRecord、ActionIntent |
| Challenge | 证据矛盾、权限越界、目标漂移、风险/成本过限、Agent 互评不一致 |
| HumanGate | 敏感数据访问、权限扩张、高风险工具、最终提交/外发、冲突裁决由具名人审批 |
| 外部动作 / Receipt | API/CLI/企业应用写入；Receipt 记录身份、scope、输入摘要、幂等键、结果与审计归因（HA-004） |

**路径。** 成功：人类目标→按权限分解→多 Agent 产物/互审→人类 Gate→工具回执→结果评价。失败：越权、无证据、策略拒绝或人类驳回→零动作并留痕。unknown：工具调用断线或返回不可核验→保持未知、核验/补偿，禁止重复成功。（HA-002、HA-003）

**指标。** 质量：任务完成、引用可核验、冲突发现、人工推翻/修改率；成本：token/工具调用/人工审查；时延：端到端与 Gate 等待；业务：节省工时、自动动作成功率、风险事件、可解释满意度。H：哪些动作允许规则化自动批准必须按组织 PolicyPack 验证。

## S04 内容生产协同

**市场背景与目标企业。** F：多模态内容类有 109 条严格岗位样本、24 家具名公司，技术密度高；岗位把 HITL、知识产权、水印、成本和时延写入职责。法规要求审核、日志和生成内容标识。（MKT-001、CP-001、CP-002、CP-005）I：目标为电商、广告、品牌、媒体和平台的规模化内容团队。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 商品/活动上新、内容 brief、素材变更、批量本地化、合规/客诉、投放效果回流 |
| 目标 / GoalVersion / 成功判据 | 按 brief/商品/权利/渠道版本交付可发布内容；成功=事实、品牌、权利和标识 Gate 通过且渠道 Receipt 可核验 |
| 参与角色 | 品牌/内容 owner、策划、文案/设计、商品运营、法务/IP、合规审核、投放、模型/平台、外部创作者 |
| 具名责任结构 | `Accountable`=品牌/内容 owner 对发布；法务/合规对权利与禁止项；创作者对来源声明；模型无发布权 |
| 现有事实系统 | PIM/商品数据、DAM/素材库、品牌规范、生成平台、版权/授权、CMS/广告平台、实验与客诉（CP-003、CP-004） |
| 上下文与证据 | brief、商品事实、模板、风格/禁用项、来源授权、模型/提示版本、标识规则、渠道规格 |
| 协同断点 | 商品事实与画面不一致；来源权利不清；多版本审阅混乱；标识丢失；内容与投放结果断链 |
| Artifact | 内容 brief、候选图文音视频、来源/权利清单、风险报告、标识 manifest、发布包 |
| Challenge | 幻觉/商品不一致、肖像/IP、品牌偏差、敏感内容、不可达渠道规格、成本超限（CP-003、CP-004、CP-005） |
| HumanGate | 肖像/IP、品牌高风险、受监管品类、大规模投放与公开发布由具名 owner/法务审核 |
| 外部动作 / Receipt | CMS/店铺/广告发布、撤回、替换；Receipt 含资产 hash、渠道版本、标识、发布时间、平台状态 |

**路径。** 成功：事实/权利校验→生成→自动检查→人审→标识→发布回执→效果/客诉回流。失败：事实、权利或政策不通过→阻断/返工。unknown：平台发布超时或外链内容状态不明→暂停复投并核验。（CP-001、CP-002、CP-004）

**指标。** 质量：事实准确、品牌一致、违规/IP/客诉、人工通过率；成本：单资产成本、返工、人审与生成成本；时延：brief 到可发布、批量吞吐；业务：采用率、点击/转化的受控实验增量、撤回率。禁止把单一企业自报提升外推。（CP-003、GG-004）

## S05 经营增长协同

**市场背景与目标企业。** F：该类有 83 条严格样本和 41 条高薪信号，商业优先模型排名第一；营销算法需影响评估、广告档案和投诉/证据保存，AIGC 素材可经 A/B 订单转化回流。（MKT-001、GG-002、GG-003、GG-004、GG-005）I：目标为电商、零售、平台、广告与销售运营部门。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | GMV/转化目标、商家/商品变化、客群机会、预算调整、活动、实验结果、投诉/异常 |
| 目标 / GoalVersion / 成功判据 | 在预算、客群授权、库存和合规版本下验证经营假设；成功=受控实验得到可信增量证据，扩量/停止决定及平台 Receipt 完整 |
| 参与角色 | 经营/增长 owner、商家运营、营销/投放、数据科学、内容、价格/品类、财务预算、隐私/合规、平台代表 |
| 具名责任结构 | `Accountable`=经营 owner 对目标，预算 owner 对支出；数据/隐私 owner 对客群使用；平台/广告主承担法定义务（GG-001、GG-002、GG-003） |
| 现有事实系统 | CRM/CDP、商品/订单、广告与推荐、预算、实验平台、商家后台、投诉与广告档案 |
| 上下文与证据 | 目标/基线、客群与授权、策略、预算、素材、价格/库存、实验设计、归因窗口、历史投诉 |
| 协同断点 | 目标与预算脱节；相关性冒充因果；客群/价格不合规；实验回流不能解释；内容效果被错误归因 |
| Artifact | 增长假设、客群/策略包、预算计划、实验协议、结果与归因报告、合规档案 |
| Challenge | 样本偏差、增量性、隐私授权、公平性、库存约束、虚假宣传、预算异常 |
| HumanGate | 客群启用、预算/出价、价格优惠、活动上线、策略扩大与暂停由具名经营/预算/合规 owner 批准 |
| 外部动作 / Receipt | 创建/修改广告活动、客群、优惠、推荐策略；Receipt 含平台对象、金额/范围、版本、幂等键与生效状态 |

**路径。** 成功：目标/基线→机会与约束→策略→合规/预算 Gate→小流量实验→结果回收→扩量/停止。失败：合规、库存、预算或实验无增量→不扩大并留理由。unknown：广告/价格写入或归因数据未确认→冻结扩量。（GG-002、GG-003、GG-004）

**指标。** 质量：实验有效性、归因可信、策略合规、客户投诉；成本：CAC、投放/优惠、模型与运营；时延：机会到实验、异常到暂停；业务：增量 GMV/毛利、转化、留存、商家采用和 ROI。H：商业价值必须用客户真实财务口径复核，岗位薪资只能是先验信号。

## S06 物理智能协同

**市场背景与目标企业。** F：具身/智驾类严格样本 121 条，为七类最大。智能网联汽车试点已明确申报、测试/安全评估、准入、限定上路、事件处置、暂停退出以及企业、使用主体和城市责任。（MKT-001、PI-001、PI-002、PI-003）I：首批应聚焦车企、自动驾驶运营、机器人/设备制造中有真实世界闭环的团队。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 新数据/场景、模型/软件版本、仿真或实车测试、部署/OTA、接管、事故/安全事件、投诉 |
| 目标 / GoalVersion / 成功判据 | 在 ODD/系统/安全版本约束下完成数据—测试—限域部署闭环；成功=安全 Gate、设备/车队 Receipt 和现场状态一致，失联进入最小风险状态 |
| 参与角色 | 制造企业、系统/安全 owner、数据与标注、算法、仿真/测试、车辆/机器人运营者、使用主体、城市/监管、事件响应 |
| 具名责任结构 | 企业对产品/系统安全负责；使用主体对运行阶段安全与接管负责；城市/监管履行试点与事件管理；模型无控制终局权（PI-001、PI-003） |
| 现有事实系统 | 传感/车队、数据湖与标注、仿真、版本/制品、测试场、OTA/运维、接管与事故、监管报送（PI-003、PI-004） |
| 上下文与证据 | ODD/系统定义、数据授权、场景覆盖、版本依赖、仿真/实测结果、安全 case、接管/最小风险策略 |
| 协同断点 | 数据—版本—测试不可追溯；仿真与实车偏差；职责跨制造/运营/城市断裂；事件回流慢；远程动作无确认 |
| Artifact | 数据批次/场景集、标注争议、测试计划/报告、安全 case、发布包、接管/事件报告 |
| Challenge | 边缘场景覆盖、数据合规、标注冲突、性能退化、接管可行性、最小风险策略与回滚 |
| HumanGate | 数据使用、道路/现场测试、版本准入、OTA/控制动作、事故分级和暂停退出由具名专业人员/机构批准 |
| 外部动作 / Receipt | 下发测试/OTA、启停任务、限域/降级、监管报送；Receipt 必须来自设备/车队/监管事实系统并含版本与现场状态 |

**路径。** 成功：场景/数据→训练/标注→仿真→集成/实测→安全 Gate→限域部署→运行回执/事件回流。失败：测试不通过、安全条件缺失或事件触发→不部署/降级/暂停退出。unknown：设备失联、OTA 状态或接管结果不明→进入最小风险状态并人工核验。（PI-001、PI-003）

**指标。** 质量：场景覆盖、接管/安全事件、误检漏检、版本可追溯；成本：数据标注、仿真/实测、车队/设备运维、算力；时延：数据到修复、事件到响应、OTA；业务：可用里程/任务完成、停机、事故损失、部署范围。H：机器人领域的责任与 Receipt 仍需补充，不把汽车证据直接外推。

## S07 知识办公协同

**市场背景与目标企业。** F：企业产品/方法材料呈现权限判断、检索、证据组织、答案生成与人工核对链路；知识运营还含清洗、索引、标签/权限、上线测试、日志反馈。（KO-001、KO-002、KO-003、KO-004）I：这些材料证明能力和方法存在，不证明客户生产环境普遍采用；目标为有分级知识、文档与内部流程的中大型组织。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 问答/检索、文档/汇报、表单/流程、知识更新、权限变化、过期/错误反馈 |
| 目标 / GoalVersion / 成功判据 | 在用户身份、知识版本和流程权限下形成有引用的办公结果；成功=来源可核验、必要人审完成、业务系统 Receipt 与对象版本一致 |
| 参与角色 | 员工/请求者、流程 owner、领域专家、知识/数据 owner、权限管理员、合规、Agent/模型 |
| 具名责任结构 | `Accountable`=流程 owner 对业务结果，知识 owner 对来源/更新，数据 owner 对权限；员工对外发/高风险使用负责（KO-001、KO-002、KO-003） |
| 现有事实系统 | OA、知识库/DMS、IAM、邮件/IM、ERP/CRM/HR/财务、表单审批、日志 |
| 上下文与证据 | 用户身份/权限、查询意图、版本化知识、来源引用、模板、截止时间、敏感级别、历史反馈 |
| 协同断点 | 权限过滤错误；答案无引用；过期/冲突知识；生成结果直接用于高风险决策；写入业务系统无 owner |
| Artifact | 有引用答案、摘要/文档草稿、表单草稿、知识缺口/冲突、更新建议、DecisionRecord |
| Challenge | 来源冲突/过期、权限不足、敏感信息、模板/政策不符、结论超出证据 |
| HumanGate | 对外发布、HR/财务/法务决定、权限变更、业务系统写入与知识正式发布由具名 owner 审批 |
| 外部动作 / Receipt | 创建文档、提交表单、更新知识、触发 OA/ERP/CRM；Receipt 绑定对象 ID、版本、权限身份与结果 |

**路径。** 成功：身份/权限→检索→引用生成→核对→必要 Gate→写入回执→反馈。失败：无权限、无足够证据或高风险不可自动处理→拒答/转专家。unknown：业务系统或知识更新未回执→保持草稿/待确认。（KO-001、KO-002、KO-004）

**指标。** 质量：引用正确、答案准确/采用、知识缺口关闭、权限事故；成本：员工检索/编辑、人审与模型；时延：查找/成稿/流程完成；业务：节省工时、流程周期、一次解决、知识复用和返工率。

## S08 客户服务协同

**市场背景与目标企业。** F：机器人可按意图/流程转指定人工技能组并透传上下文；投诉处理存在受理理由、时限、调解、终止、评价与统计责任链。（CS-001、CS-002）企业方案和岗位共同把客户旅程、服务质量与运营效率作为目标。（CS-003、CS-004、CS-005）

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 咨询、订单/售后、投诉、负面情绪、机器人低置信/循环、退款/补偿、监管转办 |
| 目标 / GoalVersion / 成功判据 | 在身份、订单和政策版本下解决或正确升级客户问题；成功=责任人/客户可见结果与退款、转接或工单 Receipt 一致，避免重复处置 |
| 参与角色 | 客户、机器人、一线客服、专家/二线、班组长、投诉/质检、退款/补偿审批、产品/知识运营 |
| 具名责任结构 | `Accountable`=服务/投诉 owner；`Responsible`=当前具名客服或处理人；机器人只在授权范围内回复/收集，不承担最终处置责任 |
| 现有事实系统 | CRM、会话/呼叫、订单、商品/政策知识、工单、退款/补偿、质检、投诉与评价 |
| 上下文与证据 | 身份/授权、会话、订单/履约、政策版本、既往工单、情绪/意图、承诺、附件和投诉请求 |
| 协同断点 | 转人工丢上下文；机器人重复询问；承诺与权限不符；退款/补偿无依据；投诉时限和 owner 不清 |
| Artifact | 会话摘要、意图/证据、工单、建议答复、转接包、补偿方案、投诉决定与理由 |
| Challenge | 身份、事实/订单冲突、政策适用、越权承诺、客户脆弱性、升级必要性 |
| HumanGate | 退款/补偿、账号/合同变更、重大投诉、法律/安全事项和对外承诺由具名人员批准 |
| 外部动作 / Receipt | 转人工、建/派工单、退款/补偿、修改订单/账号、发送通知；Receipt 含队列/处理人、金额、对象和状态 |

**路径。** 成功：识别/取证→机器人处理或带上下文转人工→人类 Gate→动作回执→客户确认/评价。失败：身份或证据不足、政策禁止、客户拒绝方案→说明理由并升级/终止。unknown：转接、退款或消息发送状态不明→不得重复扣款/补偿，进入核验。（CS-001、CS-002）

**指标。** 质量：首解率、转人工上下文完整、复开/投诉、质检与 CSAT；成本：单接触成本、人工/模型、补偿；时延：响应、转接、解决和投诉时限；业务：留存、流失、服务转化、投诉风险与员工体验。（CS-003、CS-004）企业自报效果不作通用基线。

## S09 供应链履约协同

**市场背景与目标企业。** F：国家指南把计划、采购、生产、库存、交付、物流、供应商和异常协同连成端到端链路；专项行动要求数据贯通、风险识别与协同响应。（SL-001、SL-002、SL-003）I：目标为制造、零售、电商、物流和医药等有多主体履约网络的企业。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 需求/订单变化、缺货/积压、供应异常、质量问题、运输延误、价格/交期变化、库存调拨 |
| 目标 / GoalVersion / 成功判据 | 在需求、库存、合同、质量和交付版本约束下恢复履约；成功=跨系统数量/时间/承诺一致，供应商或承运商 unknown 已核验 |
| 参与角色 | 供应链 owner、计划、采购、供应商经理、生产、仓储、物流、销售/渠道、质量、财务/法务、外部供应商/承运商 |
| 具名责任结构 | `Accountable`=供应链/履约 owner；采购、库存、运输、质量分别有具名 Responsible；供应商/承运商对承诺与回执负责（SL-001、SL-002） |
| 现有事实系统 | ERP/S&OP、SRM、MES、WMS、TMS、OMS、库存/价格、质量、合同/付款、IoT/承运商平台 |
| 上下文与证据 | 预测、订单、库存、产能、BOM、供应商能力/合同、交期、运输事件、质量和成本约束 |
| 协同断点 | 预测与订单/库存不同步；跨企业版本不一；异常无 owner；优化建议忽略合同/质量；承运回执丢失 |
| Artifact | 需求/供给计划、异常 case、调拨/补货/采购建议、供应商挑战、交付承诺、处置与影响报告 |
| Challenge | 数据时效、预测偏差、供应商承诺、成本/服务权衡、质量/合规、单点依赖与业务连续性 |
| HumanGate | 供应商切换、价格/合同、采购单、付款、加急/替代、库存报废和客户承诺由具名 owner 批准 |
| 外部动作 / Receipt | 创建/变更 PO、调拨、仓运任务、供应商通知、客户承诺；Receipt 来自 ERP/WMS/TMS/SRM 并含数量/版本/时间 |

**路径。** 成功：事件→事实快照→影响分析/方案→跨角色 Challenge→Gate→多系统动作回执→持续跟踪。失败：约束不可满足、质量/合同不允许或负责人拒绝→升级/重排并保留业务影响。unknown：供应商/承运商未确认或多系统状态冲突→不宣布履约完成。（SL-001、SL-002、SL-004）

**指标。** 质量：预测/库存准确、承诺一致、异常闭环、质量缺陷；成本：库存、采购、仓运、加急、缺货；时延：异常响应、采购/调拨/交付周期；业务：OTIF、fill rate、库存周转、缺货/积压、毛利和业务连续性。（SL-001、SL-004）

## S10 医疗服务协同

**市场背景与目标企业。** F：互联网诊疗要求医疗机构和医师承担诊疗责任，明确实名、病历、处方、药师审核、质控和不良事件；医疗质量由机构主要负责人负总责、临床科室和医务人员落实。（MS-001、MS-003）公开材料中的 AI 场景集中于辅助诊疗、病历、质控和随访。（MS-002、MS-004、MS-005、MS-006）I：首版目标为开展上述工作流的医疗机构/科室，不覆盖保险、药研或泛医院运营，也不证明医院部署规模或临床效果。

| 字段 | 场景模型 |
| --- | --- |
| 触发事件 | 患者咨询/就诊、检查结果、病历生成、诊疗/处方建议、质控预警、随访、异常/不良事件 |
| 目标 / GoalVersion / 成功判据 | 在患者身份/同意、临床证据和规则版本下辅助诊疗/质控/随访；成功=医师/药师专业 Gate、签名和 EMR/处方 Receipt 一致，AI 无终局权 |
| 参与角色 | 患者、接诊医师、护士、药师、科室 owner、医务/质控、检验/影像、信息/安全、AI 系统、监管 |
| 具名责任结构 | `Accountable`=医疗机构主要负责人/科室；`Responsible`=接诊医师对诊断治疗、药师对处方审核、医务人员对记录与执行；AI 无诊断/处方终局权（MS-001、MS-003） |
| 现有事实系统 | EMR/HIS、LIS/PACS、处方/药品、预约/随访、质控/不良事件、身份与同意、监管报送 |
| 上下文与证据 | 身份/知情同意、主诉/病史、检查、指南/药品规则、病历版本、医师签名、质控和随访状态 |
| 协同断点 | 数据跨系统缺失；AI 建议无来源；医师责任被 UI 弱化；处方/病历未签名；质控预警无闭环；患者风险升级晚 |
| Artifact | 就诊摘要、辅助建议及证据、病历/处方草稿、药师审方、质控 Challenge、随访计划、不良事件记录 |
| Challenge | 身份/数据完整、禁忌/相互作用、指南适用、诊断不确定、危急值、转诊/线下必要性、隐私 |
| HumanGate | 医师诊断/治疗与签署、药师审方、高风险分诊/转诊、对外病历/报告、不良事件上报必须由具名专业人员完成 |
| 外部动作 / Receipt | 写入病历、开具/撤销处方、预约/转诊、随访提醒、质控/不良事件上报；Receipt 含医师/药师签名、患者对象、版本和状态 |

**路径。** 成功：身份/同意→事实收集→AI 辅助→医师/药师 Challenge 与 Gate→系统回执→随访/质控。失败：不适宜互联网诊疗、证据不足、禁忌或专业人员拒绝→转线下/补检/停止。unknown：病历/处方写入、签名或通知状态不明→不得视为已诊疗/已发药，立即核验。（MS-001、MS-002、MS-003）

**指标。** 质量：病历准确/完整、处方审核、质控缺陷、漏诊误诊/不良事件、医师修改率；成本：医护时间、检查/随访、模型与系统；时延：就诊到决策、报告/处方、危急值响应；业务/结果：服务可及、随访完成、再入院/并发症等经批准临床指标、患者体验。H：任何临床阈值和效果声明都需真实机构研究或审计，企业案例不能外推。

## 十场景共同结论

I：跨场景证据共同支持“事实系统—上下文证据—产物—质疑—具名人类决定—外部动作—可信回执”的建模链路，但负责主体、不可逆动作、证据标准与结果指标明显不同。这使共享内核获得评估资格，不证明所有对象都应做成同一 UI 或同一数据表。H：前端最终可归拢为工作台、证据/产物审阅、Gate/行动与结果视图等少量页面，但必须经 ScenarioPack 字段验证后再冻结。
