# 见微-人机协同平台：历史来源提炼表

日期：2026-08-26  
用途：记录历史实现中值得提炼的能力。用户已确认这些候选点可以作为见微-人机协同平台的产品能力方向；这不等于允许直接复制旧代码。每项技术实现仍需证明不会引入旧业务状态机、第二真相源或重复接口，才可进入新内核。TAG 与 RelayOS 仅是来源标签，不是新版本模块名、服务名、项目名或运行时依赖。

## 1. 已接受的能力方向（实现待逐项 Gate）

| 历史能力 | 提炼结果 | 新版本归属 |
| --- | --- | --- |
| SQLite/WAL、原子写入、幂等、Outbox | 保留实现经验与测试，重新绑定通用对象 | Event Store / Command Runtime |
| HTTP/SSE、project-scoped read | 提炼为 Workspace API 与实时 Projection | Runtime / Experience Plane |
| Run lease、fencing、restart/replay | 保留并改为 provider-neutral Run 语义 | Runtime Plane |
| ContextSnapshot、Evidence、Citation | 保留不可变输入与稳定定位契约 | Context / Evidence |
| Challenge、Artifact | 去除风控语义，保留补充信息和结构化产物 | Work Runtime |
| advisory-only、human-only Decision | 上升为全平台 Authority invariant | Control Plane |
| WorkCase、GoalVersion | `WorkCase` 改为通用 `Work`；保留目标版本 | Work Runtime |
| AuthorityGrant、Accepted Handoff | 保留时间、范围、具名接受语义 | Identity / Governance |
| HumanGate | 保留受保护动作控制点 | Governance |
| ActionIntent、ExecutionReceipt | 保留外部副作用与未知结果语义 | Integration Plane |
| Scenario configs / fixtures | 改为 BusinessPack 与去标识化验收数据 | Extension Layer |
| Graph、timeline、audit | 从统一 Event 投影，不作为第二真相源 | Experience / Evaluation |
| backup、restore、observability | 作为后续可靠性资产，不计入当前 P1 完成度 | Operations |

## 2. 只作为测试数据或反例的资产

- business/risk/pass/veto、金融预审、`3＋2＋1` 等固定业务词汇；
- 原有流程状态名、页面布局和角色专用 API；
- 风控补证闭环，降级为第一组 compatibility fixture；
- 十场景配置，降级为通用性假设，不视为十个已验证场景；
- GLM 真实候选运行记录，用作模型质量与限流失败数据；
- 权限绕过、跨 stream 去重、stable ID、receipt 校验等历史缺陷，用作负向契约测试。

## 3. 不进入新版本的内容

- TAG 或 RelayOS 的产品品牌、阶段编号和双项目目录边界；
- 两套并存的状态机、Command path、Event schema 和前端 read model；
- 模型直接作权威决定或失败时静默回退；
- 未验证的生产、真实 Connector、市场需求和安全结论；
- 为兼容旧代码而永久保留的行业专用核心对象。

## 4. 迁移方法

1. 先列出候选能力、收益、代价和可能造成的业务绑定，与用户逐项讨论。
2. 共同确认后，才为该能力设计通用 contract 与 compatibility tests。
3. 从历史来源提取单项机制和对应测试，不整体复制目录。
4. 每个能力先改成通用命名与接口，再进入新 runtime。
5. 历史 fixture 通过后，再增加第二个非风控业务包证明通用性。
6. 新版本拥有独立入口、状态模型、API 和 UI 后，旧代码才可归档；在此之前它们只读保存，不能被产品运行时 import。
