## 当前 MVP

- 产品名称：**见微-人机协同平台**。
- 决赛业务范围：**融资租赁**，不混入银行、保险、信托或全牌照叙事。
- 后端唯一一级业务事项：**融资租赁事项**。
- 组织主线：**业务 ↔ 大风控**。
- “业务”指触达供应商、获取和推进商机、联系和服务客户的销售及业务人员群体。
- 大风控固定为：**政策、信审、商务、资产**；决赛重点是信审，并保留信审与政策的强关联。
- 每个融资租赁事项只有一条总生命周期；高层逻辑从商机和尽调进入政策、信审、商务与资产存续。
- 政策产物是每个事项必经的控制输入；政策人员负责模型评分、策略、反欺诈、规则和引擎能力，不逐项目审批。信审基于政策产物承担项目风险判断责任。
- 后端是一条可反馈、可重评的融资租赁业务流图：商机获取 → 尽调 → 政策能力应用 → 信审/风控判断 → 商务执行与起租 → 资产存续。
- 产品采用“大业务流 + 小协同内核 + 少数可插拔能力接口”；专业库负责具体工作，见微负责受控调用、上下文、人工权威、事件、证据和回执。
- 产品采用异常驱动自动化：业务确认客户与设备融资需求后，正常路径尽可能自动推进，异常、高风险或权威决定才精准找人；该目标覆盖尽调、信审、商务与资产，不只服务授信。
- 路线先后端内核，再少量关键可视化，最后完整可视化与主动感知；正式 P 编号尚未冻结。
- 风控是显性优势和主要证据，但见微不是单一信审或风控 Agent。

当前跨环节主循环候选：

> 感知变化 → 解释为什么找谁 → AI 推荐若干人或 Agent → 有权人员确认 → 受控上下文分发 → 人与 Agent 执行 → 结果、证据与回执返回。
