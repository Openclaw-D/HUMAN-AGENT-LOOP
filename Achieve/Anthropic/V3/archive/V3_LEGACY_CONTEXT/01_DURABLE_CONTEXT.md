# 见微 V3 可继承历史语境

本文只整理长期有效的 context。它解释组织、业务与产品落地环境，但不把所有背景都变成后端对象。

## 1. 产品要解决的根问题

见微的稳定问题定义不是“再做一个 AI 聊天入口”，而是减少融资租赁工作中信息传递的损耗、重复、失真与责任断层。

长期有效的产品机制是：

- 连接人、规则、既有系统与 Agent，不推翻现有系统；
- 所有角色围绕同一 Case、同一已确认事实和同一 Context Version 工作；
- 机器承担可自动处理的读取、比对、归纳、候选判断与路由；
- 人负责授权、事实确认、例外判断和正式生效；
- 变更可追溯、可回放、可比较、可失败关闭，并可在模型不可用时回到既有流程。

V3 已将这一通用技术机制收窄到融资租赁场景。过去“融资租赁只是试验场”的广义叙事已被 Gate 1 替代；比赛 Demo 中融资租赁是唯一产品语义边界。

## 2. 公司与事业部背景

目前可以稳定吸收的组织层级是：

> 集团治理 / 董事会约束 → 融资租赁公司 → 事业部 → 融资租赁 Case

当前 V3 的业务内容聚焦小微事业部。集团与租赁公司负责目标、约束和资源传导，不需要在 Demo 中建设一套完整集团管理系统。

历史 TQ 材料中的小微组织可以概括为：

| 组织层 | 历史角色 | 长期有效职责语义 | 在 V3 中的处理 |
| --- | --- | --- | --- |
| 前线 | 新回、存回、直租、辅助 | 获客、项目推进、材料与事实形成、系统/流程/数据支持 | 主要进入业务 Role Application 和商机 Thread；不是四套后端 |
| 中台 | 风控、渠道、产品、销推 | 专业判断、供应商与渠道、产品方案、销售推动 | 风控进入风控 Role Application；渠道/产品/销推是业务能力来源与 Context contributor |
| 后台 | 企划、业管、财务、网安 | KPI、组织运营、资金收益、架构权限安全 | 作为领导/管理 Projection、共享服务与治理能力；不是新的 Case Authority |

历史材料中的“风控”是一个聚合标签。V3 已进一步冻结：风控固定包含政策、信审、商务、资产四个专业板块，并在同一风控 Role Application 内以四类 principal（账号主体）区分写入权限。

用户后续补充的公司级科技背景同样只作为组织 Context：模型相关能力由 AI 团队支撑，传统规则引擎、前后端、测试与工程能力由传统科技团队支撑，科技能力在租赁公司层面集中。它们是 capability provider（能力提供方）和 Adapter 建设方，不拥有融资租赁业务事实。

## 3. 12 个历史 Agent 的正确继承方式

TQ 曾形成 12 个工作角色：

> 新回、存回、直租、辅助、风控、渠道、产品、销推、企划、业管、财务、网安

它们的价值在于表达“谁提供什么输入、用什么能力、形成什么产物、交给谁”，不在于要求 V3 建设 12 套应用、12 份 Context 或 12 个权威对象。

V3 的映射应保持三层分离：

1. Organization Actor：组织中的人、团队或职能；
2. Role Application：领导、业务、风控、外部协同四类产品入口；
3. Process Thread：商机、政策、信审、商务、资产五路并行工作。

一个组织角色可以在同一 Case 中参与多个 Thread；一个 Thread 也可以引用多个组织角色的输入。组织结构决定可见范围、责任与路由，不复制 Case Authority。

## 4. 小微融资租赁业务背景

### 4.1 经营边界

- 公司持融资租赁牌照，Case 必须有可识别的设备 / 租赁物锚点；没有适格设备基础的纯信用融资不是当前产品边界。
- 公司属于商业融资租赁，不具备银行系金融租赁同等资金成本与集团银行资源优势。
- 技术的现实作用是降低信息不对称、运营成本和协作成本，提高风险定价、客户体验、厂商粘性与有效转化，最终提升风险调整后的可持续净利润。
- 净利润是 North Star；规模、投放、时效、风险、资产质量、合规和体验是 driver 或约束，不能替代净利润。

### 4.2 三类一级经营路径

- 直租：以新设备、供应商、交付与付款为传统基本盘；
- 存客回租：基于既有合作与履约信息的再次合作，信息不确定性通常较低；
- 新客回租：新客户利用已有设备融资，风险、专业要求和定价空间通常更高，可能需要属地化现场尽调。

三类路径共享同一个 `FinancingLeasingCase`、五路 Thread 和 Authority Kernel。它们影响 Scenario、Evidence、条件路由和 Role Projection，但不能生成三套后端。

直租与售后回租当前保持同等战略地位；最终 Golden Case 选择不能反向声称公司战略优先级。

## 5. Case 与五路协同

V3 运行骨架已经从旧版“前线—中台—后台大拓扑”收敛为：

> 一个 `FinancingLeasingCase` + 一个 `caseId` + 一条 Event 历史 + 一个当前 Context Version + 五路异步 Process Thread

五路为：商机、政策、信审、商务、资产。它们在产品信息架构上有宏观顺序，但运行上不是同步瀑布。

每次被确认的新事实或 Evidence 进入同一 Case 后：

1. 保存原事件与 Diff；
2. 推进唯一 Context Version；
3. 触发五路分别读取同一已确认 Context；
4. 五路独立产生 candidate run；
5. 自动结果可以推进，也可能因风险、矛盾或补件要求回退；
6. 需要正式生效的内容进入有权 Human Gate，并产生 Receipt。

旧信息不可覆盖。历史中有价值的“V0/V1/V2/V3、DIFF、原始材料定位”概念应转化为 Event、Context Version、snapshot 与 Receipt，而不是前端自己维护版本。

## 6. Evidence 与信审资产

旧 JW 的六维评审、原材料预览、字段定位、风险色、规则命中与评审影响记录是高价值专业资产，但只能作为信审 Thread 内的 Evidence / Skill / Workspace 能力，不再承担 V3 总产品架构。

稳定可继承的 Evidence 原则：

- 原始材料只读并保留来源；
- 结构化事实可以被有权人修正，但必须记录原值、修改人、时间、原因和版本；
- `scoreGrade`、`decisionGrade`、confidence、Evidence 完整度和 hard gate 分开表达；
- 缺失或不可核验通常触发补件 / 人工复核，不自动等于拒绝；
- 新材料的影响应呈现为 Evidence → Fact / Version → Gate / 判断 → 新旧结论，而不是制造连续概率曲线；
- 没有真实历史样本时，不展示伪精确违约概率、模型准确率或坏账下降数字。

## 7. 领导经营语境

历史 TQ 的“人类决策在上、前中后台协同、共同数据在下”提供了一个重要直觉：领导不是逐条处理基层活动，而是设定目标、边界、优先级和授权，并只处理高价值异常。

当前 V3 已进一步收敛为 KPI 经营驾驶舱：

- 目标沿集团 / 租赁公司 / 事业部传导；
- 时间支持年、半年、季、月、周、日；
- 展示目标、应达、实际、差值、趋势和归因；
- 下钻到影响指标的 Case 与 Evidence；
- Leader Agent 可以解释偏差、组织下级反馈并形成 Shadow 方案；
- 领导确认后可以产生 Management Action，但是否能覆盖专业 Gate 仍未冻结。

企划、财务与专业团队提供指标口径、目标、实际数据和解释；Leader Agent 只做聚合、分析和候选，不应凭聊天生成新的 KPI 真相。

## 8. Demo 与前端长期经验

可以继承的前端经验：

- 所有角色都先有 Case Panel，再进入同一 `caseId` 的角色化 Workbench；
- 多 Case 面板可以按阶段、模式、行业、区域、门店 / 团队、风险收益和异常状态形成 Role Projection；具体维度不在 Direction 阶段硬编码；
- 领导看组合与异常，业务看推进与补件，风控看专业 Gate，外部只看受邀步骤和有限进度；
- 一屏只传达少数结论，细节下钻；图谱、矩阵和时间轴只在能解释关系时使用；
- Mobile / Desktop 使用同一应用、同一对象与动作语义，只调整布局与信息密度；
- Demo 采用一个 Golden Case 完整闭环，背景 Case 只提供稀疏且一致的只读 Projection。

## 9. 明确淘汰或降级的历史方向

以下内容不得因本次归档迁移而恢复：

- 把见微重新扩张为通用 OA、通用项目管理、全集团战略执行平台或所有金融业态平台；
- 把 TQ 的 12 Agent 直接建成 12 套前端、12 个 backend aggregate 或 12 份 Context；
- 把“前线—中台—后台”作为融资租赁 Case 的权威状态机；
- 把旧 JW 六维评分或单一总分当成五路流程与最终业务结论；
- 恢复旧四阶段作为 V3 主链，或把商机重新塞回政策；
- 把“科技感、机甲、Unity、大量连线”当作产品架构；它们最多是比赛开场或视觉素材；
- 复用旧硬编码账号、mock gateway、单项目裁剪、旧材料状态或旧前端状态作为业务真相；
- 把目标值、模拟数据、规则合成结果或 Prototype 表述成真实内网生产成效；
- 在 Direction 阶段硬编政策、商务、资产等专业步骤和规则；
- 因旧版“领导纯观察者”限制领导端；Gate 13 已将其修正为可形成受控 Management Action。
