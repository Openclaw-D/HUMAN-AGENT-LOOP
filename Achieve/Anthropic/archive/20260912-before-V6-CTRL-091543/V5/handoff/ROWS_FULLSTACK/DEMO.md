# ROWS 演示指南（DEMO）

适用：`V5/ZCODE_ROWS_FULLSTACK_TASK.md` Rev2 交付版本。全部数据为**合成演示**；演示身份为服务端受控的本地合成角色（张业务（演示）），**不是生产鉴权**；不产生正式 Decision/Receipt。

## 1｜启动（必须用 dev:node，见"运行时说明"）

```bash
cd C:/Users/22673/Desktop/Anthropic/jianwei-v3/site
npm.cmd run dev:node -- --port 3311
```

- 启动前确认 3311 空闲（`netstat -ano | findstr :3311`）；只启动自己的实例。
- 浏览器打开 `http://localhost:3311/v5-preview`。
- 数据文件：`<site>/.v5-preview-data/rows-store.json`（首次 GET 自动生成 approval 种子 v7）。**持久化等级：单进程 JSON 文件，无多实例/事务保证。**

> 运行时说明：`npm run dev`（vinext）把路由跑在 workerd，禁 `node:fs`，持久化不可用（DEFECT-1，实测记录于 IMPLEMENTATION §1）。**演示与测试一律用 `dev:node`**。next dev 有项目级单实例锁（`.next/dev/lock`），同仓库只能跑一个 dev 实例。

## 2｜主演示脚本（约 3 分钟）

1. **四域横条总览**：顶部 远山精密制造 / 新客回租 · JW-2026-018 / 演示项目；项目进展"审批推进中"（灰度条为演示示意，无数字总进度）；四条横条 = 政策（绿灯已确认）/ 信审（黄灯待补充）/ 商务（灰准备中）/ 资产（灰待启动），每条四段灰度分段（悬停可见分段名）。
2. **提交补充说明（核心闭环）**：待办卡"补充设备清单"→点"提交材料"→输入说明（示例：设备清单与报价要点）→"提交说明"。观察：版本 v7→v8、待办转"待复核"、信审状态灯文字转"待复核"（**仍黄灯——不自动变绿**）、项目沟通追加业务说明与系统记录。
3. **持久**：F5 刷新——状态不丢（服务端 JSON 文件，localStorage 不再是事实源）。可重启服务再刷新验证（见 §4）。
4. **第二视口**：另开一个窗口/手机模拟器读同一 URL——读到相同版本与状态。
5. **项目沟通**：底部"项目沟通"展开，输入消息发送——版本继续递增，记录留档。
6. **生命周期情景（演示控制）**：顶部"演示情景"切换（标注"演示控制·非业务操作"）：
   - 起租后资产管理：资产域黄灯"观察中"、待办变"确认首期巡检安排"（v23）；
   - 已结清（演示）：全域绿灯、无开放待办（v41）；此时提交补充说明会被拒（409 NO_OPEN_TODO），沟通仍可留档；
   - 切回"审批推进中"重置回 v7 种子（重置会清空演示期写入，属预期）。

## 3｜边界（如实声明）

- 合成数据与合成后续判断（消息均带"合成"标识）；无真实模型/接口/公司数据。
- 演示情景切换是**演示控制**，不是业务审批/放款/结清按钮；页面无任何正式审批入口，不产生 Decision/Receipt。
- 红线不靠聊天解除：补件只把状态推进到"待复核"，由专业域复核，不自动绿灯。
- 业务视角仅总览与沟通，无四域专业详情入口（越权访问无对应路由）。

## 4｜恢复与排障

- 重置演示数据：删除 `<site>/.v5-preview-data/rows-store.json` 后刷新（下次 GET 重建 approval 种子）。
- 服务重启后状态不变（文件持久化）；若文件被手工改坏，接口返回 500 `STORE_CORRUPT` 并**拒绝静默重置**——按上条删除文件重建即可。
- 端口被占：换端口 `--port 33xx`；同仓库同时只能跑一个 dev 实例（`.next/dev/lock`）。
- 测试自证：`node --test test/v5-preview-http.test.mjs`、`node --test test/v5-preview-recovery.test.mjs`（各自起 3399/3398 隔离实例，运行前须关闭其他 dev 实例释放锁）。
