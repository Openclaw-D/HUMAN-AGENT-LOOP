## 一句话定义

见微 V5-RISK 当前是基于小微融资租赁业务观察的人机交互探索原型：保留政策、信审、商务、资产视角，以有限投入完成简单直观、前后端联通的demo。下文既有业务骨架与完整闭环受2026-09-08/09资源和交付边界约束，不构成公司业务完备性承诺；正式对外文案尚未冻结。

## 第一价值

2026-09-05 用户确认八项 A：风险更早、更完整被发现 → 跨域不断链 → 减少重复劳动与等待 → 提升效率。继承 V4 可用内核，重新冻结风险产品定义；已有实现须按新契约评估适配。

让融资租赁风险更早、更完整、可追溯地被发现，并进入正确的 Human Gate，使资金更可能进入真实、合规、可偿付、风险收益可解释的资产；同时帮助客户的真实融资问题被正确理解和推进。产品不承诺固定收益，也不以单纯提速为成功。

新客回租是唯一首期 Golden Case，但不是产品唯一服务对象或唯一价值来源。任何优化都必须同时检查客户、业务、政策、信审、商务、资产与公司整体的成本、风险、责任和收益；不得以一个角色提速为由，把重复劳动、等待、风险或兜底责任静默转移给另一个角色。

新客回租本身不是差异化，租赁物确存、确权、排重等单点能力也不是见微必须争夺的主战场。见微的核心差异化是一个 Case 内的全局协调接续：同一风险从 Evidence 被发现，到四域分工、Human Decision、商务条件、起租前复核、资产观察与前向反馈始终可追溯、不断链。这里的“全局”只指小微一个 Case 与四个风控域，不扩张为集团级平台或大而全生命周期系统。

## 首期范围

### 继承的四域职能骨架

政策以实际风险五色组织规则（紫、红、黄、蓝、绿），不以操作类/风险类作为产品主分类；信审承接既有六维（合规、交易、生产、营收、负债、流水），风险另作汇总，不是第七维。商务按适用交易模式承接条件；资产同时保留周期巡视、变化观察与专业反馈。能力逐项模块化建设并有明确专家评审责任，不以人数或并发数替代质量。

具体解释、历史来源、预付参考链路与巡视周期的适用边界只维护于 [V4四域协作骨架](V4/DOMAIN_FRAMEWORK.md)。本轮不替换新客回租主案例，不扩合同、付款、物流等交易系统，不把色度当作自动审批权或前端配色任务。

包含：

- 政策、信审、商务、资产四个独立专业域；
- 一个来自既有受理/尽调流程的项目引用，以及带来源、时效、完整度和核验状态的 Context；封存只代表快照不可改写，不代表内容已经真实、完整或一致；
- Evidence、WorkItem、Dependency、Candidate、Human Decision、Receipt、Contribution、Event 与 Projection；
- 按依赖穿插并行、正式 Gate、否决/退回、贡献保留和资产 Evidence 前向反馈；
- Golden Case 所需的真实 API、失败语义、状态投影和最薄交互。

不包含：

- 客户经营、商机管理、尽调采集、融资需求入口或直租/回租分支；
- 汽融、其他事业部或集团级通用化；当前只以小微团队、小微项目、小微风控与小微资源为合法建设范围；
- 通用 CRM、BPM、Agent 平台、模型平台或自研拖拉拽画布；
- 全量制度数字化、全生命周期系统或生产级部署声明；
- 客户、交易供应商未经内部核验直接进入大风控正式流程。

## Authority

- 现有派驻制、逐级报批、岗位职责、必经审批、关键角色决定权和领导例外路径保持不变；
- Human 是责任与 authority 主体；Agent/模型始终 `authority=none`；
- 确定性规则只有在组织授权、版本固定、适用范围明确时才能拦截；模糊事项只输出 Candidate；
- 高、中风险必须过人，低风险也至少需要轻量人工确认；
- 模型不得批准、否决、自动突破流程、创建正式 Receipt 或静默改写业务状态；
- 所有正式动作必须记录 Actor、来源、对象、时间、版本和结果。

## 协同内核

- 四域不是四个孤立栏目，也不是严格串行的整段流程；具体 WorkItem 由 Evidence、Dependency 和 Receipt 驱动；
- 上游业务陈述、十问与材料包先作为待核验 Claim/Evidence 进入；系统必须区分已披露、待核验、已验证、相互矛盾和已过期，不能把业务提交直接升级为事实；
- 低成本、可撤回、无硬依赖的工作可以提前或并行；正式、高成本或明确依赖前序批准的动作必须等待；
- 否决只停止真正依赖的后续工作，已经形成的 Evidence、专业判断、事件和人员贡献继续保留；
- 退回表示需要补充或重做，不等于批准或否决；
- 资产保持独立贷后责任，同时把逾期、巡检、催收、诉讼和处置经验以前向 Evidence/Candidate 反馈政策与信审；
- 多模态结果是带来源和不确定性的 Derived Evidence/Candidate，不能单独证明现场事实。

## 技术原则

- `REUSE FIRST / NO WHEEL`：成熟平台或既有系统能满足身份、权限、流程、存储、日志、模型网关、工作流和页面 Gate 时直接复用；
- AI 能力编排运行时保持可插拔，不绑定 Dify、LangGraph 或任何单一品牌、低代码/代码优先形态；选型综合能力上限、集成适配、稳定性、可观测性、安全、运维和总体成本，以满足业务契约且 ROI 为正为准。租赁内网 Dify `1.13.2` 只保留为当前可用候选与验证环境，不进入对外产品身份；
- Capability Graph 可以重组 Agent、模型、Prompt、检索、Tool、Candidate 和低成本任务；Authority Graph 中的 Human Role、权限、必经审批、正式顺序和 Receipt 规则不可拖动；
- 外部能力通过稳定 API、Tool、MCP、Plugin 或 Workflow Adapter 接入；具体入口随所选运行时适配。通用 `SKILL.md` 不假设可原样导入，须拆解为 Prompt/Knowledge/Workflow 与可执行 Tool；
- 具体模型、平台和供应商不是产品身份。模型必须经服务器端可替换 adapter/gateway 调用，失败不能污染正式状态；
- 内部算力只抽象为“有限、受控、需精细调度的内网算力”，具体拓扑、数量和模型清单不得进入产品文档或演示。

- 当前工作壳采用“顶部 Case Context + 左侧角色看板/事项工作区 + 右侧 Case Chat”。移动端将三者重排为 Context 顶栏与“看板 / 事项 / 协同”切换；Chat 只形成解释、草案、Candidate 和补件建议，不能直接产生正式 Decision 或 Receipt；

## V5 首个闭环与衡量

一个新客回租 Case：材料进入、风险发现、四域协作、人工决定、商务条件、资产观察、前向反馈。该覆盖描述不表示严格串行。商机、尽调及交易系统提供 Context 或结果引用。

冻结指标框架：访前退回率、重复补件次数、无效现场成本、跨域等待时间、关键风险提前发现率、人工有效投入。定义分母、基线、采样与成本口径后再设目标；尚无收益百分比或 ROI 实测承诺。

V4 历史测试是工程参考，不代表 V5 产品接受或当前重验。具体案例事实、规则阈值、岗位 Gate、平台选择、字段与页面仍待收敛。

## HARD STOP

出现以下任一情况立即停止扩张：改变制度 authority；模型获得正式决定权；未经核验的外部输入直达风控；为了演示伪造持久化、身份、数据或生产接入；把首期扩成全生命周期/通用平台；泄露受限信息；或多个 Agent 同时写同一文件、契约、迁移或共享状态。
