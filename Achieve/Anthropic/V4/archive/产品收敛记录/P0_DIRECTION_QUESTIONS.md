# 见微 V4｜P0 大方向收敛问题

状态：`P0 ACTIVE / FOUR-DOMAIN SCOPE APPLIED / PLATFORM FIT OPEN`

日期：2026-09-03

## P0 判断

当前仍处于 P0。最新一轮进一步把全生命周期和六角色方案收窄为“业务送入现行受理/尽调形成的项目 Context，首期只做政策、信审、商务、资产四域轻量协同组件”。四域不是全局串行页面，具体工作按依赖穿插并行。产品冻结复用优先、不造通用轮子，并把 Capability Graph 与不可拖动的 Authority Graph 分开；最终仍需核验成熟平台与最小差异组件边界。

P0 不再需要继续扩业务范围，但也不能在“到底做在 Dify/成熟平台里，还是保留多薄的自研控制面”尚未核验时仓促结束。在用户接受完整宪章前，不进入项目级 exact contract、灰阶图或 FRONT/BACK。

## 第一轮 North Star 候选（已被修正）

第一轮曾将见微描述为版本化 Human–Agent Operating Cell。该表述现只保留为问题历史，不再拥有当前产品定位 authority；当前第一身份以根部 `NORTH_STAR.md` 的纯中文“融资租赁业务与风控协同层”为准。

对象不再按“融资事项何时成为唯一 Case”提问，而改为确认融资需求主线与多阶段/专业对象的关系；One/IMAX 也已降为 ROI 驱动的实施选项。

## 十个 P0 顶层问题（第一轮原题）

以下内容用于保留提问与纠偏来源，不是当前待回答清单。当前待回答项只看本文末尾判定与 `P0_PRODUCT_CHARTER.md`。

### Q1｜产品第一身份是什么

候选层级：对业务说“融资事项协同与风险增强层”；对产品说“版本化 Human–Agent Operating Cell”；对技术说“融资租赁 domain control and authority layer”。需要确认哪个是唯一第一身份，其余两个是否只是解释层。

### Q2｜领域边界到底到哪里

“融资需求”是融资租赁内部用于覆盖直租/回租等模式的统一入口，还是 V4 真正准备跨到其他融资产品？当前最窄建议是只做融资租赁，融资需求只作为该领域的宏观入口。

### Q3｜第一责任用户是谁

系统可以服务所有角色，但首个试点必须有一个对结果负责的 primary owner。需要确认是大风控总监、业务区总、信审负责人，还是“业务区总 + 大风控总监”的双 owner；其他人是使用者而非第一设计中心。

### Q4｜唯一核心对象何时成立

商机和融资事项是否是两个相连但不同的一级对象？当前最窄候选是：商机保持 Opportunity；正式发起尽调时创建/确认 Financing Case，之后贯穿政策、信审、商务和资产。需要确认，不再用“兑现”充当转换节点。

### Q5｜V4 与既有系统、One/IMAX 分别拥有什么

需要冻结 V4 是业务 System of Record（权威事实系统），还是只拥有协同、Context、Evidence、Decision、Receipt、Contribution 等控制账本，而交易事实继续由既有系统持有。也需确认 One/IMAX 是未来可适配的通用底座，还是当前 North Star 的必要组成。

### Q6｜非线性工作的统一规则是什么

当前最窄候选是“生命周期顺序稳定，正式 authority 按依赖推进；材料准备、风险识别和 Candidate 可并行”。需要确认是否允许某些正式阶段并行，还是所有正式状态仍严格依赖前序 Human/规则 Receipt。

### Q7｜自动化最多可以到哪一步

需要确认组织授权的确定性政策规则能否正式拦截、退回或通过低风险事项；传统评分模型能否产生正式结果；生成式模型是否永远只产生 Candidate。当前最窄建议是 P0 不开放生成式自动批准，中高风险必须过人，低风险也保留快速人工确认。

### Q8｜人的长期贡献是不是一级产品能力

需要确认 Contribution Ledger 是否成为跨 Case 的一级长期对象，还是只作为管理 Projection。当前最窄建议是“贡献证据一级化，但不生成单一信任分、不自动授予权限、不直接决定奖惩”。

### Q9｜客户与供应商是第一类产品参与者吗

需要确认他们是否拥有长期身份、权益、参与记录和版本状态，还是 P0 只把他们定义为受控外部信息来源。当前最窄建议是领域模型中是一等参与者，首期产品表面只提供受控参与，不直达大风控。

### Q10｜什么单一证明足以让 P0 结束

需要选择一个不依赖直租/回租标签的 Golden Case，并明确唯一核心价值证据。候选是：一个融资需求进入尽调，政策发现关键风险，跨专业提前协助但不越权，Human 作出标准或例外决定，上游否决可停止依赖工作，所有贡献和 Receipt 仍被保留。需要确认它是否足以代表 V4，或者首个证明必须覆盖其他更关键矛盾。

## P0 Exit Gate

上一版“Q1–Q10 全部回答 + 单一 Golden Case 证明”的 Gate 已被纠正。P0 以 `P0_PRODUCT_CHARTER.md` 获用户整体接受为退出条件；Golden Case 从 P1 起验证产品宪章。P0 完成只授权进入 P1 宏观 Operating Model，不自动授权代码、灰阶图、部署或决赛包装。
