# 见微 V4-LIFE North Star

状态：`FROZEN CORE / CURRENT ROOT AUTHORITY`

最后更新：2026-09-03

## 1. 一句话定义

见微 V4 的对外第一身份仍是“融资租赁业务与风控协同层”；首期交付形态进一步收窄为“小微大风控四域轻量协同组件”。它由业务侧送入现行受理、尽调已经形成的项目 Context，只把政策、信审、商务、资产四个专业域做精、做专、做窄、做落地，不建设商机、客户经营、尽调或全生命周期管理系统，也不改变制度、岗位、逐级报批、审批顺序和正式决定权。

- 不以“通用人机协同平台”作为产品身份；人与模型如何协同是实现手段，不是比赛范围。
- 产品范围只覆盖融资租赁。融资需求是直租、回租的共同上位表达，不借此扩张到其他融资产品。
- 首期不在产品入口和 Golden Case 中区分直租、回租，也不把“交易供应商”设为核心角色；供应商是直租等特定模式下才出现的条件对象，不应反向把通用融资需求主线限定成直租。
- 首期产品核心固定为政策、信审、商务、资产四个大风控专业域。业务是上游输入、补充材料和接收风险反馈的协同接口；客户是业务事实来源之一，不建设独立客户角色应用或直接进入大风控的产品路径。
- 第一设计与控制中心位于大风控；首要责任视角来自风控负责人，产品落地与后端风控逻辑由发起执行团队把控。业务是必要协同主体，但不控制大风控的专业逻辑。
- 具体由哪一个具名岗位承担产品级最终责任，仍需在 P0 内确认；这不改变现有流程中各岗位本来的审批责任。

## 2. 不可改变的制度底线

1. 不改变现有制度性、流程性和根本性安排。
2. 所有既有报批、上报和审批要求继续生效；任一必经关键角色未批准、退回或拒绝时，事项不得自动推进。
3. 可以重新组织信息呈现、材料准备、协同方式和模型辅助，但不得重排 authority graph（权力关系图）。
4. 所有提交、修改、处理、判断、退回、批准和外部动作都必须可执行、可留痕、可保存、可回看，并绑定 Actor、时间、来源和版本。
5. 突破流程不是绕过制度，而是进入现有制度允许的非标/例外报批路径，由有权领导决定。

## 3. 人、Agent 与底层能力

- Human 是责任与 authority 的主体。
- Agent、模型和 Harness 永远 `authority=none`，只能整理材料、梳理逻辑、发现缺口、生成清单和提出 Candidate。
- Tool、MCP、Plugin、规则引擎和其他机器能力属于更底层能力，不与人平级。
- 组织明确授权、版本固定、适用范围明确的确定性规则可以执行其授权范围内的动作；生成式模型不得借“自动化”名义取得该权力。
- 正式动作必须由具名 Human Gate 或组织明确授权的确定性规则产生，并返回可验证 Receipt。

## 4. 业务背景与首期产品边界

```text
上游 Context：业务按现行制度提交已受理、已完成必要尽调核验的项目材料
首期产品核心：政策 · 信审 · 商务 · 资产
```

- 商机和尽调仍是融资租赁真实业务的上游事实，但不属于首期 V4 的产品模块、独立页面、角色应用、Agent 系统或演示主段。V4 只接收由现行系统或具名业务人员形成并经必要核验的 Context/Evidence。
- 首期不自建客户、商机、尽调、融资需求或直租/回租入口，不重复既有 CRM、尽调采集或业务流程；这些事实需要时只以引用、适配器或最小输入契约进入四域网络。
- 政策、信审、商务、资产是四个专业责任域，不是四个必须整域串行完成的页面。具体 work item 采用 Evidence/Receipt dependency graph（工作依赖图）：只要所需依赖已经具备，就可以跨域提前、穿插或并行运行。
- 非线性不是任意越级。模型处理、可撤回材料准备、低成本单项信息核验和 Candidate 可以提前；只有明确依赖上游正式结论的动作和高成本工作，才必须等待对应 Receipt。一个阶段仍有未完成工作，不自动阻止另一个阶段的无依赖工作开始。
- 在重大前序 Gate 尚未通过时，不应向后续角色发起大量问题或工作，避免以表面并行浪费整体时效。上游正式否决后，依赖该结论的工作应停止或冻结，但已形成的证据、判断与贡献不得丢失。
- 资产仍是独立的贷后专业责任域，但不是信息孤岛。历史和在管资产形成的逾期、巡检、催收、诉讼与处置经验，可以向前成为政策、信审的 Evidence 或 Candidate；这是四域风险知识反馈，不是把资产并入信审或要求现场演完完整生命周期。

## 5. 风险优先，而非速度优先

V4 的价值优先级固定为：

```text
制度与权限完整
  → 发现更多风险、提前暴露风险、拦截更多风险
  → 全程可追溯和可恢复
  → 工作更顺畅、更自然、更高效
```

不得以减少 Human Gate、缩短审批链、乐观成功或隐藏不确定性换取速度指标。

V4 同时服务两端的正向价值：帮助客户更清楚地形成可被理解和推进的真实融资事项；帮助租赁公司把资金投向更真实、合规、可偿付、风险收益更可解释的资产，尽量避开欺诈、不可持续现金流和持续下行风险。系统不能承诺固定收益，但必须让风险、依据和责任更早可见。

## 6. 政策、模型与平滑融合

- 政策人员关于模型幻觉、既有模型/规则/参数/制度连续性和平滑过渡的顾虑是正确且必须被满足的产品约束。
- 政策是与信审紧密关联的专业规则域，不是统领全部业务的上位主体。
- 既有制度、规则、参数和经批准模型继续作为正式依据；LLM 优先承担检索、解释、材料整理、差异提示和候选建议。
- 经组织明确批准、版本固定且适用范围明确的确定性政策规则，可以在授权范围内直接拦截；这是组织规则的执行，不是模型取得了 authority。
- 对不能被确定性规则直接判定的事项，应先进行必要的补充核验，再向人提供风险分层、倾向、通过可能性和预计时效等 Candidate；不得把倾向或百分比伪装成正式决定。
- 概率和时效只有在真实历史样本、口径、版本与校准证据成立时才能给出数值；证据不足时只能表达区间、趋势或“无法可靠估计”。
- 高风险和中风险事项必须经过人；低风险事项可提供更轻量、快速的人工确认选项，但不得静默变成模型自动批准。
- 非标或突破事项必须由有权领导沿正式例外流程决定；模型只能辅助准备，不能批准、否决或替领导承担责任。

## 7. 同一目标与人的工作价值

- 业务、政策、信审、商务和资产不是彼此对立的阵营，而是围绕组织长期稳健经营共同工作。
- 产品不得默认业务人员不可信，也不得把所有人长期置于被怀疑、被否定的体验中。
- 人不是流程中的形式节点。长期贡献、专业判断、主动学习和把个人知识投入真实事项，是 V4 的一级产品价值；系统应帮助这些投入在事项之间连续积累，而不是只记录点击和数量。
- 资深员工的任职年限、历史表现、专业积累和组织信任应被看见，并可在现行制度允许时影响工作便利度与核验强度；正式权限仍必须由组织授予，不能由模型或单一工龄指标自动扩张。
- 人员价值不得只按项目数量或最终是否起租评价。即使项目因政策否决而未起租，已经完成的稳定产出、及时响应、风险发现、专业判断和有效协作仍是工作贡献。
- 精确指标、权重和授权算法尚未冻结，不能先做个人总分或模型生成的信任分。
- 如既有系统已维护客户、项目和历史事件，V4 只按授权引用所需 Context，不另建客户全景或第二套事实来源。

## 8. 外部参与的硬边界

- 客户不是首期组件的直接操作角色；首期不建设客户门户、客户身份体系或客户自助流程。
- 交易供应商退出首期核心角色、Golden Case 和通用主线；未来只在直租等确需供应商的模式中作为条件对象接入，不能取得内部大风控 authority。
- 外部输入不能直接穿透到政策、信审、商务或资产人员并成为正式事实。
- 首期路径必须是“外部事实 → 业务或现行制度中的确定内部受理核验角色 → V4 四域协同组件”。未来如接入客户或交易供应商交互面，同样必须经过内部核验。
- 中间角色的正式岗位名称尚未确认，但该 Human Gate 不得被 Agent、中台或虚拟助手替代。
- 外包律所属于资产域中的专业服务供应商，应具有受控身份、案件参与、进度、响应、回款与服务评价记录；其评价不能只看未经案件难度校正的单一回款率。

## 9. 系统与底座边界

- V4 的重点是小微融资租赁四个大风控专业域的受控协同，不是重复建设通用人工智能底座、CRM、尽调系统、BPM、Agent 平台或可视化编排器。
- `REUSE FIRST / NO WHEEL` 是硬边界：身份、权限、正式流程、数据库、日志、模型网关、工作流画布和通用 Web 能力，只要现有系统或成熟平台满足 authority、安全、审计、接口和部署 Gate，就直接复用；V4 只补小微风控领域模板、适配器和无法复用的最小差异。
- 产品采用双图原则：Capability Graph（能力图）可以重新组合 Agent、模型、Prompt、检索、Tool、Candidate 和低成本任务；Authority Graph（权力图）固定现有 Human Role、权限、必经审批、正式顺序和 Receipt 规则。任何拖拉拽都不得修改或绕过 Authority Graph。
- One/IMAX 可以作为可视编排或通用能力底座复用，但不是 North Star 的必要组成；是否采用只由实际适配度、开发成本、维护成本和可验证收益决定。ROI 为负时不得为了概念完整强行接入，自研内部能力仍是可选路径。
- 内网低代码人工智能编排平台优先承担模型调用、提示词、检索、工具与普通工作流编排；其现成画布就是首选编排面，不再自研另一套拖拉拽画布。它属于 Capability Plane（能力层），不得拥有正式业务 authority、canonical state（权威状态）或最终 Receipt。
- 可用内网算力被视为有限且受限披露的经营资源。具体来源、拓扑、数量和模型清单不进入产品文档；产品只保留容量等级、服务约束和经批准的运行指标。
- 模型与算力资源按任务风险、业务价值、时效、质量、并发和单位资源收益动态路由，不冻结一个全局模型或并发数字，也不以 GPU 利用率最高作为唯一优化目标。
- V4 与既有系统分别拥有哪些权威事实仍需在 P0 内冻结。当前不得把“能展示或同步某项数据”等同于“V4 成为该数据的权威来源”。

## 10. 资产闭环与多模态边界

- 政策、信审、商务、资产四个大风控专业域都必须被完整表达。共享客户、合同、租赁物、风险、进度等信息，不等于合并岗位或共享正式决定权。
- 资产域至少覆盖起租后的周期性巡检、逾期预测与预警、催收进度、现场核验、诉讼/执行进度、后续计划和处置结果；具体巡检频率由现行规则、风险分层与人工决定配置，不在产品中硬编码。
- 现场照片、视频、文档、时间地点、采集设备和操作记录属于原始 Evidence；特征提取、差异检测、篡改/重复/合成识别和二维转三维结果属于 Derived Evidence 或 Candidate。
- 生成式三维重建会补全相机未观察区域，不能证明资产真实存在、数量正确或现场未被篡改。它只能帮助空间复核、变化对比和人工理解，必须保留原始介质、来源链、不确定性和 Human Gate。
- 资产数据量不足时，不得用复杂模型包装伪精确的逾期概率、律所能力或人员评分；优先采用规则、可解释统计、人工判断与分阶段验证。

## 11. 产品与展示边界

- 商务保持真实的线性、制式化定位；资产保持独立且包含大量线下工作。
- 首期管理 Projection 只回答四域正在处理什么风险、哪些依赖可并行、哪个 Human Gate 在等待、产生了什么 Receipt；不建设商机、尽调或客户经营看板。
- 领导 PPT 的简化属于决赛冲刺阶段。当前不能为了展示简洁而删除底层状态、制度边界和版本事实。
- V4 的交付必须建立在真实后端状态、API、持久化、失败语义和前后端联调证据上；决赛 PPT、预录素材、静态 fixture 或舞台叙事不能替代真实 E2E。
- 实施顺序以“产品与后端契约 → 后端核心 → 前端 → 前后端联调与部署 → PPT、演示和脚本”为准。该顺序不允许跳过每个阶段本来的验收 Gate。
- 当前比赛展示按约 10 米观看距离、约 3 米 × 6 米主屏的估算基线设计。手机是角色交互面，不是领导唯一可见面；关键动作必须同步形成大屏可读的共享 Projection。精确场地参数留待赛前实测，不把估算冒充正式规格。
- 四块现场屏幕默认按镜像同一 canonical 大屏设计，不依赖扩展桌面或不同屏分别输出；若赛前证明支持独立输入，再把多屏差异化作为可选增强。
- 比赛主段只讲政策、信审、商务、资产四域如何围绕一个小微项目 Context 发现风险、共享 Evidence、按依赖协同并进入正确 Human Gate。业务输入只作极短触发，不表演商机、客户或尽调流程；模型与算力治理只作可信落地约束，不占主要展示篇幅。

## 12. HARD STOP

出现以下任一情况，必须停止并回到 V4-LIFE Control：

- 需要删除、跳过或重排现有报批与审批节点；
- 需要让 Agent、生成式模型或前端拥有正式业务权威；
- 需要把非标突破做成自动通过；
- 需要让客户或供应商信息未经内部核验直接驱动大风控决定；
- 需要用是否起租或项目数量作为人员价值的唯一指标；
- 需要以效率为由减少风险检查、证据、留痕或 Human Gate；
- 需要在缺少历史校准证据时，用伪精确的通过率或时效数字影响正式判断；
- 需要把内网人工智能编排平台当成正式审批系统、权威状态源或责任主体；
- 需要自研已有成熟能力可以满足的 CRM、尽调、BPM、Agent 底座、模型平台或通用拖拉拽画布；
- 需要让拖拉拽、Prompt 或 Agent 编排修改 Human Role、正式权限、必经审批或 Receipt 规则；
- 需要把生成、补全或重建的三维内容当作现场原始事实；
- 需要把未经批准或未脱敏的现场影像、客户材料送出受控数据边界；
- 需要在文档、演示或对外沟通中披露受限的内部算力拓扑、数量或模型清单；
- 需要让公开免登录页面访问真实内部数据、内部凭据或正式业务写路径；
- 需要把手机小屏中的不可见操作、预录结果或静态 fixture 冒充为已经完成的现场 E2E；
- 需要在宏观权威尚未接受前进入灰阶图、前后端实现或决赛包装。
