# 见微 V4｜P0 产品宪章

状态：`P0 ACTIVE / FOUR-DOMAIN SCOPE APPLIED / PLATFORM FIT OPEN`

日期：2026-09-03

## 1. 宪章用途

本文件是 P0 的唯一整体验收对象。它只冻结产品骨架，不展开岗位级材料流转、精确指标、schema、灰阶图或代码。

## 2. 已冻结产品骨架

### 第一身份

见微 V4 是“融资租赁业务与风控协同层”；首期交付只做“小微大风控四域轻量协同组件”。它不是全生命周期管理系统、通用人机协同平台，也不以 One、IMAX、Dify 或某个模型作为产品身份。

### 范围

- 只覆盖小微融资租赁大风控场景，核心专业域固定为政策、信审、商务、资产。
- 商机与尽调属于真实上游业务 Context，不属于首期产品模块、独立页面、角色应用或 Agent 系统。业务按现行制度送入已经受理并完成必要核验的项目 Context。
- 首期不开发客户经营、商机管理、尽调采集、融资需求入口或直租/回租分支；相关交易事实只从既有权威来源按需引用。
- 业务是输入、补充材料和接收反馈的协同接口；客户与交易供应商都不进入首期直接操作面。
- 现有派驻制、逐级报批、岗位职责、审批顺序和关键角色决定权全部保留。

### 控制与协同

- 第一设计与控制中心位于大风控；业务是必要协同主体。
- Human 保持正式 authority；Agent/生成式模型只产生 Candidate。
- 授权确定性政策规则可直接拦截；不确定事项先补充核验，再给风险分层、倾向、经校准的概率或预计时效，由人作正式判断。
- 四个专业域不是四个必须整域串行完成的页面。具体 work item 按 Evidence/Receipt 依赖图穿插并行；一个专业域未全部结束，不自动阻止其他无依赖工作开始。
- 非线性不等于越权：只有明确依赖正式前序或成本较高的动作等待对应 Receipt，不以批量提前打扰换取表面速度。

### 人与外部参与者

- 人的长期贡献、专业判断、学习与知识投入是一级价值，不能只看数量或是否起租。
- 客户与交易供应商只作为受控事实来源；外部信息必须先经现行制度中的内部 Human Role 受理核验，不能直接驱动四域正式决定。

### 技术底座

V4 重点是四域的小微风控模板、受控编排和必要适配，不建设通用底座。身份、权限、正式流程、存储、日志、模型网关、工作流画布和通用页面只要已有成熟能力通过 Gate 就必须复用。低代码人工智能编排平台优先承担 Agent、模型、Prompt、检索、Tool 和普通 AI Workflow；它不拥有业务 authority、权威状态或 Receipt。可编排的是 Capability Graph，不可拖动的是 Human Role、正式权限、必经审批和 Receipt 规则组成的 Authority Graph。

### 资产闭环

- 政策、信审、商务、资产四个大风控专业域都必须被完整表达。
- 资产保持独立贷后责任，同时把逾期、巡检、催收、诉讼与处置经验向前反馈政策和信审。
- 客户与项目的长期事实继续由既有权威系统维护；V4 只引用当前四域工作所需的 Context/Evidence。
- 原始现场介质是 Evidence；反欺诈识别和二维转三维只是 Derived Evidence/Candidate。
- 外包律所作为资产服务供应商纳入进度和绩效治理，但不得仅以原始回款率评价。
- 资产域可以引用起租、存续、巡检、预警、催收、诉讼/处置与结清信息，但首期只实现 Golden Case 证明所需的最小资产闭环，不演完整时间跨度。

### 交付真实性

- V4 必须形成真实可验证的状态、API、失败语义、交互和 Projection；这些能力可以由既有系统、成熟平台与最薄 adapter 共同提供，不预设必须自建独立后端。
- 实施顺序固定为：产品边界与平台适配 Gate → 最小差异契约 → 必要 adapter/配置 → 最薄交互 → 联调与部署 → PPT、演示和脚本。
- Mobile Web、桌面工作台和大屏是同一权威状态的不同交互或 Projection；手机中的关键动作不能成为现场唯一可见证据。
- 具体模型供应商不是产品身份。模型由服务器端可替换 adapter/gateway 调用，凭据不进入浏览器，模型失败不得改变正式业务状态。

## 3. 两个容易混淆的概念

### 不是“全生命周期系统”，而是四域协同组件

P0 不建设客户、商机、尽调和融资需求对象体系。组件只接收一个稳定项目引用及经核验 Context，在政策、信审、商务、资产四域中组织 Evidence、Candidate、WorkItem、Dependency 与 Human Receipt。既有系统已有的状态、审计和事件能力优先复用；只有缺口才补最小 adapter/ledger。

### “交易事实”与“协同治理事实”

- 交易事实：客户主体、租赁物、供应商、直租/回租、融资金额、期限、合同、付款、起租等描述交易本身且通常已有权威系统的数据。
- 协同治理事实：谁在何时提交了哪个版本证据、命中了什么规则、模型给了什么 Candidate、谁完成了 Human Gate、产生了什么 Decision/Receipt、哪些工作依赖被停止、哪些贡献被保留。

当前最窄候选是：既有系统继续拥有交易事实的权威来源，V4 拥有或引用协同治理事实；V4 可以同步和展示交易事实，但不因展示而自动成为其权威来源。

### 与传统流程系统的本质差异

传统流程系统主要回答“当前走到哪一步、下一张表交给谁”。V4 必须进一步回答“当前有哪些事实和不确定性、哪些专业工作可以立刻并行、哪些动作依赖哪一个 Receipt、模型发现了什么跨材料矛盾、谁有权正式决定、否决后哪些工作停止但哪些贡献仍保留”。

如果 Golden Case 只能展示四个栏目和模型摘要，而不能证明 dependency-aware routing、跨域 Evidence、Human authority 与事件可追溯，V4 就没有形成足够区别，不应继续扩张。

通用拖拉拽画布也不是产品差异。V4 的领域价值在于：把可重组 Agent/Tool 能力约束在不可被重组的权限、必经审批和 Receipt 轨道内，并将这一边界落实到政策、信审、商务、资产四域。

## 4. P0 最终收口建议

以下七项不是重新开放讨论范围，而是 Control 根据截至本轮的 User Authority 给出的最窄答案。用户可以一次整体接受，也可以只指出需要修改的编号。

### P0-A｜对象拓扑

已冻结：首期只表达政策、信审、商务、资产四个专业域；业务提交一个经现行受理/尽调形成的项目 Context，商机和尽调不建设为产品模块。四域 work item 按依赖并行，不建立大而全生命周期状态机。

### P0-B｜事实所有权

推荐冻结：客户、租赁物、金额、期限、合同、付款和起租等交易事实继续由既有权威系统持有；V4 拥有或引用路由、Context、Evidence 版本、Candidate、Human Gate、Decision/Receipt、依赖和贡献等协同治理事实。同步展示不改变事实所有权。

### P0-C｜产品级责任结构

推荐冻结：风控负责人承担组织 sponsor、制度边界与最终组织责任；发起执行团队承担产品 owner、建设运行和风控逻辑控制；业务是协同接口，政策、信审、商务、资产是首期四个产品核心角色并保持各自制度责任。客户不建设直接操作面。产品责任不替代流程审批责任。

### P0-D｜唯一第一价值承诺

推荐冻结唯一第一承诺：“让融资租赁风险更早、更完整、可追溯地被发现，并进入正确的 Human Gate，使资金更可能进入真实、合规、可偿付、风险收益可解释的资产。”同时帮助客户的真实资金问题被正确理解和推进；不承诺固定收益。减少无效摩擦与人的长期成长属于后续价值，不能削弱第一价值。

### P0-E｜最终产品形态

产品形态冻结为“可复用成熟平台 + 小微四域领域包 + 必要 adapter + 最薄 Projection”。不预设独立 V4 后端或完整工作台。Dify、One/IMAX、既有流程系统和现有页面谁能通过 Gate，谁就直接承担对应能力；只有四域领域语义、Evidence/Candidate/Receipt 绑定或现场 Projection 的真实缺口才写新代码。

P0-E 不比较“谁的画布更好看”，只检查六项：能否引用可审计的权威状态；能否把四域 Human Gate 与 Agent Candidate 分开；能否绑定 Evidence、Dependency 与 Receipt；能否让业务入口、四域工作面和镜像大屏观察同一状态；能否在模型/平台失败时关闭而不污染业务；能否通过 API/配置导出和替换。满足项直接复用，缺失项才进入最小差异组件。

### P0-F｜知识学习边界

推荐冻结：“个人判断 → 来源与权限保留 → 专业审核 → 版本化组织知识 → 后续事项引用”的学习闭环属于产品核心；它与绩效评分、自动授权和模型训练默认隔离，未经审核的个人判断不能成为组织规则。

### P0-G｜最小数据原则

推荐冻结：只采集用户明确发起的工作交互、任务驱动的现场多模态 Evidence 和获授权系统事件；不做环境监听、全天录音或隐性持续监控。每类数据必须有用途、范围、可见性、保留期、访问权和删除/归档规则。

## 5. P0 Exit Gate

当前最新校正已将全生命周期和六角色方案收回为“上游项目 Context + 政策/信审/商务/资产四域轻量组件”，并冻结复用优先、禁止造通用轮子、能力图可编排而权力图不可拖动。第一价值已获用户认可。P0 仍需完成一次成熟平台能力 Gate，并对更新后的 P0-B、P0-C、P0-E、P0-F、P0-G 作整体接受；在此之前不把文件改为 `ACCEPTED`，也不自动授权 FRONT/BACK、部署或决赛包装。
