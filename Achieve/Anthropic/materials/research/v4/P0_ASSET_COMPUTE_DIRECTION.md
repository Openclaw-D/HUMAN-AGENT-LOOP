# 见微 V4｜资产闭环与算力治理补充

状态：`P0 SUPPORTING DIRECTION / NO IMPLEMENTATION AUTHORITY`

日期：2026-09-03

## 1. 保密边界

- 用户提供了受限内部基础设施信息。具体组织归属、硬件型号、服务器/卡数量、总容量和模型清单均不在本文件或 Context Log 中记录。
- 产品只使用“有限、受控、需精细调度的内网算力资源”这一架构约束。
- 公开检索未获得能够可靠对应用户口述硬件型号的官方规格，因此不使用相邻型号替代，也不生成或持久化内部容量数字。

## 2. 资产域的新定位

资产不是生命周期最后的孤立看板，而具有双重方向：

1. 向后承担起租后的巡检、逾期、催收、现场、诉讼/执行和处置；
2. 向前把历史资产表现转成政策与信审可引用的 Evidence/Candidate。

这形成四域风险反馈闭环，但不把资产岗位并入信审，也不改变现有正式流程。首期组件只接收上游项目 Context，不建设或展示商机、尽调与完整生命周期。

## 3. 资产域最小能力地图

### 贷前/审查反馈

- 历史逾期与迁徙表现；
- 历次巡检异常和整改结果；
- 催收、诉讼、执行和回款结果；
- 同类客户、租赁物、区域及历史条件场景中交易供应商的风险模式；交易供应商不进入首期 Golden Case；
- 以上内容只形成可追溯风险特征与 Candidate，不自动替代政策、信审判断。

### 起租后持续管理

- 基于规则与风险分层生成巡检计划，频率可配置；
- 现场照片、视频、文档、时间地点、设备与人员操作的来源链；
- 本次巡检内部多板块结果，以及跨多次巡检的变化；
- 逾期、催收、现场、诉讼/执行、后续计划和完成 Receipt；
- 每次操作的贡献与质量证据，但不直接压成个人总分。

### 外部法务资源

- 律所身份、授权案件、阶段进度、响应、材料质量、成本、回款和沟通记录；
- 评价需校正案件难度、金额、账龄、地区和所处阶段，避免通过挑选容易案件获得虚高回款率；
- 内部法务与外部律所的精确分工及金额阈值待真实制度核验，不在 P0 猜测。

## 4. 客户与项目历史的引用边界

客户、项目和历史事件的权威底座优先沿用既有系统。V4 不另建客户全生命周期模型，只按授权引用四域判断所需的项目 Context、历史 Evidence 与已有 Receipt；如果现有审计不能支撑 Golden Case，才补最小追加记录。

在此之上可以生成：

- 客户时间轴：适合看先后、阶段和变化；
- 关系图谱：适合看客户、租赁物、律所、事项及条件存在的交易供应商关系；
- 并列对比：适合比较多次巡检、逾期和处置结果；
- 管理看板：适合看组合风险、阻塞、贡献和资源配置。

这些都只是可选 Projection，不属于首期必做范围，也不能成为第二套事实来源。

## 5. 多模态与反欺诈分层

```text
原始介质与采集来源
  → 完整性/重复/篡改/合成检测
  → 特征、差异与空间重建 Candidate
  → Human 复核
  → Decision / Receipt
```

最低边界：

- 高风险场景优先使用任务内直接采集、引导式多角度拍摄和随机挑战，降低旧图复用；
- 保留原始文件哈希、拍摄上下文、上传者、时间、版本和处理链；
- 来源证明只能说明介质及其处理链是否可验证，不能自动证明画面中的业务事实为真；
- 任何生成或补全的三维区域必须显式标记，不参与资产存在性、数量或价值的正式证明；
- 真实现场资料只有在安全、合规和数据边界获批准后才能进入对应模型。

## 6. 内网编排平台与 V4 分层

### 能力层

内网低代码人工智能编排平台优先处理模型接入、检索、提示词、工具、普通工作流和快速迭代。它可以替换，失败时不得改变正式业务状态；它也不直接承担物理 GPU 调度或全局资源最优化。

### 权威与适配层

既有权威系统优先处理项目身份、权限、Human Gate、Decision、Receipt、审计、幂等和失败关闭。只有其无法绑定四域 Evidence/Candidate/Dependency 的真实缺口，才由最薄 V4 adapter/ledger 补齐。能力层输出必须经过权威接口验证，不能因拖拉拽直接成为正式状态。

### 模型服务层

独立的模型服务与资源路由层承担模型实例、队列、批处理、并发、降级和资源计量。模型版本按能力、资源占用、并发、时效和质量注册。较大模型不因单次能力强而默认优先；较小模型也不因吞吐高而自动胜出。

### 调度初始分类（Candidate）

- 即时 Gate：确定性规则命中、权限校验和状态读取；低延迟、高优先级，正式 Gate 不依赖生成式模型可用性。
- 交互辅助：检索、摘要、缺口提示和简单问答；优先使用能稳定满足体验的较轻模型。
- 准实时分析：政策/信审材料理解、风险 Candidate 和复杂交叉核验；允许排队、降级或切换模型。
- 异步重任务：批量文档、多模态巡检、空间重建和历史回测；按任务价值与截止时间进入资源队列。
- 离线经营分析：组合风险、贡献和算力 ROI；定时运行，不与高优先级在线 Gate 抢占资源。

精确 SLO、优先级、抢占和降级规则属于 P3，不在 P0 写死。

## 7. 算力 ROI 看板

看板以“工作负载 × 模型版本 × 资源池”为主视角，可下钻到 GPU-hour，但不把物理卡利用率当成业务价值。

### 技术侧

- 请求量、成功率、队列等待、超时与回退；
- 首响应、P95/P99 时延、吞吐和并发；
- GPU-hour、显存峰值、利用率、功耗和批处理效率；
- 不同模型、量化、批大小与实例数的实际基准。

### 业务侧

- Candidate 被人接受、修改和拒绝的比例；
- 节省的人工复核时间与减少的重复补件；
- 新发现风险、提前发现风险和减少损失的可核验证据；
- 催收/诉讼进度改善与风险调整后的回款贡献；
- 单位 GPU-hour 带来的可接受业务收益。

动态调度目标是：在 authority、安全和任务 SLO 约束下，最大化边际业务价值与风险减少，而不是最大化调用量或满卡率。

## 8. 当前公开技术核验

- World Labs 于 2026-09-01 发布 Atlas，可从少量图像进行空间重建并输出点云或三维高斯表示；官方同时说明未观察区域会被模型补全，因此只能作为复核 Candidate，且当前为 early access。
- Dify 官方文档支持工作流、Tool/Model/Trigger 插件和自定义本地模型接入，能够承担可替换的能力编排；这不构成其适合承担融资租赁正式 authority 的证据。
- NVIDIA Triton Model Analyzer 可测量吞吐、P95/P99 时延、队列时间、显存和 GPU 利用率，适合作为模型部署基准证据；业务 ROI 仍需 V4 自己关联业务 Receipt。
- C2PA 与 NIST 的公开资料支持介质来源链和篡改/合成检测，但二者都不能把“来源可验证”直接等同于“画面业务事实真实”。

## 9. 下阶段必须验证

- 四专业域共享事实、Candidate 与 Human Gate 的精确边界；
- 小样本逾期预测是否存在稳定、可校准的真实增益；
- 律所评价的案件难度校正与反激励设计；
- 多模态采集来源链、隐私、反欺诈与内网空间重建可行性；
- 编排平台、既有权威系统、最薄 V4 adapter 和模型服务之间的能力差距、接口及失败关闭；
- 算力价值归因是否足以支持动态资源调整。
