# 见微 V2 决策记录

状态：`CURRENT PRODUCT AUTHORITY SUMMARY`

## 已冻结

1. 产品名称保持“见微-人机协同平台”。
2. 决赛范围只使用融资租赁。
3. 后端唯一一级权威对象是融资租赁事项；演示事项为 `FL-DEMO-001`。
4. 组织主线是业务与大风控协同。业务指触达供应商、商机和客户的一群人；大风控分政策、信审、商务、资产。
5. 顶层只出现政策、信审、商务、资产。商机与现场尽调作为事项前段活动融入政策材料解析等流程。
6. 政策产物是项目必经输入；政策人员不是逐项目审批人。
7. 高层主脊线为政策 → 信审 → 商务 → 资产，主阶段不倒退；新证据通过局部回流和新版本重新判断。
8. 一次 Evidence/Event 生成一个 Context Version，四板块异步候选处理共享同一版本。
9. 四板块可并行准备候选；每个板块内部五流程严格顺序。
10. 候选准备度与业务权威分离；只有具名 Human Gate 和真实 Receipt 才能推进正式动作。
11. 模型与 Agent `authority=none`；模型只推荐候选，人最终选择。
12. 信息只追加不覆盖；必须能回看每个时间点的人、证据、动作、理由和版本。
13. 高风险动作失败、超时或回执未知时失败关闭。
14. 产品优先回答“为什么找我、我负责什么”，再解释 Agent 如何辅助。
15. 最高集成 Gate 是低侵入、复用现有系统、可回退和短 Time-to-First-Value；不建设重平台。
16. 当前只在外网使用合成、去标识和公开材料；不得索取或推断集团未授权资产。
17. Adapter 默认 fake/stub；live smoke 只能使用项目独立脱敏产品凭据，不得复用 coding runner 凭据。
18. Unity 保留共创、协同、全域的开场叙事；Web/后端拥有唯一业务 Projection。
19. 1920×1080 工作台采用黑白灰、顶部四板块、左侧五流程、中央图谱/矩阵、右侧可调接续台。
20. V1/V2/V3 是同一内核的成熟阶段，不是三个页面或三套后端。
21. 演示内核中的 Evidence 接受、事实确认、具名 Human Gate 与候选问答必须追加 Authority Event；幂等重放不得重复追加。
22. 每个 Context Version 必须有政策、信审、商务、资产四条显式 Stage Run 记录；Projection 必须失败关闭地检查四路版本一致。
23. 当前 Event Ledger 与 Stage Run 历史只在进程内有效。可查询不等于生产持久化，不得宣称可跨重启恢复或满足正式审计留存。
