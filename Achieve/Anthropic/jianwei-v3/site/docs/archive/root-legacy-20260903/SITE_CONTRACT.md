# 见微 V2 融资租赁工作台实现契约

状态：`ARCHIVED V2 HISTORICAL CONTRACT`

> V3 说明（2026-08-30）：本文以下内容保留为已验证的 V2 backend / UI 历史契约，不再约束 V3 信息架构或 Authority schema。V3 Gate 1–19 与 D1 的原始冻结契约已经原样纳入 [`docs/v3-archive/contracts`](./docs/v3-archive/contracts)，不再依赖仓库外路径。当前九个 V3 正式入口复用一套 shared surface family；商机、洞察与五个专业工作台读取同一个本地 SQLite Context/Message/Receipt runtime。消息和 Agent candidate 均为 `authority=none`；只有具名政策、信审、商务、资产人员通过 RBAC 才能记录带 `confirmed_human` Authority Event 与正式 Gate Receipt，业务/JW 不能调用。背景 Case 只允许独立只读摘要。不得用本文的四板块、二十固定流程和精确百分比反向覆盖 V3，也不得把本地 SQLite、合成数据或未接身份源的能力写成生产能力。

## 1. 唯一业务对象与组织语义

- 唯一权威业务对象是融资租赁事项，本地合成事项为 `FL-DEMO-001`。
- 顶层只有政策、信审、商务、资产四个板块；业务与大风控协作，不混入银行、保险、信托或全牌照叙事。
- 政策产物是项目必经输入，但政策人员不是逐项目审批人。模型没有业务权威，候选输出必须进入具名人工 Gate。
- 当前演示聚焦信审，但上下文必须能从政策接入，并向商务、资产继续传递；回流只新增版本和事件，不覆盖历史。

## 2. 四板块与五个四字流程

- 政策：材料解析、规则核验、量化评估、智能预审、智能更新。
- 信审：模型解析、事实核验、证据回链、协调沟通、人工复核。
- 商务：合同审批、物流查验、资金匹配、付款核验、最终付款。
- 资产：起租建档、租金监测、风险预警、催收处置、诉讼退出。
- 四个板块共享同一条融资租赁事项信息。一次材料/事实/事件接入形成唯一 Canonical Evidence/Event 和 Context Version，由政策、信审、商务、资产四条候选处理链异步消费；不得要求重复上传，也不得为四板块复制四份互不相干的事实。
- 四板块可以同时推进 AI/Harness 候选准备，但每个板块内部五个流程严格按顺序：前序未完成时后序只能是 `locked`，不能产生正式完成状态。
- 异步候选准备不等于正式业务完成。商务、资产可以提前生成候选合同字段、物流清单、资产档案或租金监测模板，但签署、付款、起租、催收、诉讼等正式动作仍必须满足前序依赖并进入具名 Human Gate。
- 顶栏只显示四个两字板块名；每个板块按钮内部显示五格实际进度。
- 左栏只显示当前板块的五个四字流程和状态，不重复显示项目或四板块导航。

## 3. 1920×1080 页面结构

- 黑白灰 GPT 风格，桌面基线 1920×1080，避免整体滚动和横向溢出。
- 顶栏与主体必须复用完全相同的四列网格：`104px | 中央工作区 | 10px 拖动线 | 右侧接续台`，两条纵向分隔线从顶部贯穿到底部，不得被 Header 截断。
- 左上 104px 品牌格只保留上下两行：上方“见微”，下方事项编号 `FL-DEMO-001`；项目全名进入中央当前页标题。
- 四个大板块进度按钮从中央工作区左边缘开始；右上“否决/提交”与右侧接续台严格同宽对齐，否决在左、提交在右。
- 主体左栏固定 `104px`；每项只显示四字流程名称和一行状态，不使用占空间的大编号。中间占剩余空间；右侧接续台默认约 420px。
- 右侧分隔线可拖动，接续台建议范围 320–620px；键盘可操作，移动端退化为纵向布局。
- 中间只保留当前板块的业务内容、矩阵/关系图谱切换和少量关键事实，不重复导航。

### 3.1 接续必须成为第一视觉层级

- 顶部四板块不是四个孤立按钮：政策 → 信审 → 商务 → 资产必须由连续主脊线/箭头连接，清晰表达融资租赁事项的大接续。
- 每个板块卡片内部的五格不是装饰：必须按当前板块五流程的真实顺序和进度连接，悬停/聚焦可读流程名称和状态。
- 左侧五流程必须具有连续纵向脊线，明确显示已完成 → 当前 → 等待；点击任一流程后中央工作页、右侧接续和上下游节点同步切换。
- 中央当前流程页面必须显示最小接续链：上一步结果 → 当前 Agent/人员与工作 → 当前 Human Gate → 下一流程；关系图谱负责展开复杂关系。
- 右侧必须显示来自哪里、当前节点、完成后交给谁，形成与顶部和左侧一致的三层接续，不得只靠一段说明文字。

### 3.2 黑白灰进度语义

- 板块候选准备度只允许 `0/20/40/60/80/100` 六档，由该板块按顺序完成的流程数量 `completedStepCount × 20` 派生，不接受前端任意百分比。
- `0%` 是纯白；`20/40/60/80%` 使用从浅到深的四档细灰度；只有五步候选准备全部完成的 `100%` 才使用纯黑底。
- 禁止因为“当前选中”就把整张板块卡片变黑。当前选中只用边框、内描边或排版强调，不能冒充完成状态。
- 每个板块内部流程状态只有 `completed | active | locked`。只能存在一个 `active`；其前序必须全部 `completed`，其后序必须全部 `locked`。
- 顶部板块底色表达 `prepProgressPercent`（候选准备度）；业务权威状态必须另行显示 `authorityState = waiting_dependency | ready_for_gate | approved`。即使候选准备达到 100%，未取得正式 Gate Receipt 时也必须明确标为“准备完成·待前序/待人工”，不得伪装成业务已通过。
- 顶部四板块、左侧五流程、右侧进度条使用同一后端 `prepProgressPercent/completedStepCount/authorityState`，三处不得互相矛盾。

### 3.3 真正的全域关系图谱

- 默认视图是一个贯通政策 → 信审 → 商务 → 资产的全域图谱画布，四个板块作为从左到右的集群；缩小可看完整融资租赁版图，进入流程时自动把当前板块和当前节点居中聚焦，上下游保持可见但弱化。
- 必须继承 P1 已验证的图谱交互机制：点阵背景、滚轮以指针为中心缩放、拖动空白画布平移、拖动节点调整位置、连线实时重算、适应画布、聚焦当前。
- 本轮图谱编辑只允许调整个人视图布局并按 `caseId + contextVersion` 保存位置；节点、关系、权威状态仍由后端 Projection 提供，前端不得新增/删除业务关系。
- “关系图谱 / 业务矩阵”切换按钮高度约 46–48px、字号 15–16px，默认关系图谱；矩阵只显示当前流程的真实业务信息。

## 4. 接续与智能判断

- 一条信息接入的事务边界是同步接受和版本化：后端先返回唯一接受回执，再以同一 `contextVersion` 启动四板块候选处理；四条处理链可以异步完成并增量更新 Projection。
- 所有板块必须回报同一个 `contextVersion`、各自 `processRunId`、当前顺序步骤和候选准备结果。结果只追加事件和版本，不覆盖原始 Evidence/Event。
- 每次聊天由后端根据 `caseId + stageId + flowId` 组装受控 Context Packet，至少包含：项目、当前板块、当前流程、上一节点结果、规则版本、已确认事实、证据缺口、待人工决策和下一接续目标。
- 前端右侧必须看得见“来自哪里、模型自动完成什么、为什么找我、需要我决定什么、将交给谁”。
- 模型只能生成候选解释、证据缺口和 1–3 个 Next Actions；不得提交、否决、确认事实或伪造回执。
- 当前页面右上“否决/提交”都进入具名 Human Gate，后端返回可见 Receipt。板块内部的普通沟通和补证继续在右侧接续台完成。
- 产品模型使用独立环境变量 `JIANWEI_MODEL_API_KEY`，不得读取或复用 GLM coding runner 的 `ZAI_API_KEY`。
- 默认产品模型 endpoint 为 Z.AI general API `https://api.z.ai/api/paas/v4/chat/completions`，不得使用 Coding Plan endpoint；模型名由 `JIANWEI_MODEL_NAME` 配置。
- 未配置产品凭据时必须明确显示“本地候选推理”，使用 deterministic stub；不得伪装为实时模型。配置后调用失败必须 fail closed，不把失败降级伪装成模型成功。

### 4.1 右侧一秒读懂卡片

- 右侧顶部固定为当前节点摘要，不是泛化聊天说明。首屏必须在一秒内回答：现在什么情况、完成多少、卡在哪里、我该做什么、完成后交给谁。
- 至少包含两条横向百分比条：当前板块总体完成度、当前流程完成度；百分比和值由后端派生。
- “当前情况”卡：当前结论/状态 + 为什么找到当前人员。
- “AI 已完成”卡：只列模型/Harness 已真实完成的 1–3 项，不把候选写成正式结果。
- “待我处理”卡：只突出当前人要做的一个首要动作、具名 Owner、缺失证据和 Human Gate。
- “下一接续”卡：下一流程/板块、接收人或 Agent、将携带的 Context Packet 与成功回执条件。
- Chat 位于这些摘要卡之后，作为补充沟通入口；不得让聊天区域挤掉一秒读懂信息。

## 5. 板块差异化主工作区

- 页面粒度锁死为“二十个流程 = 二十个不同工作页”。四个板块级主工作区或把当前板块五流程重复成表格均不通过。
- 左侧流程切换必须同时改变：页面标题与目标、主可视化、业务矩阵、关系图谱、关键指标、证据/缺口、右侧 Context Packet、AI 自动工作、Human Gate 和下一接续。
- 页面可复用渲染组件，但不得复用同一组业务数据、矩阵行或图谱节点冒充不同流程。
- 默认先显示贯通四板块的全域关系图谱，自动聚焦当前流程；矩阵作为同页切换视图并使用当前流程自己的数据。
- 矩阵是当前流程的实际业务信息，不得用“当前板块五流程 + Owner + 状态”作为矩阵。

### 5.1 二十个工作页的主可视化与矩阵语义

- 材料解析：OCR/分类/字段映射与共享信息分发图；矩阵为材料、分类、栏目、字段、可信度、原始定位与 `contextVersion`。
- 规则核验：系统规则适用与例外图；矩阵为规则 × 客户/主体/设备/租赁结构的命中、缺口与例外。
- 量化评估：归一化与六维画像图；矩阵为维度、原始值、归一值、权重、贡献度、证据和异常解释。
- 智能预审：候选结论与 Human Gate 依赖图；矩阵为判断项、候选结论、支持/反对证据、置信提示、待人工问题与影响。
- 智能更新：版本反馈与四板块回流图；矩阵为 V1/V2/V3 变化、触发事件、影响范围、回执、回退点与下一 Context Version。
- 模型解析：多模态解析管线；矩阵为材料、提取字段、候选值、可信度、原始定位与核验状态。
- 事实核验：事实冲突图；矩阵为事实、来源、冲突、证据、核验人和正式状态。
- 证据回链：结论—证据血缘图；矩阵为结论、证据、页码/字段定位、时效、缺口与影响。
- 协调沟通：人与 Agent 接续图；矩阵为问题、发起人、责任人、截止时间、上下文版本与回执。
- 人工复核：候选判断—人工决定图；矩阵为判断项、模型候选、支持/反对证据、人工结论和理由。
- 合同审批：合同义务与条件图；矩阵为条款、信审条件、偏差、法务意见、Owner 与状态。
- 物流查验：设备物流时间线；矩阵为设备/序列号、物流节点、单据、现场证据、异常与责任人。
- 资金匹配：资金方案匹配图；矩阵为资金方/方案、成本、期限、前置条件、可用额度与匹配状态。
- 付款核验：付款条件依赖图；矩阵为付款条件、证据、收款账户、核验人、状态与缺口。
- 最终付款：付款 Gate 与 Receipt 图；矩阵为最终清单、责任人、前置 Gate、外部回执与最终状态。
- 起租建档：合同—设备—保险—租金计划资产谱系；矩阵为资产、合同、设备、保险、起租日与档案状态。
- 租金监测：租金现金流时间线；矩阵为期次、应付日、应付额、实付额、逾期天数与核销状态。
- 风险预警：风险信号传播图；矩阵为信号、阈值、观测值、严重度、证据、Owner 与处置状态。
- 催收处置：分级催收决策树；矩阵为客户/期次、逾期桶、建议动作、人工批准、还款承诺与回执。
- 诉讼退出：诉讼资源与退出路径图；矩阵为案由/资产、主张、证据、外部资源、成本、授权与退出状态。

### 5.2 Flow Workspace Projection

- 后端为每个 `PublicFlow` 返回独立 `workspace`，至少包含 `headline/objective/visualization/matrix/graph/indicators/evidenceGaps/nextActions`。
- `visualization` 必须声明当前流程的业务可视化类型和数据；`matrix` 必须具有当前流程专属列定义与行数据；`graph` 必须具有当前流程专属节点、边和关系标签。
- 前端不得从 `stage.flows` 自动生成矩阵，不得用板块级固定 `stage.workspace` 或 `stage.graph` 响应五个流程。
- 右侧接续台只显示当前 `stageId + flowId` 的 Context Packet 和 Receipt；其他流程的 Receipt 不得显示为当前页回执。
- 每个 `PublicFlow` 必须返回顺序状态 `prepState = completed | active | locked`；每个 `PublicStage` 必须返回 `completedStepCount`（0–5）、由其派生的六档 `prepProgressPercent`，以及独立的 `authorityState`。
- Projection 必须返回事项级 `sharedContext = { contextVersion, evidenceEventId, consumerCount: 4 }`，以及四个板块各自的 `{ processRunId, contextVersion, currentFlowId, prepProgressPercent }`；四者 `contextVersion` 必须一致。
- 当前流程的 `workspace` 还必须返回 `currentSituation/whyMe/aiCompleted/primaryHumanAction/nextHandoff/successReceiptCondition`，供右侧一秒读懂卡片使用；不得由前端以统一模板填充二十个页面。

## 6. 后端最小闭环

- `GET /api/cases/FL-DEMO-001/projection`：返回四板块、五流程、共享 Context Version、四条候选处理链、六档准备度、业务权威状态、差异化内容和当前 Receipt。
- `GET /api/cases/FL-DEMO-001/events?afterSequence=&limit=`：按严格递增 sequence 只读分页返回进程期 Authority Event；未知事项、非法游标/limit 和非 GET 方法必须失败关闭。
- `POST /api/cases/FL-DEMO-001/evidence`：接收一条合成/脱敏信息及 `{requestId,evidenceId,kind,title,summary,actor}`；以幂等、同键异载荷冲突和失败关闭方式生成唯一 Evidence/Event 接受回执与新 `contextVersion`，并让四板块候选 Projection 同步读到该版本。不得实现真实内网上传或把候选写成正式事实。
- `POST /api/cases/FL-DEMO-001/messages`：接收 `{message,requestId,stageId,flowId}`，由服务端组装 Context Packet；保持幂等、同键异载荷冲突、输入校验、超时和 fail-closed 语义。
- `POST /api/cases/FL-DEMO-001/decisions`：接收 `{action,actor,requestId,stageId,flowId}`，`action` 仅为 `reject|submit`；返回具名 Human Gate Receipt，不允许模型调用。
- `POST /api/cases/FL-DEMO-001/facts/:factId/confirm`：保留具名人工确认；确认后 Projection 必须回读服务端状态。
- 当前持久化仍是进程内合成 runtime；不得写成已接真实集团系统或生产数据库。
- Projection 必须暴露诚实的 `runtimeAudit = { persistence: 'in_memory_demo', authorityEventCount, stageRunRecordCount }`，不得把可查询的进程期事件冒充生产持久化。

## 7. 验收 Gate

- 四板块、二十个四字流程与布局符合本契约；顶部进度按钮、左窄栏、可拖动右栏、当前页否决/提交均可操作。
- 一条 Evidence/Event 接入后，政策/信审/商务/资产必须共享同一 `contextVersion` 并各自产生候选处理结果；同键重放不重复，同键异载荷冲突，失败不推进版本。
- Evidence、事实确认、具名决定和候选问答追加的 Authority Event 必须有序、可分页、可回看；幂等重放不重复追加，事件数与 Projection 审计计数一致。
- 四板块准备进度可并行不同；每个板块内部必须保持 `completed* → active? → locked*` 的唯一顺序，板块进度只能是 20 的整数倍。
- 顶部/主体采用贯穿的 `104px | 中央 | 拖动线 | 右侧` 网格；全域图谱可缩放、平移、拖节点、适应画布和聚焦当前，布局变化不改变后端业务关系。
- 切换四板块时中间内容、矩阵、图谱、右侧 Context Packet 与动作必须真实变化。
- Chat 从浏览器到后端完整连通；本地 stub 与 live model 状态可区分；live 模式仅在独立产品凭据存在时验收。
- Human Gate 否决/提交具有后端 Receipt，未知/失败不能显示成功。
- 单测、lint、build、HTTP 并发与错误路径通过；1920×1080 浏览器截图、控制台和关键交互通过。
- 本轮只做本地 V2，不部署；Git 提交或推送仅在用户明确授权后执行。
