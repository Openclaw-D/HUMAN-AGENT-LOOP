先建立可以与 3311 共存的验证环境。允许在本批执行目录下建立非 Git 临时运行副本：仅复制当前演示所需源码和明确配置，复用已安装依赖；拥有独立构建输出、数据目录和经检查未占用的回环端口。记录复制清单和源码哈希，保证验证的是当前交付源码。禁止复制凭据、真实数据、受保护历史；禁止替换核心技术栈或为避锁修改生产配置。

3311 仅可 GET 和查看；禁止 POST、seed、故障注入、重启或清空其存储。测试进程仅清理本批自己创建且核实 PID/端口的进程。若现有依赖无法实现隔离，交回精确阻塞及需要的最小选择，不停止现场服务。

## 检查点二：交互可靠性修复

1. 所有状态入口统一防回退：首次加载、轮询、焦点恢复、冲突刷新、写入重放、情景切换。旧 GET 晚到不得覆盖较新状态；相同版本不制造重复效果；失败仍保留可用画面和草稿。
2. 消息和说明都保留完整未知结果请求，提供可到达的“确认结果/原样重试”路径。待办转待复核不能让未确认请求消失。重放成功只确认对应请求，不覆盖更高版本，不误清用户随后修改的草稿。已确认的待复核待办不应开放新的普通补充提交。
3. 明确切换情景期间在途请求和草稿的处理：不能把旧说明悄悄提交给新待办，不能让旧响应复活已结束情景。沿用全局单调版本。重置前明确说明影响并提供取消；取消不发写入，确认才切换。不得把普通业务行为变成审批动作。
4. 复核提示按实际相关域显示；审批情景归信审，起租后巡检归资产。摘要、域灯、待办、消息一致，补充说明不自动变绿。
5. 错误统一显示简洁中文，含无法连接、冲突、无开放待办、无权操作、数据不可用等。不得向业务页面透传内部字段、原始堆栈或系统路径。内部错误码和日志仍可供测试，不破坏协议。

每个缺陷添加真实行为回归，不仅是搜索源码中是否有某个函数。保留原先通过的并发、幂等与失败关闭规则。

保留四域横条结构、顺序和黑白灰语义灯，只做紧凑收口。以 390×844 为主要验收视口，默认全部段名收起时，当前待办标题及“补充说明”入口完整进入首屏；通过缩减重复说明和合理间距实现，不能靠缩小到难读文字、改变浏览器缩放或截图裁切达标。若这要求显著重排页面，先交首个视觉预览停下反馈。
