# Goal MAIN｜把手机总览与访谈做成一个真正可用的闭环
先读 ZCODE_R3_GOALS_20260913.md 和独立复验报告。你是唯一产品writer；不要回头扩通用平台。
## Objective
修正R2长页面，交付普通小屏一屏总览、可聚焦访谈，以及A/B候选进入产品后的端到端证据。
## 工作顺序
1. 冻结当前恢复快照与写面。收敛总览：紧凑项目头、一行预审/尽调/签约/租后、政策信审商务资产四行各四点（接收/处理/协同/核验）、剩余空间聊天和输入、视频入口。删除重复大进度条/大卡片占位，将调试信息收进非默认区域，保留必要模拟说明。
2. 默认普通字号下一屏无需页面滚动，聊天内部滚动；详情原页聚焦，顶部右侧展开/收缩。不要禁用系统无障碍缩放。草稿、选中项、阅读位置往返保持；软键盘实际测不到需单列。
3. 访谈默认进入竖屏全屏布局，不再先堆表单。顶部少量文字提示、中间画面、底部可回看字幕，左本机翻转、中挂断、右本机拍照。长内容内部滚动，挂断不能被挤出可视区；无真实媒体时保持诚实未配置。内部提示不泄露给客户，Agent不发声。
4. 与A冻结接入映射：产品generation维持当前非负语义，优先适配边界+1并在请求/快照一致转换，不破坏持久化；contextVersion从同一权威读取获得。先核对现有接口，不盲目复制第二套状态机。
5. 按B版本化契约接入新控制器或提供等价修复证据，淘汰旧行为而非同时留两个不一致执行路径。相机失败可选图，取消/挂断/离页资源正确释放。
6. 用C场景跑总览→访谈→文字提示→草稿纠偏→人工确认→挂断→聊天待办；变更时间线来自真实应用事件，不伪造后台思考。datetime24h/人/现有level/变化/影响；level未知不发明权限。
## DoD
- 三种精确CSS viewport下，正常字号document纵向溢出≤1px，横向≤1px；长聊天与长字幕不改变外框。若无精确控制能力，明确阻塞，不报达标。
- 每主要板块展开/收缩连续20次，无草稿、选择、位置丢失；键盘与无障碍另外分项记录。
- 合成端到端至少覆盖：正常提交、未知结果同ID恢复、暂停迟到响应、证据更新失效、挂断后待办保留、两会话隔离、重要分歧并存、相机取消释放。用服务端状态和UI共同证明。
- R2 108项保留或解释合法迁移；typecheck/lint/build与独立隔离HTTP检查，失败不得写PASS。
## Evidence / stop
每checkpoint截图必须带测量JSON及操作步骤，至少总览/长聊天/全屏长字幕/聚焦恢复。交INTEGRATION_RECEIPTS列A/B输入hash、产品落点、C回放结果。阻塞某模块时继续无依赖布局；重大授权缺失停该项，不擅自绕过。
