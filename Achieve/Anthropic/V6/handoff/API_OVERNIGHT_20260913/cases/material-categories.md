## 二、客户上传的后续输入约定（仅整理，本轮不建页面）

按 DECISIONS 既有要求 + 产品现有 supersede 机制（`evidence/supersede` 路由：原件不可覆盖、`supersedes/supersededBy` 链）对齐：

1. **逐次存档、不可覆盖**：每次提交生成新记录（新 materialId 或新 version），旧版保留；更正以"新版本取代旧版本"表达，永不改写原件。
2. **每次提交必带字段**：`sourceId`、`version`、`submittedAt`、`sourceType`（沿用第 4 项五类）、`sha256`、`status:'claimed'`；未人工核实前一律 `claimed`，禁止上传方自标 `verified`。
3. **失败关闭**：缺 `sourceId/version/sha256` 的提交应被拒绝而不是猜测补齐；重复提交（同 sourceId+version+sha256）幂等返回已有记录。
4. **与五大类目映射**：上传入口的类目选项直接复用第一节第 2 项的五大类目及子类，避免第二套分类法。
5. **边界**：本约定不包含 OCR/识别、自动归类或真实性判断；预处理类能力须独立边界与验收（CONTEXT_LOG 2026-09-12 条目限定）。
