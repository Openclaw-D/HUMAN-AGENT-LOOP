# F1/F2 真实浏览器可重复验证步骤

自动化能力（node:test）只能执行纯函数与源码断言；真实组件行为以下列可重复浏览器步骤补齐（ZCode IAB 已实测通过，Codex 可用任意浏览器 + CDP fetch 包装复验；不自称自动化等价）。

## 前置

- 打开被测页面（3399 生产 `http://localhost:3399/v5-preview` 或 3321 dev）；F12 Console 可用。
- （可选注入）Console 安装回执控制包装：`window.__origFetch = window.fetch.bind(window)`，随后按需 `window.fetch = async (i, n) => { const r = await window.__origFetch(i, n); if (new URL(i, location).pathname === '/api/v5-preview/messages') throw new TypeError('injected'); return r; }` ——服务端真实落账、页面侧丢回执。发送前失败变体：调用 origFetch 之前直接 throw。
- 每条用例前：`sessionStorage.clear()` + 演示情景切到"审批推进中"（经页面确认卡）并刷新。

## F1-A（消息通道）

1. 展开"项目沟通"，输入 `A内容（合成）` → 发送。注入丢回执：页面显示发送失败、出现恢复行。
2. 输入改为 `B内容（合成）` → 点击发送：应提示"已有一条项目沟通消息尚未确认结果……本次未发送；内容已保留"，Network 面板 **无新增 POST**。
3. 点击恢复行"确认消息结果"：Network 面板出现 **恰好 1 次** POST /messages（载荷 = A 的原始 requestId/expectedVersion/text，幂等重放），消息条数不增加。
4. 断言：**输入框仍为 B 原文**；旧错误提示已消失；恢复行消失；sessionStorage 无 `jw:v5-preview:pending-message-request`。
   - 修复前行为（red）：第 4 步输入框为空（B 被清空）且旧错误残留。

## F1-B（说明通道）

1. 待办卡"补充说明"展开，输入 `A内容（合成）` → 提交说明，注入**发送前失败**（表单保持打开、恢复行出现）。
2. 输入改为 `B内容（合成）` → 提交：提示"已有一条补充说明尚未确认结果……本次未发送；草稿已保留"，无新增 POST。
3. 点击"确认说明结果"：恰好 1 次 POST /notes（A 原载荷，此刻首送成功）→ 待办转待复核、表单卸载（既定语义）。
4. 切换情景到"起租后资产管理"（确认卡确认）→ 待办卡"补充说明"重新展开。
5. 断言：**表单内容 = B 原文**（草稿未被确认 A 的动作清空）。
   - 修复前行为（red）：第 5 步表单为空。

## F2-A（情景门比对当前上下文）

1. 审批情景：发送消息 X，注入丢回执（形成未知记录，服务端已落账）。
2. 经确认卡切换到"起租后资产管理"（恢复记录作废）。
3. 断言：切换后无恢复行；随后任一 GET/轮询下页面情景保持"起租后"；无"确认…未完成"之类陈旧提示（X 的回执若在此期间晚到，应被情景上下文门拒绝且静默）。

## F2-B（回执副作用先判所有权）

1. 制造说明未知记录（发送前失败）→ 展开输入 B。
2. 提交 B → 阻断提示出现（无 POST）。
3. 确认说明结果（A 幂等/首送成功）。
4. 断言：B 保留 **且** 旧阻断提示消失（不得出现"内容已保留"与空输入/新草稿并存）。

## M-GET（真正旧 GET 晚到）

1. Console 安装：捕获下一个 GET /project 的响应并扣住（`const res = await orig(...); await gate; return res;`）。
2. 等轮询被扣住后，从页面发送一条消息（正常到达，版本 +1，DOM 更新）。
3. 释放被扣住的旧 GET。
4. 断言：DOM 版本/消息数保持写入后的值，不回退。

## M-DBL（双击确认）

1. 制造消息未知记录；双击"确认消息结果"。
2. 断言：Network 面板最多 1 次非重放 POST（第二次同载荷请求为幂等重放或被禁用态拦截），消息条数不变，恢复行消失。
