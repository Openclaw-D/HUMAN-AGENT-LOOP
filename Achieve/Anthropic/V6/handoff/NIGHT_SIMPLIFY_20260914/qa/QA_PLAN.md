# D路 QA_PLAN（NIGHT_SIMPLIFY_20260914）

## 定位

独立验收"前端简化+固定演示"的实际可用性与状态可靠性。旧 API 通过结果（`../API_OVERNIGHT_20260913/qa/`）只作回归基线与适用范围参照，**不替代本轮新产品验收**。

## 约定

1. **判据来源**：A 的 CONTRACT（数据形状/会话约定/刷新约定）+ C 的状态图（人工节点/分支语义）+ 公共契约产品目标。A/C 未落盘前，按源码现状与 RESTART_HANDOFF 的已接受基线（五阶段/四域/50-50/入口）审。
2. **前置门**：A 声明可测试 + 给出 D 专属合成会话与数据写窗口之前，只做源码/脚本审查与测试准备；不写共享数据。
3. **五类重点风险**（任务书指定）：越过人工节点、过时证据、错误全绿、重置污染、固定/真实混用。
4. **工具**：复用旧路 `regress_api.py`（URL 可配置）思路改写为本轮固定演示回归；UI 用既有独立浏览器测试上下文（不动用户当前浏览器 viewport/zoom/标签页）。mock 只用于断言边界；真实页面测试不得用 mock 冒充。
5. **不建立新大型 harness**：每阶段少量高判别力路径，有新改动再复跑。

## 数据纪律

- 测试脚本先自审数据作用域：只触 A 划定的专属会话；不碰共享演示首会话；"重新开始"只允许在专属会话内验证。
- 每个真实测试命令与结果记录到 `RESULTS_LOG.md`，不复制旧测试计数。
- 无法在线验证的项（真实 provider）如实列"未测"，不算固定演示阻断。
