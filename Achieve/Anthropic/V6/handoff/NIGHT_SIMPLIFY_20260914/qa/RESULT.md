## 退回循环残留项的独立结论（理由充分版，不因 A 接受即视为正确）

**结论：现行"退回仅一次"为正确收口。理由：**
1. **与机制版一致**：C 机制版在图内编码"退回仅一次"（DD-07B 无 return 选项，decide(return) 返回 INVALID_DECISION），是状态机语义的权威表达；wave-2 删除 s12/s17 return 后，产品行为与之一致（本轮 UI 实测：s12 仅确认/纠正两按钮）。
2. **流程正当性**：退回的业务含义是"材料不足以支撑判断，退回补充后必须再判断"。补充后的再判断节点若再提供退回，等于允许对同一疑点无限延期而不收敛，与核心闭环"判断更新后继续"矛盾；有限路径（确认挂账闭环清单/纠正更正作废旧意见）才是判断的合法终态。
3. **防错误全绿不受影响**：退回窗口内四域如实显示"退回补充状态，尚未通过；对应阶段不显示为完成"（UI 截图）；结清终态必须经确认/纠正到达（HTTP N-S12 实测 settled+四域全完成）。
4. **可逆性兜底仍在**：误操作有「重新开始」（仅重置主线，实测 remote-store 不变）；每圈循环需两次显式人工动作，不存在自动滑入。
5. **未来若需多次退回**（真实业务存在该可能）：正确做法是把再判断节点做成独立步（不同签名+独立文案），而非恢复同节点循环——C 的 a-shape 差异清单 §3.1 已给出该方向。
