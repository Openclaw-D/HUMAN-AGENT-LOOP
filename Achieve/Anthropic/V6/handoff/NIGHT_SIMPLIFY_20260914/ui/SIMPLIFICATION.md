前提：首页 50/50、五阶段、四域矩阵、单一入口链接**全部保留，不重做**。以下建议的目标文件均为 A 的写面；B 在 `candidate/` 提供可复制实现。

## 一、最重要五项保留/合并/折叠建议

### 1.【保留】路由与三态骨架不动
- 内容：`/v5-preview` → ChatPanel 工具行 Link（`chat-panel.tsx:154`）→ `/v5-preview/remote-session` → 头部返回 Link。loading/error/empty/ready 四态与中文文案保留。
- 用户影响：无（行为不变）。风险：最低；这是已验证的来回路径。

### 2.【提升+合并】视频/模拟画面升为页内主体，砍掉"三步全屏"链路
- 现状：画面位藏在 语音按钮 → voice 区 → "进入全屏访谈"（`page.tsx:528-530`）；模拟开关（`:516-519`）勾选后页内无可见变化。
- 建议：把全屏覆盖层的画面位（`:844-847`）提为页内常驻"现场画面区"（模拟态默认、含当前问题条与模拟徽章）；全屏仅保留为放大按钮。模拟开关直接作用于画面区。
- 精确文件：`remote-session/page.tsx`（删 `:832-886` 覆盖层主体 → 迁入 `sivScroll` 顶部新区块）、`se-interview.module.css`（新增 stage 区样式，候选已给出）。
- 用户影响：进入页面即见"现场"主体，符合"业务端视频为主"。风险：与产品"不穿过大面积假画面"底线冲突的化解 —— 默认态仍是**诚实标注的模拟/未接入位**（非真实画面），与现有覆盖层同语义，只是不再深藏。

### 3.【合并】两处"挂断"、两处"拍照"统一为单一语义
- 现状：全屏"挂断"=只关覆盖层（`page.tsx:872`）；CameraPanel"挂断并释放全部"=停轨撤URL（`camera-panel.tsx:392`）。全屏"拍照"（`:876-883`）点了却要退出全屏去证据面板操作。
- 建议：画面区控制条统一为：`放大`、`模拟画面开关`、`拍照/选图`（直接挂 CameraPanel 的既有入口，不新增拍照实现）；"挂断"字样仅保留在 CameraPanel 原位（真正释放资源处）。
- 用户影响：消除同名异义按钮；演示中模拟场景不触碰摄像头。风险：低（不新增设备调用路径）。

### 4.【折叠】内部技术/演示配置收敛为一个次级区
- 现状：泄漏见 UI_INVENTORY §4；`preview.module.css` 637 行死代码。
- 建议：业务按钮 title 只留业务语义（"真实模型辅助分析"成败文案保留中文用户话术）；`JIANWEI_MODEL_MODE`/session 切片/provider/预算/CONTRACT 字样/控制器版本号全部收进唯一"演示与技术"抽屉（现有 `:640-676` 的超集，或并入 A 的演示控制二级区）。死代码 `preview.module.css` 由 A 删除。
- 用户影响：业务面干净；演示诚实声明仍在（页脚合成声明 + 抽屉）。风险：无功能损失。

### 5.【合并】恢复条与反馈行组件化，消灭双实现
- 现状：PendingBar 在 empty（`:438-444`）与 ready（`:467-477`）两分支重复；paused/notice/writeError 三类反馈混排在 dock（`:822-828`）。
- 建议：抽 `PendingBar`、`FeedbackLine` 两个小组件（候选已实现），页内单一渲染点。
- 用户影响：一致的重试/反馈体验。风险：低。

（附带建议，非前五：CameraPanel 在演示路线默认折叠、保留"检测能力"入口；`preview.module.css` 删除前先在本路记录 hash，见 RESULT.md。）

## 二、CP2 目标布局

### 桌面（≥900px）— 侧栏式
```
┌────────────────────────────────────────────────────────────┐
│ ← 返回项目 │ ●进行中 │ 远程尽调 · <项目号> │ [人工待处理 n] │ 演示与技术 │  48px
├───────────────────────────────────────────┬────────────────┤
│ 现场画面区（16:9，页内主体）                  │ 四域风险提示     │
│  [模拟画面 · 非真实画面] 徽章                │  政策 ▏条目≤2   │
│  合成头像位 / 模拟会议视图                    │  信审 ▏…       │
│  底部浮层：当前关键问题（一行省略+展开）        │  商务 ▏…       │
│  控制条：模拟开关 · 放大 · 拍照/选图            │  资产 ▏…       │
├───────────────────────────────────────────┴────────────────┤
│ 记录层（折叠 tabs：证据与拍照 ▏历史问答/转写）— 复用现有 details 风格 │
├────────────────────────────────────────────────────────────┤
│ 内部交流（半开：最近 3 条 + 输入行；完整列表进记录层）             │
├────────────────────────────────────────────────────────────┤
│ 操作坞：访谈记录输入 + 关键字段核对 + [提交访谈记录][暂停][转人工]  │
│ 反馈行：未知请求恢复条 ▸ 成功通知 ▸ 错误（单行轮换，aria 各自保留）  │
└────────────────────────────────────────────────────────────┘
```

### 手机（375×667）— 紧凑单列
- 顶部 48px 不变；画面区 16:9 固定（≈211px 高），问题浮层可两行。
- 四域提示：画面区下方紧凑横向四 chip（点击展开该域条目，手风琴）；不让核心视频被挤没。
- 记录层/内部交流：默认折叠为两行摘要行；操作坞常驻底部（≥44px hit area，沿用现有规范）。
- 溢出策略：面板内部滚动（沿用 `sivScroll` 模式），页面不整页滚动。

### 层级原则
1. 现场画面 + 当前问题（第一层）2. 四域风险提示（第二层，桌面右栏/手机 chip）3. 证据与记录（第三层，折叠）4. 内部交流（第四层，半开）5. 演示与技术（抽屉，最深）。
