## 重要声明（先读）

1. **全部案例均为匿名合成**：企业、人物、设备、编号、金额、银行、事务所均为虚构，不影射任何真实公司或个人。
2. **不声称用户已提供三套资料**：三个案例是未来用户真实授权资料的**替代测试材料**，用于在真实数据接入前验证模型接入与评估工具。
3. **案例不预设正式审批结果**：任何 golden 中都没有"应批准/应否决"预期；数字只用于一致性测试，不是公司政策阈值。
4. **golden/ 不得作为提示发给模型**（见 README 使用流程）。

| 案例 | 合成企业 | 行业 | 拟议标的（未审批） | 设计特征 |
| --- | --- | --- | --- | --- |
| CASE-A | 辰力精密传动（虚构） | 通用设备零部件 | 设备融资租赁，680万/36期（一致性测试用数字） | **资料相对一致**：清单/发票/铭牌编号互相对应；保留4项常规缺口与专业侧重差异 |
| CASE-B | 禾丰农装（虚构） | 农业机械 | 设备融资租赁，420万/36期 | **资料有可澄清缺口**：7项缺口（受让权属、流水期间、未审计、清单外设备、现场状态、经济性口径、作价对不上），全部可补证 |
| CASE-C | 恒砥模具（虚构） | 注塑模具 | 设备融资租赁，950万/48期 | **资料有关键矛盾**：铭牌年份 vs 发票（2019/2022）、编号 2216R vs 2216、扩产说法 vs 原值持平；含 v1/v2 版本替代链 |

每案例按阶段组织（stage S1–S5）：首次沟通纪要 → 书面材料摘录 → 现场画面（文字描述+自制测试图形 SVG）→ 现场问答 → 补充材料。每条事实带：

- `sourceId` + `version`（如 `C-DOC-02` v2）；
- `sourceType`（meeting_minutes / written_document / onsite_visual / onsite_qa / supplement）；
- `status`：**claimed**（客户声称）/ **recorded**（书面材料所载）/ **observed**（现场画面观察，带 observationScope）/ **verified**（已核实，仅营业执照示例一处，标注"仅在本合成案例内成立"）；
- 观察规则写入每个案例 meta：**未观察到 ≠ 不存在**。

现场画面均为"远程会议中客户设备端拍摄的照片的**文字描述** + 自制测试图形（SVG，带显著'合成测试证据'标记）"。案例 C 的关键矛盾均可从文字描述中读出，纯文本模型可测；SVG 供未来多模态运行复用。

## 变体（inputs/variants/，一个变体 ↔ 一个评估问题）

| 变体 | 基础案例 | 类别 | 评估问题（golden 同步收录） |
| --- | --- | --- | --- |
| VAR-1 | CASE-B | 缺核心文件 | 候选是否把权属凭证**整体**缺失识别为核心缺口，并在补齐前不作倾向性推进？ |
| VAR-2 | CASE-A | 同源材料重复 | 候选是否识别三份同源流水，不计为独立佐证、不因份数降低风险评价？ |
| VAR-3 | CASE-B | 时间/设备编号矛盾 | 候选是否发现编号 0702/0207 对不上与年份 2019/2020 张力，双侧绑定证据？ |
| VAR-4 | CASE-C | 过期资料被新资料替代 | 候选是否以 v2 为准、识别客户说明函引用过期口径（14,183 vs 13,331）？ |
| VAR-5 | CASE-B | 不同专业意见 | 候选是否保留政策岗/信审岗分歧、指出共同未核实前提，不替任一方裁决？ |
| VAR-6 | CASE-B | 经济性口径缺失 | 候选是否声明核算无法完成并逐项列缺失口径，不填默认值、不建议降价？ |

变体是基础案例的**确定性派生**（`mutations: removeSource/addSource`），由评估 CLI 在运行时合成，不复制整包；每个变体的 purpose/derivationNote 说明其与基础案例及彼此的区别（非同义堆凑）。

## 评估端文件（golden/，不给模型）

`golden/case-{a,b,c}.golden.json` + `golden/VAR-{1..6}.golden.json`，schema `jw-eval-golden@1`，包含：requiredGaps / expectedContradictions / acceptableFollowUps / forbiddenConclusions（含 advisory 别名）/ currentVersions（版本替代关系）/ evaluationQuestion。

## 与主任务/A lane 的衔接

- 候选结果格式冻结为 `jw-eval-candidate@1`（字段见 README）；A lane 适配器输出经主任务映射为本格式即可直接评分，**不要求 A 修改其接口**。
- 真实模型未接入前，`candidate-responses/independent/`（人工撰写的独立参考答案）与 `controls/`（6 个负控制）用于验证评估工具本身；对它们的评分**只证明工具能工作，不证明任何模型能力**。
- 本轮真实模型调用数 = 0；未使用任何密钥或客户数据。

## 已知边界

- golden 的 matchKeys 是**预登记别名**，覆盖率是下界：同义词漏配=假阴性、别名歧义=假阳性，最终语义判断必须人工复核（见 METRIC_DEFINITIONS.md）。
- 案例中的金额/期限是"经济性口径讨论"的素材，不是定价公式输入；核算在本项目始终 `not_configured`。
- 会议/视频均为合成设定；演示时必须显著标注（见 DEMO_SCRIPT.md）。
