# V6远程尽调｜本轮产品更新

日期：2026-09-12。来源：用户语音澄清及随后明确要求整理ZCode更新包。当前阶段仍为V6-CTRL；本文区分已明确方向、本轮实现范围和未冻结探索，不代表生产授权。

## 1. 方向与替代关系

原“业务侧单项目进度看板”扩展为“业务主导、专业人员与模型协作的远程尽调”；已有四域概览、资料版本、草稿和回执保护继续复用。远程的是我方协作方式，不是客户可以脱离现场：实控人须在经营现场，财务、生产负责人及必要管理层在现场或至少实时参会。入会或自称到场不等于身份/场所真实性已核验。

实时会议是产品方向的一部分，替代早前仅异步看板、视频可有可无的表述；本次工程增量先预留视频入口、独立会议视图和接入协议，不要求同时完成视频传输、持续多模态和三维重建。一套响应式Web适配mobile/desktop，不维护两套客户端。六角色指见微、业务、政策、信审、商务、资产六个逻辑Agent，不等于六位参会人、六把密钥或六套服务。

允许探索重构既有工作流程，不把“不改旧流程”作为创新上限；并不因此取得改变公司实际制度、正式审批或部署真实尽调服务的权限。风险不能被速度交换。模型authority=none，人可以质疑、要求补证、停止和确认；不由单个人为所有人兜底，不建设责任分摊算法。

## 2. 人工监督与阈值

“有人监视”和“设预值”转为以下可验收要求，不只放一个人工确认按钮：

- 观察面：原始来源、模型提取值、引用、缺口/矛盾、当前资料版本、谁已复核。模型提取值和客户陈述不自动成为已核实事实。
- 人工动作：确认可见内容、纠正、要求重拍/补充、暂停本轮；记录具体证据和意见。确认仅针对该证据版本，新的资料或争议使旧确认过期。
- 条件分层：技术质量（例如图像是否可读）、证据充分性、业务风险、经济性分别配置，不共用一个“可信分”。模型自报置信度不得单独驱动放行。
- 用户尚未明确数值、比较方法、适用范围、触发动作、配置owner及启用条件；首轮全部未配置，不创造“80分通过”等默认标准。CP0列出待确认项；合成测试参数与业务配置隔离。
- 未配置、关键证据缺失、矛盾未闭合或结果过期时，显示待核实/待配置，不产生可执行的授信、期限或价格建议。缺口可继续收集，不把暂停某次判断误作终止全部沟通。

人工参与不保证AI正确；页面须让人能看证据、反驳和停止，不能诱导机械勾选。系统是记录和分析工具，不是因独立截图就成为独立事实来源。

## 3. 风险定价与收益底线

用户诉求：看得更清楚后，才有条件评估更合适的期限、额度、价格；必须核算，不为追求成交硬做预计负收益交易。

正确关系为：**材料质量与核验 → 对风险的认识更新 → 交易条件方案 → 风险与经济性核算 → 人复核**。资料数量不是优惠积分：材料增加也可能暴露更高风险；同样信息来源重复十次不算十份独立证据；加长期间或提高额度本身会改变风险和成本，必须重算，不能同时自动“更长、更高、更便宜”。

当前只定义核算边界与输入/输出接口，不编造公司资金成本、损失率、资本要求、最低收益率或审批标准：

- 待明确输入包括期限、金额、报价口径、付款/还款计划、资金成本、预期信用损失、运营及必要核验成本、资本占用成本与其他适用费用；每项需要来源、单位、期间、有效版本，标明假设。
- 收益究竟采用何种指标、是否折现、是否税前/税后、风险成本及资本成本如何避免重复计入，须由用户/业务owner确认。不把会计利润、现金流、IRR或风险调整收益混成同一个数字。
- 数值计算归经测试的确定性程序，不让LLM临时生成公式或补造缺失成本。模型可解释依据和提出疑点，但不决定经济性门槛。
- 暂未明确公式或关键输入时返回“核算未完成”，不显示绿色盈利、不用0填缺失值、不自动建议降价。
- 经确认口径核算的负收益方案，不推荐执行；正收益也不自动表示风险可接受。未达到经确认的门槛或关键风险仍未解决时，仍不能放行。预测并不能保证实际不亏损。
- 方案变更、资料更新、参数更新均使原核算及人工确认失效。风险结论、经济性结果、正式决定分别呈现。

作为设计参考，EBA的贷款发起与监控材料把定价与风险、盈利及成本相联系；本项目不将其当作中国租赁公司的适用制度或自动采用其指标。本轮检索到官方最终稿摘要，全文抓取受限，未作法律合规结论。[官方入口](https://eba.europa.eu/activities/single-rulebook/regulatory-activities/credit-risk/guidelines-loan-origination-and-monitoring)

## 4. 视频与现场证据空间

会议页面至少表达：项目/会话归属、实时接入状态、参会人与职责、实控人现场状态（声明/待核验/已按本轮依据确认分开）、关键问题、证据与人工复核。权限受后端约束；“专业角色视图”不等于真实登录鉴权。

视频提供流畅交流；关键数字由客户设备端清晰照片辅助，不拿接收端低清截图冒充原相机照片，不以AI补字当证据。不同手机、浏览器、焦距与网络效果需要实测，不能无条件保证清晰。

获授权角色可截图/请求取证、圈选、打问号。每条疑问绑定不可变原始证据、位置、项目/会话、采集时间与来源、资料版本；圈注和识别结果作为派生记录，不覆盖原件。截图摘要/hash有助于发现存储变化，不证明拍摄时内容真实。

系统定期采集与三维现场为后续探索保留：必须先明确采集告知与权限、频率/容量/保存边界，不能在页面打开后自动摄录。三维重建需要多视角覆盖，未知区域保留未知；模型不得生成缺失现场作为证据。Blender是可能的后处理工具，不是已选定自动重建引擎。

## 5. 这次做什么、暂不做什么

本次向ZCode交付更新包：先保全现有交付和冻结接口/写面，之后做响应式会议入口/页面骨架、视频adapter契约、合成证据标疑与复核状态、风险/经济性待配置状态。模型和视频未接时准确显示未接入，不能伪装成功。

不在本包一次性实现：自建完整会议服务、自动拨打/录音、持续音视频识别、自动定期拍摄、真实客户资料上传、三维重建、完整定价引擎、生产账户/权限平台、正式授信或报价。它们分别保留在后续范围中，不被当成不存在，也不借入口预留暗中实施。

首次联系/电话纪要/制式材料预处理保留场景候选，不能假定已存在导入/OCR/录音能力。六分钟演示为同三例先传统后远程，总长六分钟；传统流程表现须来源于明确案例，不编造实测节省，录制和模拟标清，三类预期标签不得泄露给模型。

实施任务唯一入口：[ZCode更新包](ZCODE_REMOTE_DD_UPDATE.md)。Dify仍是优先验证组合之一，性能接近时考虑团队现有经验；新视频需求不意味着Dify负责媒体传输或必须重写全部后端。
