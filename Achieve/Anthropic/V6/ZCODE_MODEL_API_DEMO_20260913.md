# ZCode：真实模型API最小演示接通

## 目标
前端停止扩展。沿用V6-Front当前工程，由一个writer串行接通：已有合成访谈证据/问题 → 服务端调用一个真实模型，以信审角色给出追问/依据 → 页面显示 → 人工补充或纠正后重新分析 → 保存并刷新读回。复用现有代码，不重建后端、通用编排或新平台。建议60–90分钟有界交付，资源缺失时交可配置实现和明确缺项，不循环等待。

其他三域保留现有内容，不强制每次四路模型调用；50/20/15/15是产品重心，不是token分配公式。普通项目聊天本轮保留人工沟通，不顺带自动接模型。客户上传、企微、录音转写、视频接入均留后续，不能一起开发。

## 已核对的现状
- lib/v5-preview/service.ts的postMessage仅追加人工消息。
- remote-service.ts的simulateFollowUps调用createBridgedModelAdapter()，默认createSimulatedTransport，结果标为model_simulation。
- model-adapter/providers/http-json.mjs已有请求/响应映射，但没有实际HTTP调用；它的JSON模式、metadata等参数不能假定所选provider全部兼容。
- bridge支持传入transport，但新请求的真实内容、requestId、证据版本及结果返回后状态需实际接线；不能只换环境变量便宣布接通。

## 先核清配置，再完成接线
只使用用户明确配置的产品模型服务。只报告配置是否存在，不打印密钥、不扫描历史/其他软件凭据、不复用coding账号。产品密钥沿用JIANWEI_MODEL_API_KEY；端点、模型名、real/simulation模式使用明确的服务端配置并写无秘密示例。不能使用NEXT_PUBLIC前缀保存秘密。

有明确已配置provider时，核对其官方接口文档，仅实现这一种。若尚无服务选择，复用现有HTTP兼容映射做一个可配置transport候选；缺端点/模型/密钥时返回未配置，列出这三项供用户一次补齐，不伪装真实测试通过。不要同时实现Dify和多家provider，不安装新SDK。

真实请求只发合成数据。只有用户确认服务、模型和可用产品凭据后才发送；已有总预算每批50万tokens是上限，本轮先1次探针，再最多3次闭环调用，失败不自动消耗式重试。记录实际usage，不以耗完预算为目标。

## 最小实现边界
1. 用现有运行时fetch补服务端transport，配置校验、明确超时/取消、HTTP失败与JSON解析失败反馈。端点仅由服务端配置，浏览器不能任意指定URL。不得输出Authorization或原始敏感错误体。
2. 保留模拟入口的原含义；新增一个明确“模型辅助分析”的真实入口/API，不把真实调用偷塞进simulate命名路径。尽量共享原有逻辑，避免复制整套服务。未配置时按钮/结果清楚标未配置。
3. 初期只请求信审。实际证据正文/客户陈述必须进入请求，仅发送hash不能让模型理解材料。正文只用当前合成项目内已提供内容；回复只能引用提供的证据。无需复杂评分或定价，模型只给疑点和建议追问，不做正式审批。
4. 响应须标真实模型来源、角色、证据版本；模拟和真实可区分。不要把model_simulation改成真实显示文字但仍保存错误类型。必要时给类型增加兼容分支，旧记录可读、无需迁移或重置。
5. 人工补充/纠正复用已有记录路径，保留原意见；新一次分析读到新内容，标明所依据版本。不重做文档版本平台。
6. 接口复用已有requestId和版本控制。同请求重复提交不得重复追加；请求进行中防重复调用。模型等待期间不能拿旧state覆盖最新存储：返回后重新读状态，核验会话暂停/证据版本/请求归属，过期结果不当作当前有效结论。仅修这条真实路径所需部分，不扩成全面R4重构。
7. real失败返回明确失败或未知，绝不静默回退模拟冒充成功；可让用户另选现有模拟入口。单角色不需要新增四角色聚合器。

## Ownership与保全
执行前确认前端writer已交回。一个writer，不新增sub-agent。修改前保存本轮拟改文件SHA256快照与diff到V6/handoff/MODEL_API_DEMO_20260913/baseline；本轮是既有接口的有界接入，不做大版本迁移。Git提交/标签/worktree/新依赖仍不允许；若发现必须重大改版则停在精确缺口，不绕过baseline门。

允许写site下lib/v5-preview/model-adapter/**、remote-model-adapter-bridge.ts、remote-service.ts，以及必要的remote类型/存储兼容扩展；app/api/v5-preview下新增窄范围真实分析路由；app/v5-preview/remote-session/page.tsx仅入口、状态和结果呈现；必要的api-client调用函数。具体文件清单在开工记录中列明，不能顺带改普通聊天服务、总览布局、权限体系或其他版本。检查现有API路由风格再决定名称，报告确切方法和路径。

3467是本轮自有预览，允许在记录PID与配置变更、保存当前数据快照后，必要时为服务端环境变量做一次受控重启；保持同数据目录，不重新播种、不清空。3311/3321/3399保持只读。不得公网部署或建隧道。预览副本只同步白名单源文件，源/运行hash一致。

## 验收与交付
- typecheck、改动文件lint、针对真实调用路径的少量测试：未配置、正常响应、超时/无效响应、重复请求、等待期间证据更新或暂停。mock测试只证明接口逻辑，不能代替真实调用。
- 真实资源具备时，从实际页面用合成问题调用，看到真实回复，人工纠正后再次分析，刷新读回；核对旧结果不覆盖新资料。无需大规模压测或生产权限建设。
- 无配置时仍完成可测试代码，结果明确“接线已实现，真实调用未验证”，交唯一资源清单；不得宣称端到端完成。
- 最终只交RESULT.md、必要diff/快照与测试证据：实际API方法/路径、配置名和是否存在（不含秘密）、预览URL、source/runtime hash、真实调用次数/usage、通过/失败/未测、剩余一个下一步。不要堆大量状态文档。

Codex只独立复验，本任务由用户在ZCode中转交；文件存在不等于已启动或已获真实服务凭据。
