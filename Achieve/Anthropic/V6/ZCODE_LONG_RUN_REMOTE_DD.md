# ZCode长程任务｜V6远程尽调研究、实现与验证

日期：2026-09-12。状态：按用户最新要求生成，未代发、未启动。用户转交后由ZCode自身Harness执行。时间窗口约8–10小时；普通检查点不等待用户回复，安全/权限/重大baseline硬门不取消。不是要求使用长sleep、空转或消耗完额度。

## 0. 最新覆盖与开始方式

本任务替代ZCODE_REMOTE_DD_UPDATE.md中的“CP0仅交文档后强制等Control”“每个普通检查点均等人工接受”执行方式。前包的接口、安全与功能定义继续继承；本文明确增加有界持续实现、证据驱动纠偏和隔离探索。当前不是无限运行，也不是一次性重做所有业务系统。

开始先完整读：根AGENTS.md、DECISIONS.md、V6/CONTRACT.md、V6/REMOTE_DD_UPDATE.md、V6/ZCODE_REMOTE_DD_UPDATE.md及本文。冲突以最新用户指令和本文明确覆盖为准；不能把旧V4路径当当前主线，不通过Codex应用或隐式通道取指令。

用户关心的不是“Agent很多”或“跑满十小时”，而是：**在不牺牲风险识别、证据真实性与经济性底线的前提下，业务发起、专业人员与模型围绕同一现场/资料形成有效追问、补充和人工判断；维护一套mobile/desktop前端。**

风险不能被速度交换。资料更多可能发现风险变高，不自动换取更长期限、更高额度、更低价格。人工监督不是机械勾选或让某个人承担全部责任。模型无正式审批权，不发明规则/成本/资料，不让预计负收益方案因促成交易而放行。

## 1. 可观察目标：先正确，再提高效率

不编造一个综合“风险分”作为唯一优化指标。用下面的证据卡逐轮观察；硬门优先，不能用速度提升抵消正确性失败。

| 维度 | 本轮怎么测 | 不能伪称 |
| --- | --- | --- |
| 缺口/矛盾发现 | 合成案例含已标注事实、缺口、冲突；统计发现/漏报/误报，展示有效后续问题 | 三例通过等于真实金融准确率 |
| 证据可追溯 | 展示结论和问题可回到对应原件/版本；不存在的引用数为0作为当前用例门 | hash或截图证明现场真实 |
| 人工可控 | 人可纠正、补证、暂停；资料变化使旧确认过期；无模型自动批准路径 | 有人看着就绝不出错 |
| 状态可靠 | 重复提交不重复写、旧回执不污染新会话、刷新/重启恢复或明确未知 | 检查点自动保证外部付费调用恰好一次 |
| 风险/经济性边界 | 缺阈值/公式/成本不得给可执行优惠；负收益fixture阻断推荐，正收益不覆盖风险缺口 | 用fixture数字假冒实际核算 |
| 协作效率 | 同一案例记录重复提问数、澄清轮次、人工动作数和实测延迟，区分模型/媒体/后端开销 | 剪辑六分钟等于业务六分钟通过 |
| 可用和可接手 | 一套页面双端可操作；说明配置/运行/恢复步骤，记录依赖和资源 | 看板有角色文字就是真实多用户系统 |

每轮指标写实测值或NOT TESTED，不为没有定义的指标发明合格线。模型质量的expected结果只在评估端，不能连同“好/中/坏客户”标签送给模型。

## 2. 长程推进节奏

记录startedAt及计划结束时间。约8小时进入收口，最多10小时留下安全可恢复交付；提前达到下述DoD可结束，不为凑时长添加功能。无法持续到时限如Harness终止/额度不足，立即保全并如实说明，不能声称后台仍运行。

循环：**读当前契约与现场 → 选择一个当前目标 → 最小实现 → 运行测试和观察页面/数据 → 写证据 → 修正 → 下个目标**。每个循环建议控制在20–60分钟；时间仅工作节奏，不替代安全门。阶段预计顺序而非按小时硬摊任务：

### P0｜保全、复验与执行地图

- 读取rework-2报告和原始证据，运行相关聚焦回归核对F1/F2，不把执行者过去自报当当前全通过。
- 保存精确涉及文件的原样副本、diff/hash、分支/HEAD及非Git测试数据说明；已有删除/未跟踪文件均视为用户成果，不清理。
- 形成BASELINE.md、INTERFACE.md、OWNERSHIP.md、PLAN.md，明确一个writer和回归面，随后在可执行范围内继续，不因“计划已写完”停止。
- **重大改版Git baseline硬门仍在**：没有明确授权不得commit/tag/push/worktree。若需替换存储/框架、破坏性schema迁移、推翻现有主体或其他重大改版，暂停该写面，列精确baseline需求；可继续不依赖该变更的测试、接口验证和隔离实验。不许把文件快照说成已满足Git baseline，也不许以“增量”改名绕过重大改版Gate。
- 仅在确认为获准的小型可撤销增量、保持原格式/核心语义与依赖不变时，按下面写面推进；有关键分类冲突就写阻塞，不擅自宽解。

### P1｜远程尽调页面与接入骨架

- 保留原四域概览，加入远程尽调入口、会议视图及可返回项目的路径；一套Web，mobile/desktop仅布局差异。
- 表达项目/会话、参会角色、实控人现场要求、问题/证据区、模型与人工复核状态。实控人必须在经营现场，财务/生产等人现场或至少实时入会；状态自报与核实区分。
- 视频adapter未接入时如实说明；模拟单独开关与显著标签。没有配置不申请摄像头/麦克风、不定时采集、不上传。
- 首个可视结果就保存预览地址、截图和自查。用户未回复不阻断普通循环：先修明显布局/交互问题，再推进不依赖新视觉决定的后端；不擅自重构已认可整体视觉。

### P2｜合成证据—疑问—补充—人复核闭环

- 原始证据与派生圈注分离；问题绑定原图/来源/版本，补充与确认不覆盖原件。
- 合成图像圈选和标疑可用，手机缩放后坐标仍指向正确区域；有无图替代说明、输入校验及错误恢复。
- 持久状态沿用当前已接受机制，处理幂等、并发冲突、陈旧回执、页面离开与返回。真实身份未配置时不能开放未知用户跨项目访问。
- 实现阈值/核算的未配置、缺输入、待人工、过期/阻断状态；不实现没有确认口径的金融公式，不制造优惠值。

### P3｜六角色模型业务链路及adapter验证

- 六角色的职责、有限参与条件、输入输出与权限分开；规则和模型步骤结合，业务发起、见微辅助，保留专业分歧。
- 现有技术可用时优先复用。不需要六套服务，不构建通用Agent平台，不强迫六次轮转。
- 先用确定性stub验证协议/错误和状态，显著标记SIMULATION；随后只有拿到用户安全提供且用途确认的产品凭证、已就绪运行环境时，才验证一条真实模型链路。
- Dify配置/管理员归Codex且前序尚未完成，不能自己接管其写面或取旧凭证。缺接入时，写READY_FOR_INTEGRATION和精确接口/DSL草案，在隔离目录继续协议与失败路径验证，不能假装真实模型已调用，也不放弃其他可推进任务。
- 比较两种方案最多：Dify适配与一个薄代码候选，围绕同一用例/指标，后者仅隔离实验。依赖未安装时只做源码/协议层验证，不为探索私自装新框架。选型变化须用户/Control接受后才能改变主要工程路线。

### P4｜故障、回归、受控探索与完善

- 在合成隔离环境验证断网前/后、回执丢失、重复提交、A→B→A、非法/过期证据、冲突意见、模型格式错误和运行中断；每个真缺陷保留失败前与修复后证据。
- 修当前写面内高价值缺陷，强化schema、错误信息、测试与文档；不是无休止加“测试数量”。
- 探索优先选最薄弱的一项：证据来源关联、下一问价值、专业冲突保留、界面可读、适配器故障恢复。不要因为一个方向难就转去做无关酷炫页面。
- 三维现场、周期采集、完整媒体实现只做有限可行性/数据契约研究，不安装Blender/重建工具、不生成伪现场、不建设实时会议基础设施。

### P5｜收口和可接手交付

- 不晚于上限前预留足够时间复跑聚焦tests/typecheck/lint/build及HTTP/浏览器Gate；不同运行模式的证据分开。
- 交当前可演示路径、剩余阻塞、恢复方式、实际用量与运行服务清单。已有未完成动作安全停止/标记，不遗留未知后台批量付费请求。
- 最终不是承诺整套已上线：分别报告代码/模拟/真实模型/真实会议/设备/核算哪些实际通过。

## 4. 成本与安全不是长程时间授权的附赠品

- 8–10小时是ZCode任务窗口，不是产品模型无限调用预算，也不是保证Harness一定能自主跑满。
- 后续真实产品模型调用只在用户给出有效产品凭证和接入条件满足时进行；不得从Coding Plan/Codex/ZCode配置抽取密钥。
- 本轮长程执行对真实产品模型采用**总上限50万tokens**，不是通过自动拆批反复刷新额度；含并发在途预留和未知调用估计。前序每批30–50万的讨论不视作无限多批许可。达到上限后继续本地测试/文档，更多真实调用另问用户。
- 视觉模型、视频房间/流量、云部署和新付费服务不能推定在文本资源包内；未授权就不使用。没有密钥也能做协议和故障测试，但报告modelCalls=0，不能称真实推理验证。
- 未知阈值/成本/公式用未配置状态；不能因为缺关键业务输入让LLM自填。不得用表情/长相推断诚信、测谎或信用资格。

## 5. 不中断推进，但随时可被纠偏

在自己的ZCode会话中每个检查点给一条有结果的简短更新；无外部变化不刷屏。大约每30–60分钟至少写一次本地STATUS.md，包含当前目标、已验证、失败/未知、下一步、资源用量。

普通检查点自行继续，直到达成DoD、到时限或遇到不能绕开的硬阻塞。一个模块阻塞，先推进独立可验证事项；全部相关事项都被同一权限/资料阻塞时，明确结束为BLOCKED，不假装后台工作。

用户中途纠偏时：停止领取新步骤 → 将已产生变化和在途请求记清 → 写DIRECTION_CHANGE.md（原目标、新要求、受影响写面/测试）→ 小范围且明确授权的调整继续；涉及核心方向/新数据/权限/成本的变化先询问。不得在原边界和新边界之间暗自混跑。

不得主动操作Codex、发消息给Codex或创建Codex任务。交接只通过用户可见的本地文件和自己的会话；用户可把阶段报告转交Codex复验。Codex没有自动订阅本任务，不宣称它在同步监视。

## 6. 必交产物与完成定义

在V6/handoff/REMOTE_DD_LONG_RUN/保存：
- STATUS.md：随时能接手的简明状态，不含凭据或大段聊天。
- BASELINE.md、INTERFACE.md、OWNERSHIP.md、PLAN.md。
- METRICS.md：上述指标的实测/未知与用例范围，含误报漏报，不只报成功。
- evidence/：命令、退出码、原始测试结果、截图与diff/hash；模拟/真实分别归类。
- EXPLORATIONS.md：每项探索的结论、代价、未解决项与是否建议采用，不自行晋升主干。
- REPORT.md：已交付、未完成、风险、真实调用用量、复现和恢复、下一条最有价值任务。

DoD：当前可实现增量已有可运行且真实标注的闭环证据，旧功能不退化，风险/证据/人控不变量无已知未处理严重失败；非就绪依赖明确标记，不能用假数据掩盖。提前达到可交付目标就结束，不为了时长增加功能；达不到则交部分完成和明确阻塞，不写“全套已完成”。

最终由Codex独立复验、用户接受；ZCode长时间运行或自测通过不等于已被接受。
