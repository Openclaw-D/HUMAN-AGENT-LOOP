## B1. 唯一权威业务事项与组织主线

状态：`FROZEN / USER CONFIRMED`

### B1.1 后端唯一一级业务事项

- 见微 V2 后端围绕的唯一一级业务事项是：**融资租赁事项**。
- 决赛不以跨行业、跨金融业态复用的通用“协同事项”作为后端权威根对象。
- `CollaborationCase` 不得作为与融资租赁事项平级或更高层的权威业务根对象。后续即使保留协同辅助对象，也必须从属于融资租赁事项；其具体形态尚未冻结。
- 本条只冻结见微聚合、追踪和接续工作的业务根对象，不表示见微取代既有系统成为全部业务事实的权威来源。原系统继续持有其负责的权威事实，见微只保存后续讨论确认的最小协同状态、事件、责任、证据与回执。

### B1.2 决赛业务边界

- 当前业务范围锁定为**融资租赁**。
- 银行、保险、信托及全牌照叙事不进入当前后端对象、术语、流程、演示或验收。
- 跨业务复用只可作为远期可能性，不得反向改变本期数据语义和验收对象。

### B1.3 组织主线

- 主协同关系锁定为：**业务 ↔ 大风控**。
- “大业务”在本项目中统一简称为“业务”，指触达供应商、发现和推进商机、联系和服务客户的销售及业务人员群体。
- “大风控”固定包含四个板块，并按顶层顺序表达为：**政策、信审、商务、资产**。
- 决赛重点放在**信审**，但信审与政策高度关联，不得将信审描述为脱离政策独立运行的单点 Agent。
- **政策**负责准入、行业、风险政策、标准和规则支持，并与信审判断形成强关联。
- **商务**偏执行和流程，主要涉及合同、物流、资金及业务落地相关事项。
- **资产**负责起租后的租金和还款履约、催收、资产处置以及诉讼资源等存续期管理。
- 风控是显性优势和主要证据，但见微仍是业务与大风控之间的人机协同平台，不得退化为单一信审或风控 Agent。

## B2. 单一总生命周期与高层时序

状态：`PARTIALLY FROZEN / HIGH-LEVEL LOGIC USER CONFIRMED`

### B2.1 已冻结

- 每个融资租赁事项只有**一条总生命周期**。顶层只以政策、信审、商务、资产四个板块表达，不再把商机和尽调设置为与四板块平级的主节点。
- 厂商推荐商机、业务承接客户需求和现场尽调作为政策板块内的前序流程进入同一事项；它们仍由业务、厂商或尽调 Agent 承担实际责任，不因此变成政策人员的项目审批职责。
- 大风控四板块按业务逻辑时序表达为：**政策 → 信审 → 商务 → 资产**。
- 政策先提供规则、引擎能力和必要数据基础；信审据此进行风险把控；商务承接合同、物流、资金等合规与执行流程；资产承接起租后的履约、催收、处置及诉讼资源等存续管理。
- 资产是当前总生命周期的下游和收口阶段，不把起租视为事项结束。

### B2.2 尚未冻结

- 总生命周期的精确状态名、进入条件、退出条件、允许回退、循环、暂停、终止和重开语义。
- 政策板块内部商机接入、现场尽调、政策能力调用和政策结果形成的精确子流程。
- 商机、客户、供应商、资金需求之间的对象关系。

## B3. 政策的产品地位

状态：`FROZEN / USER CONFIRMED`

- **政策产物是每个融资租赁事项必经的控制输入，但政策人员不是每个事项的人工审批人。**
- 政策板块主要负责建设、发布和持续调整模型评分、策略、反欺诈、规则、引擎能力及其所需数据基础。
- 每个融资租赁事项都必须经过适用政策产物的判断或计算，并保留使用了什么政策/策略/规则版本及其结果；具体字段和结果枚举尚未冻结。
- 政策人员主要维护组织级政策能力，并在新问题、规则冲突、解释不清、重大变化或例外情形下进入具体事项，而不是逐项目批准或否决融资租赁项目。
- 信审消费政策产物和相关证据进行项目风险判断；政策判断不替代信审人员的项目审查责任。
- 因此，生命周期中的“政策”表示**政策能力应用与结果形成**，不表示每个事项都要等待政策人员完成一次人工流转。

## B4. 业务流图与可插拔能力结构

状态：`FROZEN AT PRODUCT-STRUCTURE LEVEL / USER CONFIRMED`

### B4.1 一条业务流，不是一组独立 Agent

- 见微 V2 后端首先是一条围绕同一融资租赁事项运行的**融资租赁业务流图**，不是政策、信审、商务、资产四套独立应用，也不是若干垂直 Agent 的集合。
- 高层主路径锁定为：**政策 → 信审 → 商务 → 资产**。商机获取和现场尽调作为政策板块内的前序工作进入同一事项，不再占用顶层节点。
- 该路径中的“政策”沿用 B3 语义：每个事项应用政策产物，但不等待政策人员逐项目审批。
- 同一事项贯穿全部环节；换人、换 Agent、换能力库或换外部系统时，不得重新创建另一条事项历史。

### B4.2 相互影响，不是单向流水线

- 业务流必须允许前后环节相互影响：上游材料、政策结果和信审判断影响后续商务与资产；下游执行、履约和风险结果也可以反馈前序判断与后续行动。
- 因此，后端不能只用一条不可回退的线性状态机表达全部业务；需要在单一总生命周期上保留补证、重评、例外、回退、反馈和重新进入等关系。
- 哪几条反馈边进入 MVP、各自触发什么状态变化，尚未冻结。

### B4.3 大业务流、小内核、可插拔能力

- 见微展示完整融资租赁 AI-native 业务生态，但 MVP 只自研一个小型协同内核和少数真实挂载点，不重建各板块的全部专业能力。
- 每个环节可以挂载现有或候选的 Agent、模型、规则、策略、反欺诈、数据、证据或业务系统能力；见微提供统一的能力接口、受控上下文、人工权威、事件、证据和回执语义。
- 专业能力库负责“具体工作怎么做”，见微负责“何时调用、带什么受控上下文、谁有权确认、结果怎样影响同一事项、是否有真实回执”。
- 当前代码实验只能验证候选接口，不得因某个实验模块存在就反向冻结产品对象、生命周期或板块关系。

## B5. 异常驱动的全生命周期自动化愿景

状态：`FROZEN AT PRODUCT-VISION LEVEL / USER CONFIRMED`

### B5.1 目标工作方式

- 理想工作方式是：业务人员找到客户并确认其设备融资需求后，系统尽可能自动完成后续信息采集、能力调用、规则校验、问题定位、上下文路由、补证提示和流程推进。
- 人不需要手工搬运全部材料或逐环节重复解释；系统在正常路径上主动推进，在发现缺口、冲突、异常、越权或高风险决定时，才把问题精准路由给有权人员。
- 该自动化覆盖商机、尽调、政策、信审、商务、起租和资产存续，不是只服务授信或信审。

### B5.2 移动尽调与现场问题定位

- 业务尽调的高频入口优先考虑移动端；现场拍摄设备、录入客户和交易信息可以成为事项证据输入。
- 图片、文字或模型识别结果只是候选证据，不能单独成为权威事实或项目决定；必须保留来源、采集主体、时间、适用范围和必要的人工确认。
- “三至五分钟”当前只作为**现场问题识别、定位和补充提示**的目标，不表示已证明能在三至五分钟内完成完整尽调、授信审批、合同执行或起租。
- “全自动、超智能、超准、符合规则”是长期目标，不是当前能力或决赛可宣称的已验证结果。

### B5.3 分阶段实现原则

- V1、V2、V3 是同一个后端内核在集团内网逐步落地的三个开发与成熟阶段，不是三套系统、三套业务语义或三个相互竞争的页面方案。
- V1 先把后端权威内核做扎实，重点是单一事项、角色、权限、Context Router、Handoff、Human Gate、Event、Evidence、Action 和 Receipt；只保留证明闭环所需的最小交互。
- V2 在同一内核上增加少量关键可视化、移动端入口和受控系统挂载，使业务、信审及其他有权人员能够看见原因、责任、缺口、下一步与回执。
- V3 在同一内核上进入更完整的可视化、移动现场感知、主动风险发现和跨环节智能路由。
- 当前外网决赛开发可以直接呈现 V3 目标体验，但只能使用合成、去标识、公开材料和 fake/stub Adapter；外网 V3 演示不等于集团内网已经完成 V3 集成或生产落地。
- V1/V2/V3 是内网落地阶段标识；它们不取代后续工程检查点或验收 Gate 的编号。

## B6. 最小 Human Gate 集合

状态：`FROZEN / USER CONFIRMED`

- 政策例外、规则冲突或突破既定政策，必须由具名有权人员处理；政策人员不因此成为每个事项的固定审批人。
- 最终信审结论及核心授信条件，必须由具名有权人员决定；模型、规则和 Agent 只能形成候选判断与证据。
- 合同生效、资金投放和正式起租等高影响外部动作，必须经过现有授权体系中的具名人员确认，并取得可验证回执。
- 正式催收升级、重组、诉讼和资产处置，必须由具名有权人员决定。
- Human Gate 应路由给对应有权人员，不应让最初获取商机的业务人员在后续每个阶段反复确认。
- 除上述权力决定及真实异常外，材料整理、信息抽取、规则校验、问题定位、补件提示、候选方案、上下文分发、文书草拟、状态监测和提醒原则上允许自动推进。

## B7. 单次采集、全程复用与阶段投影

状态：`FROZEN AT PRODUCT-VISION LEVEL / USER CONFIRMED`

- 同一融资租赁事项中的信息原则上只采集一次，后续政策、信审、商务和资产阶段按权限复用，不要求人员跨系统重复上传、复制或重新解释。
- 后端对外呈现一个统一的融资租赁事项业务流；不同现有系统、Agent、模型、规则和阶段界面通过受控挂载点参与同一事项，而不是各自复制一套项目事实。
- 前端不是另一套业务权威，只是同一事项在不同角色、阶段和终端上的受控投影；界面优先显示当前缺口、原因、责任、下一步、证据和回执。
- 能由模型、规则、Harness 或 Agent 预处理的内容不要求人重新填写；交互优先采用围绕单个事项的自然语言对话、动态生成的少量关键问题和必要的关键决定。
- Agent 能完成的工作交给 Agent；无法可靠完成、存在冲突、越权或需要业务权威的部分才交给人指导或决定。
- “唯一接口”当前指向统一的逻辑业务入口和权威事项语义，不预先冻结为单一 HTTP 路径或一个物理服务。

## B8. 追加式版本与影响传播

状态：`FROZEN / USER CONFIRMED`

- 事项信息永不静默覆盖。客户陈述、现场采集、证据、模型结果、规则结果、人员意见、业务决定和外部回执均形成追加式记录或新版本。
- 每个版本至少保留来源、形成时间、提交或执行主体、适用范围、与前一版本的关系及变更原因；具备相应权限的后手人员能够追溯某一时点“谁说了什么、谁做了什么、系统依据什么得出当时结论”。
- 新版本进入后，系统应识别受影响的政策结果、信审结论、商务条件和资产判断，自动触发重新计算、重新核验或 Human Gate，而不是继续沿用已失效结论。
- V1、V2、V3 可以作为前端高频版本视图，但后端不得把三个版本设为历史保留上限；完整证据链不得因展示简化被删除。
- “忠诚、真实、完整”在系统语义上首先表示忠实记录、不可静默篡改和来源可追溯。系统仍须区分当事人陈述、候选识别、证据、已核验事实和有权决定，不能把被记录的陈述自动宣称为客观事实。

## B9. 主干加回流的循环业务图

状态：`FROZEN AT PRODUCT-VISION LEVEL / USER CONFIRMED`

- 融资租赁事项的顶层主干按政策 → 信审 → 商务 → 资产表达，但它不是一次性结束的线性流水线；商机与尽调保留为政策板块内的前序流程和证据来源。
- 任一下游阶段都可以因新信息、缺口、冲突、异常或风险变化，向前序阶段发起受控的重新判断循环；完成补充、核验或重新决策后，再把结果合并回当前事项。
- 已确认的典型回流包括：信审回到政策板块内的尽调或政策能力；政策板块内的尽调回到商机接入；商务回到政策板块内的尽调或信审；资产回到信审或政策。该清单不是穷举，不以硬编码所有两两连线表达业务。
- 产品表达采用“清晰主干 + 当前激活的回流”而不是同时画出所有可能连线；前端重点回答当前为什么回流、要回到哪里、需要谁补什么、影响哪些结论以及何时闭合。
- 后端应使用统一的回流语义承载来源阶段、目标阶段、触发原因、关键问题、所需证据、受影响结论、责任主体、当前状态和闭合回执，避免每类回流各建一套特殊流程。
- 循环允许重复发生，但后续必须冻结自动重试上限、重复问题合并、无法收敛时升级人工和失败关闭语义，防止 Agent 无限循环。

## B10. 主阶段不倒退，局部循环重新判断

状态：`FROZEN / USER CONFIRMED`

- 已完成的宏观阶段不因后续发现问题而倒退或被抹去；事项保持当前主阶段，并打开一个可追溯的局部重新判断循环。
- 局部循环可以向前序人员、Agent、规则、模型或系统能力发起问题和受控上下文请求；它是同一事项中的协同，不是复制一个新事项。
- 只有受新信息影响的结论和后续动作被标记为待复核、暂缓或失效；未受影响的工作、历史事实和已取得回执继续保留。
- 循环完成后形成新版本，重新计算或重新确认受影响结论，再把结果合回当前主阶段。

## B11. V3 横屏信息架构候选

状态：`FROZEN AT INFORMATION-ARCHITECTURE LEVEL / USER CONFIRMED`

- 外网决赛 V3 的基准画布冻结为 16:9、1920×1080，并以 60fps 作为交互流畅度目标；60fps 是性能目标，不是未经实测即可宣称的结果。
- 顶部放置唯一固定的融资租赁事项主流程，稳定展示政策、信审、商务、资产四大板块以及当前所在位置；商机与尽调只在进入政策板块后展开显示。
- 顶部区域左侧显示项目名称，右侧只保留少量事项级操作；主流程进度是页面唯一置顶的持续导航。
- 主流程图不同时画出所有可能的回流连线；默认保持清晰主干，只突出当前激活的局部回流、原因和受影响节点。
- 主内容区复用既有前端中的关系与矩阵表达，并允许在“矩阵视图”与“关系图谱/画布视图”之间切换；两种视图展示同一事项内人员、Agent、规则、模型和系统能力之间的责任、协同与上下文交接关系，不再复制主阶段状态。
- 右侧保留事项级聊天窗口，首先回答“为什么找我、我负责什么、缺什么、会影响什么”，再允许自然语言补充信息、回答动态问题和触发有权决定；它不是脱离事项的通用聊天机器人。
- 三个区域共同读取同一个后端事项与事件流，只是不同 Projection，不得各自维护业务权威状态。
- 既有 `prototype/reference-ui` 仅作为关系矩阵、布局和交互资产候选；复用时必须替换与当前融资租赁语义冲突的旧状态、旧场景和旧权威逻辑。
