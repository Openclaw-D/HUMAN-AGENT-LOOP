## 2. 当前产品方向

见微围绕一个融资租赁事项，把业务、大风控中的具名人员、各板块 Agent、规则和既有系统接起来。平台负责能力注册、受控上下文、人工权威、状态、事件、证据和接续；垂直 Agent 负责具体工作。

第一体验先回答：**为什么找我、我负责什么、我能看什么和做什么。** 然后才解释 Agent 如何辅助。

当前跨环节主循环候选：

> 感知变化 → 解释为什么找谁 → AI 推荐若干人或 Agent → 有权人员确认 → 受控上下文分发 → 人与 Agent 执行 → 结果、证据与回执返回。

模型无业务权威；AI 只推荐候选，人最终选择。高风险动作必须经过显式 Human Gate，外部动作只有收到真实 Receipt 后才能认定完成，失败或未知必须关闭。

## 3. 已冻结内容

正式冻结只见 `P2_BACKEND_PRODUCT_FREEZE.md`。当前已确认：

- 唯一一级业务事项是融资租赁事项；
- 主协同关系是业务对大风控；
- 大风控固定为政策、信审、商务、资产，重点是信审；
- 每个融资租赁事项只有一条总生命周期；
- 高层业务逻辑从商机与尽调进入政策、信审、商务和资产存续；起租不是事项终点。

## 4. 最新确认：政策的产品地位

- 政策产物是每个融资租赁事项必经的控制输入，但政策人员不是逐项目审批人。
- 政策板块主要建设和维护模型评分、策略、反欺诈、规则、引擎能力及必要数据基础。
- 每个事项应用对应政策产物并保留版本和结果；新问题、冲突、解释不清、重大变化或例外时才把政策人员拉入具体事项。
- 信审基于政策产物和其他证据承担项目风险判断责任，政策不会替代信审审批。

该结论已写入 `P2_BACKEND_PRODUCT_FREEZE.md`，并作为后续业务流设计的固定控制输入。

## 5. 最新确认：大业务流、小内核、可插拔能力

- 后端产品是一条围绕同一融资租赁事项运行的业务流图，主路径为商机获取、尽调、政策能力应用、信审/风控判断、商务执行与起租、资产存续。
- 它不是四套部门应用或一组垂直 Agent；同一个事项、责任、证据和结果历史贯穿全部环节。
- 业务流不是不可回退的单向流水线。上游判断影响后续执行，下游履约和风险结果也能反馈政策、信审、业务与后续动作。
- 产品展示完整 AI-native 生态，但 MVP 只实现小型协同内核和少数挂载接口。专业库负责具体能力，见微负责调用时机、受控上下文、人工权威、结果影响、事件与回执。
- V2Z 可短周期实现隔离的候选接口，用代码暴露问题；实验代码没有产品冻结权威，不能写入主方向目录或反向决定产品。

当前下一项不是继续增加 Agent，而是选择 MVP 第一条必须跑深的跨环节反馈回路。

## 6. 最新确认：异常驱动的自动化与三阶段路线

- 理想状态是业务人员找到客户并确认设备融资需求后，系统在正常路径上自动采集、校验、调用能力、定位问题、路由上下文和推进事项；只有异常、高风险或需要权威决定时才精准找人。
- 自动化覆盖商机、尽调、政策、信审、商务、起租和资产存续，不是单一授信助手。
- 移动端是业务尽调的高频入口，设备照片和现场文字可以作为候选证据；必须保留来源并经过必要确认，不能直接成为权威事实。
- 三至五分钟只作为现场问题定位与补充提示目标，尚未验证；不能写成完整授信或全流程已自动完成。
- 实现顺序先后端内核，再少量关键可视化，最后完整可视化与主动感知。正式 P 编号仍待确认。
- V2Z 的下一个候选切片应转向 Context Router/Handoff，但必须等当前 Z 调用完成审计并由主控冻结接口。

## 8. 最小融入 Gate

- 不替换现有身份、规则、审批、Agent 或业务系统；
- 原系统继续保存其负责的权威业务事实；
- 见微只保存后续确认的最小协同状态、来源指针、责任、事件、证据和回执；
- Adapter contract-first，从 fake、stub、只读或影子模式开始；
- 移除见微后原业务仍可继续；失败关闭、可回退；
- 不承诺字面上的即插即用或当前生产部署，只证明低侵入契约与可测的首个价值。
