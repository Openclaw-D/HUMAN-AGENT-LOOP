# 任务四｜以非开发用户完整旅程为准，独立验收与交付同一个可运行产品

你是本地 ZCode 中 JW 的独立集成、用户旅程验收和发布负责人。主目标不是证明各模块各自全绿，而是证明一个普通用户无需开发者协助，就能从页面处理一个新客户并完成有权人工决定；同时验证部分解耦没有损害正确性。

## 1. 所有权与独立性

负责 Back/D/**、Back/Edge/test/e1/**、Back/Edge/scripts/**、发布/恢复/性能脚本及根部交付说明，文档放 docs/product-delivery/goal-04/。不修改 A/B/C/Connectors、Edge/src 或 Front 来掩盖失败；缺陷退回对应 writer。各自默认测试入口的业务包修改由其 owner 完成，你验证不漏挂。

固定本地实际版本、在制修改和相关文件摘要，读取 AGENTS.md 与本轮共同目标。在设计阶段就给出用户旅程和失败判据，尽早与前三路接通一个原始文件，不等模块全部结束才装配。不自动 commit/push/合并 PR，不强杀未知资源，不用未授权真实账户或费用；一主 AI 上下文，普通测试进程隔离。

## 2. 固定验收原件和期望，禁止脚本替系统做业务

准备小规模但覆盖实际需要的合成原件包：客户执照/主体材料、CSV 或 XLSX 流水、账表、PDF 购机合同、设备铭牌/现场图片及一份后到的更正或不利材料。包含金额、期间、设备编号一致与冲突两种情况；另有引号金额、非法日期/坏行、重复文件等失败样本。

允许测试创建合成原文件与隐藏期望值；禁止把答案/预填事实/固定 CLEAR 放进被测分析输入。变更原件中的金额、编号或期间后，相应观测和判断应变化；未能识别的材料进入明确人工路线，不伪装自动成功。扫描无获准识别提供方时，测试业务人员在页面定位来源、录入/复核的路线，并标注人工。

模型/政策用显式合成测试配置可验证本地产品链，真实能力与效果另列。不能通过 API 脚本直接登记“运行完成/通过意见”代替真正执行器；不能把分别通过的处理链和审批链拼成一个全程成功声明。

## 3. 真正的最终用户脚本

从一次约定的安装和管理员初始化后开始：

1. 业务在页面创建新客户并发送受限邀请；客户角色登录上传原始文件，不填内部 ID。
2. 页面显示上传/解析/预审分段状态，任务由常驻服务推进；处理产物经桥接真实进入 A，并可追溯到同一原件。
3. 专业人员查看四域意见和具体证据，向厂长/财务提出定向问题；客户在获准线程回答、补材料。重要人工核验由有权人员在页面完成。
4. 系统形成可复核的候选及完整当前依据；普通业务/客户不能批准，有权人类经页面确认作出决定，服务端留下真实回执与依据版本。
5. 刷新、退出重进、后台中断恢复后记录仍在；再添加一份不利材料，不改历史决定，但当前复核和后续动作按已批准规则限制。

全程禁止终端/SQL/调试接口/浏览器控制台补业务状态，禁止 allow-legacy-basis 和隐藏剧情按钮。测试框架可以驱动用户点击、选文件，并在只读侧检查数据库/回执来断言；它不能绕过页面替用户完成业务写入。管理员初始身份与合成政策种子要明确记录，不每个案例临时改权限。

## 4. 正反例与部分解耦验收

- 非开发验收：目标业务人员按简短正常使用说明操作，无开发者临场口头指挥。用户现场未实际执行就标 NOT_RUN；浏览器自动化证明操作可达，不冒充真人可用性验收。
- 权限/依据：匿名、跨客户、撤权回放、伪/过期豁免、旧 Gate、检查新修订、晚到结果、错设备/期间、未知外部结果与重复提交；每个失败有页面解释和合法恢复路线。
- 并发/恢复：重复上传和批准、数据已提交而响应丢失、处理驱动重启、会话断线、慢文件不拖住交互；所有失败轮次保留。
- 解耦：核心不导入租赁阈值、供应商 SDK 或界面；测试内换一个简单材料复核配置、解析或渠道适配器，不改核心事务/权限代码，真实租赁路径仍通。只做测试证明，不额外开发第二行业产品或通用平台。
- 反证：移除桥接或关键提交门时相应测试必须失败。可在隔离副本进行临时故障/变异，不污染交付源码。

## 5. 性能、工具与同版收口

先修默认测试命令漏挂/损坏、全 SKIP/零断言算 PASS、无限挂起、版本清单落后和并行环境串用。必测 FAIL/BLOCKED/NOT_RUN 不能汇总成发布 PASS。

固定同一发布快照再测；其他路修改后作废受影响结果，不能把脏树不同时刻的绿灯相加。至少三轮同环境记录页面首屏、文件处理、预审等待、关键提交、跨角色同步、查询/调用数和资源峰值；性能改善不能来自跳过核验或隐藏异常。旧兼容接口优化数据不能冒充新完整流程数据。

测试工作数据扩大与至少九角色会话；真实物理终端数量如实记录。保持输出简单，优先修用户可感知的等待和重复处理，不为毫秒指标增加无关架构。

## 6. 产品发布与恢复

统一提供正常启动、健康/依赖状态、停止和诊断入口。安装可能需要约定的操作系统/运行时前提，但步骤写成普通使用说明；若缺依赖就明确提示，不宣称任意电脑零配置。安装后每次办理不依赖开发者配置脚本。已建运行时存在时只操作自己跟踪的资源。

备份/恢复覆盖本轮全部迁移和非空关联数据、原始材料字节或可验证存储引用、解析版本、业务任务、授权、分析回执、决定与报告。恢复后重跑页面查询/继续办理，不能重放外部发送；代码回退和数据回退分开。扫描实际发布树与已跟踪文件，不泄露秘密原文；dist、源代码和契约对应同版。

D27-L-UI 是本轮硬门：二维页面上原件到人工决定，不靠开发者。真实媒体/模型提供方 D27-R 和多人空间 D27-S 单列，未授权/未实现如实保留，不用录屏/合成工厂顶替，也不让未做三维阻止本轮二维硬门验证。

分阶段：D1 冻结用户脚本/基线；D2 跟随集成并修验收工具；D3 固定版本全旅程/故障/恢复/性能；D4 非开发试用与交付。交付 ACCEPTANCE_MATRIX.md、DEFECTS.md、TEST_RESULTS.md、RELEASE_ACCEPTANCE.md，以及普通用户说明和脱敏证据。最终按“人能完成哪些动作”汇报，不按代码行数或测试总数代替交付。
