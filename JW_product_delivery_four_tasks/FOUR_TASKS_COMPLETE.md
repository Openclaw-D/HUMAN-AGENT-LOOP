# JW｜原件到人工决定：四路产品交付指令

## 共同完成标准

普通客户和业务人员，在约定的一次安装与管理员初始化之后，能通过正常页面，从一个新客户和一批原始材料开始，完成邀请、提交、处理、补证、核验、方案查看、有权人类决定与结果查询；业务过程中无需开发者陪同，无需终端、SQL、API 调试工具、手填内部 ID 或手工补状态。

允许必要的人类业务劳动：解释口径、定位来源、核实事实、处理例外、正式决定。禁止把开发者搬运数据、伪造服务回执、填写技术 JSON 当成人在回路。

本轮允许新增和调整完成上述流程必需的客户端、内部工作台、复核与决定界面，不再受“前端只能微调”限制。但不进行与办理无关的全面视觉重做，不建设新三维引擎。

## 部分解耦，不建设通用大平台

建议在现有进程与数据库基础上做模块化改造：

| 边界 | 负责内容 | 禁止混入 |
|---|---|---|
| 通用核心 | 当前身份与资源权限、材料版本与来源、运行记录、任务状态、候选/复核/正式动作、幂等、审计、事务与事件 | 租赁政策阈值、固定四域名称、具体解析 SDK、页面组件 |
| 租赁业务模块 | 客户主档、四域分工、资料口径、红线、方案、客户额度、提额机制、直租/回租要件 | 浏览器状态、供应商 SDK、通用执行器实现细节 |
| 适配与应用层 | 文件/模型/渠道/媒体适配、Edge 投影、客户入口与工作台 | 独立审批权、另一套客户授信数据库、前端自定业务状态机 |

目录名不是目的；优先提取已有代码的真实边界，不全仓搬家，不把所有领域对象降格为任意 JSON，不创造通用工作流 DSL、插件商城、跨行业产品或微服务体系。

只有当前确需替换或隔离的地方才抽接口：材料解析、模型执行、渠道发送、版本化业务政策与证据/任务/决定服务。内核通过受控接口消费业务模块；业务模块可引用通用类型，但不能绕过核心权限和提交校验。业务配置只能表达获得批准的约束，模型文本不能临时改规则或提权。

## 基线和执行纪律

- 本包是新一轮任务要求，不是对当前本地/PR 已通过的认定。各路启动时记录实际本地分支、HEAD、脏文件和相关文件摘要，读取当前 AGENTS.md 与契约。不盲目切到 main、不自动合并 PR、不覆盖其他路已有修改。
- 对此前缺陷先复现：已修保留回归，未修定向处理。不要把“假定前序完成”写成事实；未实现的客户入口、媒体、空间构建单列。
- 每路完成“小范围设计→分批实现→正反例测试→实际链路验证→同条件性能复测→修复再测”。不只交方案或待办。正常范围内连续执行；未授权费用、外发、部署或未定业务规则只阻断相关子项，不猜测批准。
- 不自动 commit/push、切分支、创建 worktree、强杀未知进程或删除未知数据库。提交边界指可审查变更集合，不是 Git 操作授权。一个主 AI 执行上下文；普通测试子进程使用各自登记的资源。
- 不启用真实客户数据、真实渠道或费用，除非已有相应明确授权；不把密钥写入仓库、前端包、日志或报告。真实敏感文件只能进入获准存储和处理范围。
- 先复用性能成果。不以删权限、跳必核项、伪造成功或复用过期结果提速。不追逐没有业务收益的微小延迟差，也不承诺未经测量的倍率。

## 四路唯一修改者

| 路 | 所有权 |
|---|---|
| 01 | Back/A/**、A 迁移与依赖、Back/CONTRACT.md；核心/业务边界和 A 应用接口的集成 writer |
| 02 | Back/B/**、Back/C/**、Back/Connectors/**；各自依赖与默认测试入口 |
| 03 | Front/**、Back/Edge/src/**、Back/Edge/contract/**、Edge 非 e1 测试、Edge 依赖与 package.json |
| 04 | Back/D/**、Back/Edge/test/e1/**、Back/Edge/scripts/**、发布/验收文档和根部交付说明；发布装配 writer |

各路文档位于 docs/product-delivery/goal-01..04/。跨目录需求写各自 INTERFACE_REQUESTS.md，明确接口的生产者、消费者、必需字段、错误语义与截止到哪一阶段需要；由对应 writer 实现。不得把必要接口长期标 OPEN 后自称任务完成。共享新目录必须先明确唯一 writer，不私下争抢。每路自己的 package.json 修自己的测试入口；独立测试由 04 检查覆盖。

## 合流顺序

先由 01/02/03 固定最小实际消费契约，由 04 冻结第一条用户路径与失败判据。随后并行实现，但尽早接通一份原始文件，不等所有模块“全绿”才接线。每阶段进入同一个受控集成版本，由 04 在不再变动的快照上测试。需要调整契约时版本化迁移，生产者和消费者同步；不能用私有 mock 永久代替缺失接口。

独立验收两条线分开：开发者 API/并发测试证明实现；浏览器用户旅程证明产品。不能以前者替代后者。二维完整办理是本轮必须交付，真实媒体和三维未完成则单独保留，不冒充整个最终产品完成。

# 任务一｜提取通用可信核心，交付可供页面办理的租赁业务服务

你是本地 ZCode 中 JW 的核心与租赁业务服务负责人。你的目标是让现有后端既可复用又可办理：通用机制与租赁规则分开，客户从进件到人工决定所需的正式服务全部可被实际页面消费。不是推倒重写，也不是再建通用平台。按“核对现状→设计→分段实施→测试→联调复测”连续执行。

## 1. 所有权和基线

仅修改 Back/A/**、A 的依赖和迁移、Back/CONTRACT.md，以及 docs/product-delivery/goal-01/。其他路的 B/C/Connectors、Edge、Front、D 不改；它们提交的必需接口需求由你统一落地，不能只登记 OPEN 后认为完成。

先读本地 AGENTS.md、现有源码与最新审核，记录 HEAD、在制文件及可运行基线。已修问题保留回归，未确认的结论不写成事实。不自动提交/推送/切分支，不覆盖其他人修改；一个主 AI 上下文，自有测试资源隔离。

## 2. 部分解耦的实现边界

在现有进程/数据库中划出以下代码边界，目录映射可自行设计，但必须有实际调用与测试：

- 通用核心：身份/资源范围、材料与版本/来源、运行与任务、候选/人工复核/正式动作、幂等、事务、审计和事件。
- 租赁业务模块：客户主档、资料口径、四域、红线与适用条件、方案、额度、提额冷却、直租/回租要件。
- 应用服务：把通用核心与租赁模块组合成客户办理用例，向 Edge 和执行器提供稳定接口。

通用核心不导入具体解析/模型/企微 SDK、页面或 Unity；不硬编码四域标签、行业阈值和额度上限。租赁模块可以使用通用类型，但不能绕开核心授权、伪造可信回执或随意改状态。金额、交易与授信等领域对象保留明确类型，不全部改成万能 Entity/JSON。

不新建第二套身份、任务、证据或审批数据库；不全仓迁移、不引入通用工作流 DSL。只抽实际存在替换需求或混合职责的边界。用一个仅测试用“材料复核”配置验证通用执行/材料/决定能力不依赖租赁四域；不开发第二个行业产品或页面。

## 3. 必须供实际页面使用的业务服务

补齐授权客户目录和创建/归集、邀请授权、材料/批次与处理状态、当前检查与待办、问题/补证、事实复核、四域意见、方案候选、正式决定、结果与历史查询。按客户权威查询当前对象，不让 Edge 只从有限事件窗口猜列表。

约定同一条追踪关系：客户→上传/材料版本→事实来源→执行运行→检查事项→评估依据→正式决定。新客户由产品流程创建，不要求用户填数据库 ID 或技术令牌。业务主体、客户联系人与内部审批身份分开；目录切换只是显示，权限由服务端决定。

A 是业务事实、复核和正式决定的权威来源；Connectors 可保存原始字节位置、解析缓存与处理任务，但不能另设一套正式授信结果。定义最小写入/回执和事件契约，让 02 真实处理结果能进入 A，让 03 无需绕过接口完成办理。

## 4. 正确性硬门

- 当前身份、客户范围、动作权限先于回执重放；撤权覆盖读、事件、报告、附件与命令，默认权限不得靠 all 掩盖未授权。
- 检查引用在正式动作时复查当前修订；Gate 必须绑定真实输入、规则版本与结果，不能只凭可信服务身份提交任意 CLEAR。过期/缺失/未知都不能通过；运行开始固定输入，结果完成绑定相同运行和输出摘要。
- 必需域由批准政策决定；豁免引用有效、有权批准的记录，冻结后撤销/过期也必须影响新正式动作。不能自报批准人或用空域集合免检。
- 设备/主体/期间/来源匹配到具体核验项；只收到同种材料不算完成。人工核验是业务人员在页面对原件作有理由的复核，不是开发者写 verified。
- 既有金额、额度账本和事务约束不退化；客户共享额度而交易仍有自身要件。新出账、历史承诺和未知外部结果区分，不擅自扩大放行政策；本轮不新增真实资金支付。
- 补充信息可能提高、降低或维持候选；不按材料数提额。既有冷却/次数/实质证据门按客户执行，不影响重要补证和不利信息处理。
- 人类决定明确记录身份、权限、依据修订、条件与理由；模型和 service 不拥有正式批准权。真实政策未批准只提供合成训练配置或明确阻断，不编公司制度。

## 5. 设计和提交阶段

A1：列现有/待抽取边界与实际接口消费者，冻结最小契约及迁移方案；让一个真实处理回执能被 A 接收、查询。
A2：贯通进件、当前证据、检查、候选与人工决定；补齐上述当前性与权限反例。与 02/03 提前联调一名新合成客户。
A3：完成兼容迁移、权威查询和实测热点优化；批量读、短事务、一致锁序，无外部慢调用占锁。每阶段形成独立文件集合并验证再推进，不能在集成窗口同时改契约和宣称冻结。

## 6. 验收

真实数据库与 API 验证：新客户授权、撤权重放、假/撤销豁免、旧 Gate、晚到分析、检查回退、错设备/错期间证据、并发决定、同申请重复占额、提额绕行及重启恢复。正式新链不能使用 allow-legacy-basis 等免检配置。

与 04 验证：从 03 页面进入的原始材料，经 02 处理形成当前依据，最终由获准用户在页面作决定；其间不得直接伪填 Gate、完成运行或改数据库补状态。测试 setup 只允许声明清楚的合成身份、批准政策与环境初始化。

解耦验收：核心不依赖租赁标签和供应商模块；更换一个测试解析器或业务复核配置不改核心状态/权限；移除新适配层后测试能检出链路断开。性能在同环境固定数据上比较查询数/锁等待/关键请求耗时，不用删门提速。

交付 DESIGN.md、实际契约/迁移、TEST_RESULTS.md、HANDOFF.md及测试证据。完成标准是页面能消费的可信业务服务与可验证模块边界，不是多几个接口或“架构已优化”。不开发催收、总账、清算等无关模块。

# 任务二｜把原始材料真正送入同一条证据、预审和人工决定链

你是本地 ZCode 中 JW 的输入处理与执行负责人。目标是消除“解析留在 Connectors，审批脚本另造数据”的断链：客户在页面上传的原件，经过持久处理与四域核验，必须成为 A 中实际可复核的决定依据。连续完成规划、实现、服务级测试和页面联调。

## 1. 所有权与基线

负责 Back/B/**、Back/C/**、Back/Connectors/**、各自依赖与默认测试入口，文档放 docs/product-delivery/goal-02/。不改 A/共享契约、Edge、Front、D；向 01/03 提交具体接口需求并完成联合消费，不能把必需桥接长期 skipped 后宣称闭环。

读取本地规则和最新源码，确认主服务是否真的启动处理驱动。保留有效去重、缓存和选择性重算，不按历史报告重复重写。无自动 Git 写操作、真实密钥读取、付费或外发授权；一个主 AI 上下文，测试资源与其他路隔离。

## 2. 解耦边界

将解析器、模型执行、业务评估、渠道发送分别通过少量明确接口接到现有调度器；接口要能换实现，不创建新平台。

解析器只负责原件→观测/结构化行/来源定位，不决定授信；C 的租赁业务模块负责口径、四域及规则；B 负责运行、租约、重试、预算和恢复，不硬编码租赁审批；Connectors 负责接入、字节与处理状态，不拥有第二套正式决定。

字段映射、材料种类和专业域分工属于业务配置/模块；传输、解析和队列机制不因出现新的租赁字段而重写。替代适配器仍经过相同身份、来源与失败契约，不能任意写业务状态。

## 3. 打通真实的数据顺序

浏览器上传→受控字节落地和元数据校验→A 登记权威材料及版本→持久处理任务→解析/观测→按当前授权提取必要内容→A 固定执行输入→B/C 执行→提交真实输出与回执→相关检查/候选更新→页面展示。

原始字节与数据库不在一个原子事务时，设计 upload/finalize/receipt 的幂等和清理/补偿；不能一边显示上传完成，一边永久丢失任务。A ID 与 Connector ID 有持久映射，重试保持逻辑动作标识，不把网络未知改成确定未发生。各段状态、失败原因、等待谁和下一动作可被 03 查询。

规则/Gate/分析结果来自真实执行产物并绑定快照，不允许桥接器为满足 A 结构直接提交固定 CLEAR 或 completed。没有模型/渠道授权时，可使用明确标记的确定性业务处理与页面人工复核完成本地流程；不得伪称模型理解或外部消息已送达。真实提供方能力另列验收。

## 4. 收敛格式范围，但把客户常用原件办下来

与 04 固定一个覆盖执照、流水、账表、购机合同和设备证据的合成原件包，并明确每种材料自动/人工处理边界。

本轮必需：可靠 CSV/TSV、XLSX（固定合理表结构）、TXT、可提取文本的 PDF；ZIP 安全解包；JPG/PNG/扫描 PDF 可安全接收和预览。扫描识别有获准提供方则接入并单列评测；没有则走“原件可见、来源可选、人工录入/校正、获准复核”的产品入口，不交给开发者预填 JSON。

先查可复用的现有库再设计解析器；新增依赖记录必要性、版本、许可证与代价。CSV 引号/逗号/换行、金额千分位与负号、非法日期、编码、重复表头/合计行、Excel 日期与缺失公式缓存等必须正确处理或明确拒绝，不能错列/错金额后仍成功。未知币种/单位不猜，坏行不能静默参与完整合计。

原件不覆盖；人工更正追加修订、定位与理由；更正事实不等于人工核验完成。上传全部入账不等于经营收入，材料数量不等于独立证明，模型/原件中的指令不得进入系统命令通道。解压有路径穿越、展开大小、层数和文件数限制；大文件传输/解析不能占满交互资源。

## 5. 预审、问题与恢复

复用有效材料处理结果，但缓存键必须包含会改变结果的主体/期间/单位等元数据、解析器/模型/规则版本与权限范围，而不是只看文件哈希。根据证据依赖选择性重算；不能因复用旧结果漏掉新冲突。

问题给出对象、依据、目的、目标回答者、受众与预期证据；不同客户角色可并行，同一公共会话受控排队。未批准自动发送策略默认只建议。获准发送走服务端授权和幂等回执；Unknown 先对账，不换 ID 盲发。

本地页面内问答作为独立受控渠道可以完整运行，不依赖未开通的企业微信外发。回答、材料到位、事实核实三者分开；会后补证继续，不重问已回答问题；暂停/重启保留真实状态、来源和执行版本。

## 6. 阶段与验收

B1：先打通一个原始文件上传到 A 材料/解析结果的主入口，补齐跨服务 ID、失败与进度；修默认测试命令漏挂/损坏。
B2：处理上述原件范围，完成人工更正/复核所需后端；联通真实四域输出到 A 的运行和 Gate/依据引用。
B3：接通问题、补证、去重、恢复和有限负载优化，在 03 页面复验。每阶段独立变更边界，不交大量无人调用模块。

必须测：引号金额反例、非法日期、坏行合计、XLSX/text-PDF 原件、扫描人工路线、同字节不同元数据、压缩异常、错主体/设备/期间、重复上传、A 提交后断网、进程被终止后恢复、旧结果晚到、补证选择性重算和暂停。

集成验收由页面实际选文件启动，不向测试提供预填事实、Gate 或分析终态。通过改动原件里的金额/编号使结果随之变化，并用隐藏在测试端的期望值校验。支持范围内不能靠永久手工操作代替承诺的自动解析。

同输入比较处理时长、调用次数、队列等待与内存，同时检查事实正确和风险遗漏。交付 DESIGN.md、支持格式与边界、TEST_RESULTS.md、HANDOFF.md及可复现实物。没连进 A 或没被页面调用的能力只记模块完成。

# 任务三｜交付非开发人员可以独立使用的客户入口与办理工作台

你是本地 ZCode 中 JW 的产品应用层与前后端集成负责人。主目标：客户、业务、专业人员和审批人能从页面把一个新客户从原始材料办到人工决定。不是调试面板，不再受“前端只能微调”限制；允许补齐必要操作，不追求无关视觉改版。

## 1. 范围与基线

负责 Front/**、Back/Edge/src/**、Back/Edge/contract/**、Edge 非 e1 测试、Edge package.json/依赖，文档放 docs/product-delivery/goal-03/。A 及业务契约由 01 修改，处理与连接器由 02，交付/e1/D 由 04。缺接口要列生产者、消费者和样例并跟进真实联调，不永久用 mock 顶替。

核对本地 AGENTS.md、实际代码/构建/启动模式。保留可复用组件与性能成果；不自动 Git 写操作或抢其他路文件，不启用未授权外部账号/费用。一主 AI 上下文，测试运行态资源登记。

## 2. 应用层解耦

将共享界面能力（登录/资源列表、文件与证据查看、任务/问题、处理进度、提案与决定记录）与租赁业务配置/投影分开。四域标签、材料要求、额度/交易字段来自版本化的租赁业务服务或受控配置；页面不实现独立审批状态机。

Edge 只做身份、资源范围、BFF 组合投影和受控命令代理，不重算额度、不制造专业意见、不另存正式决定。通用组件不导入业务数据库或解析/模型 SDK。UI 可替换，候选、权限、业务状态仍以同一 A/执行回执为准。

## 3. 必须交付的用户路径

一、普通进入：一次安装和管理员初始化后，从正常网址进入。提供授权客户目录、搜索、创建/选择、下一步，不要求手填 customerId、ProjectId、后台地址或技术 token。合成演示身份可由受控登录页选择并清楚标训练；真实身份不允许通过角色下拉提权。

二、客户提交：业务从页面创建受限邀请；实控人/厂长/财务在各自邀请范围上传、看处理进度、回答和补证，只看到获准披露内容。过期/撤销邀请清楚拒绝。支持新客户，不依赖固定演示种子。

三、内部核验：看到原件、解析结果、来源定位、主体/期间/设备、质量问题、待办与四域分析。支持校正和有理由的人工复核，显示不同版本和具体矛盾，不需要开发者编辑 JSON。普通核验操作与正式决定权限分离。

四、问题与补证：可选择回答者和受众，查看回答、补拍/补材料、暂停自动提问和人工接管。内部沟通与对客户消息显式分开；没有真实外部渠道时页面内消息能完整办理，但不可显示“已送达企业微信”。

五、方案与决定：展示现有规则支持的金额、期限、条件和测算依据；未知成本明确标未知。候选≠批准≠可用。获准用户能查看提交点阻断、证据版本，选择现有政策允许的批准/拒绝/附条件处理；条件未满足不能假装可用。正式提交有二次确认、幂等与冲突处理。

六、结果与继续：决定落库后可查看/导出授权摘要、知道谁基于什么作出什么决定；客户看到授权结果或补证要求；退出、刷新、下次登录能继续。正式历史不可静默改写，后来证据进入新复核。

## 4. 页面形态与异常操作

保持客户为唯一工作上下文；标题、资料、聊天、额度、问题和场景引用同源。切客户时取消/隔离旧请求，迟到响应不能串入新客户。任务与证据按需加载，不一次加载全部历史。

采用可落实的客户工作本：主体区处理当前工作，右侧详情/待办，底部沟通常驻；窄屏可折叠但不丢会话。可以调整当前布局以完成办理，但不重新制作 Unity、工厂模型或整套音效/玻璃动画。未接视频或三维显式标未接入，不能用随机工厂替代真实证据。

绿色表示指定事项完成，不等于授信通过；蓝色进行中、红色明确禁止/失败、灰色未知/未开始，各带文字和图形。上传/解析/分析/待复核分开，失败说明下一动作。表单有业务语言和来源提示，不把内部错误栈暴露给客户。

真实模式失联/撤权保留真实模式的错误状态，不能转模拟成功。关键提交结果未知保留 requestId 对账；重复点击不能再次落单。原件预览与下载经过当前权限，不公开媒体目录。

## 5. 实时与性能

保留明细缓存/请求合并，但当前权限、版本失效和关键风险优先。当前对象来自 A 权威分页查询，不能因事件缓冲窗口而消失。快照/订阅交接、重连、撤权与慢客户端均有明确策略；有限 seq 回查不冒充完整事件保证。

先给必要摘要，原件和报告按需取；大文件、慢解析或媒体不能堵住人工操作。官方/自有运行入口保持受控同源与合理安全头，不关闭鉴权和 CSRF 来解决联调；凭据不编进前端。

## 6. 阶段和验收

C1：客户目录/新建、受控登录邀请与一个原件上传，接真实服务。
C2：证据预览/校正/复核、问题补证、四域意见到方案与正式决定，补齐全部可操作按钮与错误路线。
C3：跨角色/刷新/撤权/异常恢复、性能复测与固定 dist 重建。每阶段给出一条可演示的真实操作路径，不只截图。

使用真实浏览器测试实际用户路径：新客户、真实文件选择、处理进度、人工修正、问题回答、决定确认与结果留存；至少两个隔离会话验证客户与内部权限，九角色按实际权限覆盖。API 单测和 DOM 静态检查不能替代浏览器集成。

非开发验收期间只允许页面操作和业务判断，禁止打开控制台改数据、手填 ID/JSON、调用调试 API、执行 SQL 或依靠已备好的结果。最终与 04 使用同一构建、同一真实新链，不开 allow-legacy-basis。

交付必要页面、状态/交互清单、DESIGN.md、TEST_RESULTS.md、HANDOFF.md和可复建产物。没环境就如实标 NOT_RUN；“按钮已画/接口存在”不能关闭该用户动作。性能重点为首屏、处理反馈、关键提交和跨端更新，不用虚构百分点。

# 任务四｜以非开发用户完整旅程为准，独立验收与交付同一个可运行产品

你是本地 ZCode 中 JW 的独立集成、用户旅程验收和发布负责人。主目标不是证明各模块各自全绿，而是证明一个普通用户无需开发者协助，就能从页面处理一个新客户并完成有权人工决定；同时验证部分解耦没有损害正确性。

## 1. 所有权与独立性

负责 Back/D/**、Back/Edge/test/e1/**、Back/Edge/scripts/**、发布/恢复/性能脚本及根部交付说明，文档放 docs/product-delivery/goal-04/。不修改 A/B/C/Connectors、Edge/src 或 Front 来掩盖失败；缺陷退回对应 writer。各自默认测试入口的业务包修改由其 owner 完成，你验证不漏挂。

固定本地实际版本、在制修改和相关文件摘要，读取 AGENTS.md 与本轮共同目标。在设计阶段就给出用户旅程和失败判据，尽早与前三路接通一个原始文件，不等模块全部结束才装配。不自动 commit/push/合并 PR，不强杀未知资源，不用未授权真实账户或费用；一主 AI 上下文，普通测试进程隔离。

## 2. 固定验收原件和期望，禁止脚本替系统做业务

准备小规模但覆盖实际需要的合成原件包：客户执照/主体材料、CSV 或 XLSX 流水、账表、PDF 购机合同、设备铭牌/现场图片及一份后到的更正或不利材料。包含金额、期间、设备编号一致与冲突两种情况；另有引号金额、非法日期/坏行、重复文件等失败样本。

允许测试创建合成原文件与隐藏期望值；禁止把答案/预填事实/固定 CLEAR 放进被测分析输入。变更原件中的金额、编号或期间后，相应观测和判断应变化；未能识别的材料进入明确人工路线，不伪装自动成功。扫描无获准识别提供方时，测试业务人员在页面定位来源、录入/复核的路线，并标注人工。

模型/政策用显式合成测试配置可验证本地产品链，真实能力与效果另列。不能通过 API 脚本直接登记“运行完成/通过意见”代替真正执行器；不能把分别通过的处理链和审批链拼成一个全程成功声明。

## 3. 真正的最终用户脚本

从一次约定的安装和管理员初始化后开始：

1. 业务在页面创建新客户并发送受限邀请；客户角色登录上传原始文件，不填内部 ID。
2. 页面显示上传/解析/预审分段状态，任务由常驻服务推进；处理产物经桥接真实进入 A，并可追溯到同一原件。
3. 专业人员查看四域意见和具体证据，向厂长/财务提出定向问题；客户在获准线程回答、补材料。重要人工核验由有权人员在页面完成。
4. 系统形成可复核的候选及完整当前依据；普通业务/客户不能批准，有权人类经页面确认作出决定，服务端留下真实回执与依据版本。
5. 刷新、退出重进、后台中断恢复后记录仍在；再添加一份不利材料，不改历史决定，但当前复核和后续动作按已批准规则限制。

全程禁止终端/SQL/调试接口/浏览器控制台补业务状态，禁止 allow-legacy-basis 和隐藏剧情按钮。测试框架可以驱动用户点击、选文件，并在只读侧检查数据库/回执来断言；它不能绕过页面替用户完成业务写入。管理员初始身份与合成政策种子要明确记录，不每个案例临时改权限。

## 4. 正反例与部分解耦验收

- 非开发验收：目标业务人员按简短正常使用说明操作，无开发者临场口头指挥。用户现场未实际执行就标 NOT_RUN；浏览器自动化证明操作可达，不冒充真人可用性验收。
- 权限/依据：匿名、跨客户、撤权回放、伪/过期豁免、旧 Gate、检查新修订、晚到结果、错设备/期间、未知外部结果与重复提交；每个失败有页面解释和合法恢复路线。
- 并发/恢复：重复上传和批准、数据已提交而响应丢失、处理驱动重启、会话断线、慢文件不拖住交互；所有失败轮次保留。
- 解耦：核心不导入租赁阈值、供应商 SDK 或界面；测试内换一个简单材料复核配置、解析或渠道适配器，不改核心事务/权限代码，真实租赁路径仍通。只做测试证明，不额外开发第二行业产品或通用平台。
- 反证：移除桥接或关键提交门时相应测试必须失败。可在隔离副本进行临时故障/变异，不污染交付源码。

## 5. 性能、工具与同版收口

先修默认测试命令漏挂/损坏、全 SKIP/零断言算 PASS、无限挂起、版本清单落后和并行环境串用。必测 FAIL/BLOCKED/NOT_RUN 不能汇总成发布 PASS。

固定同一发布快照再测；其他路修改后作废受影响结果，不能把脏树不同时刻的绿灯相加。至少三轮同环境记录页面首屏、文件处理、预审等待、关键提交、跨角色同步、查询/调用数和资源峰值；性能改善不能来自跳过核验或隐藏异常。旧兼容接口优化数据不能冒充新完整流程数据。

测试工作数据扩大与至少九角色会话；真实物理终端数量如实记录。保持输出简单，优先修用户可感知的等待和重复处理，不为毫秒指标增加无关架构。

## 6. 产品发布与恢复

统一提供正常启动、健康/依赖状态、停止和诊断入口。安装可能需要约定的操作系统/运行时前提，但步骤写成普通使用说明；若缺依赖就明确提示，不宣称任意电脑零配置。安装后每次办理不依赖开发者配置脚本。已建运行时存在时只操作自己跟踪的资源。

备份/恢复覆盖本轮全部迁移和非空关联数据、原始材料字节或可验证存储引用、解析版本、业务任务、授权、分析回执、决定与报告。恢复后重跑页面查询/继续办理，不能重放外部发送；代码回退和数据回退分开。扫描实际发布树与已跟踪文件，不泄露秘密原文；dist、源代码和契约对应同版。

D27-L-UI 是本轮硬门：二维页面上原件到人工决定，不靠开发者。真实媒体/模型提供方 D27-R 和多人空间 D27-S 单列，未授权/未实现如实保留，不用录屏/合成工厂顶替，也不让未做三维阻止本轮二维硬门验证。

分阶段：D1 冻结用户脚本/基线；D2 跟随集成并修验收工具；D3 固定版本全旅程/故障/恢复/性能；D4 非开发试用与交付。交付 ACCEPTANCE_MATRIX.md、DEFECTS.md、TEST_RESULTS.md、RELEASE_ACCEPTANCE.md，以及普通用户说明和脱敏证据。最终按“人能完成哪些动作”汇报，不按代码行数或测试总数代替交付。
